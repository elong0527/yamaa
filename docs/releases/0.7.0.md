# yamaa 0.7.0

0.7.0 comes between 0.6.x and 1.0.0. It fixes defects, settles the interface
questions that 1.0.0 would otherwise freeze as they stand, and adds features;
1.0.0 follows it and the feedback on it (#4064 D294). Like 0.6.x, 0.7.0 is
outside the stability contract, which starts at 1.0.0 (#3030 D1), so it breaks
some 0.6.x files and calls, and each break has one line under
[Upgrading](#upgrading). The [0.6.0
notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.6.0/docs/releases/0.6.0.md)
describe the 1.0 interface that 0.6 releases for testing and every change up to
0.6.0, and the
[0.6.1](https://github.com/elong0527/yamaa/blob/yamaa-v0.6.1/docs/releases/0.6.1.md)
and [0.6.2
notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.6.2/docs/releases/0.6.2.md)
the patches since. Report what you find through the [issue
forms](https://github.com/elong0527/yamaa/issues/new/choose): the 0.6/0.7
feedback form for what you tried and how the interface felt, the bug report for
a defect.

## Install

Install the Python package from PyPI with `python -m pip install yamaa` (#3030
D57). The wheels cover CPython 3.12 to 3.15 on Linux x86_64 and aarch64 with
glibc 2.28 or later, macOS arm64 and Windows x64; elsewhere pip builds the
source archive, which needs Rust 1.82 or later and a C compiler. Each GitHub
release carries the same Python files, and also R binary packages for Windows
x64 and macOS arm64, for R 4.6 and R 4.5, which install without Rust, Rtools or
a network; the R source package, for Linux and any other R from 4.2.0; and the
standalone `yamaa` command line for Linux, Windows and macOS, which needs no
Python, R or Rust and ships unsigned (#3030 D52). Install the R package from
the GitHub release. The
[Python](https://github.com/elong0527/yamaa/blob/main/python/README.md#installation)
and
[R](https://github.com/elong0527/yamaa/blob/main/R/yamaa/README.md#installation)
package pages give the commands, [Supported platforms](#supported-platforms)
lists every platform, and [Installing in a restricted
environment](https://elong0527.github.io/yamaa/articles/restricted-environments/)
covers machines without internet access.

## Supported platforms

Each cell names the CPython or R series that native qualification installs and
tests the package with, the oldest glibc a Linux wheel needs, or the Rust
target of the command-line binary; `no` means the release has no such package.

| Platform | Python wheel | Python source archive | R source package | R binary package | Command-line binary |
| --- | --- | --- | --- | --- | --- |
| Linux x86_64 | CPython 3.12 to 3.15 on glibc 2.28 or later | CPython 3.12 to 3.15 | R 4.2 or later | no | `x86_64-unknown-linux-musl` |
| Linux aarch64 | CPython 3.12 to 3.15 on glibc 2.28 or later | CPython 3.12 to 3.15 | R 4.6 | no | `aarch64-unknown-linux-musl` |
| macOS arm64 | CPython 3.12 to 3.15 | CPython 3.12 to 3.15 | R 4.2 or later | R 4.5 and 4.6 | `aarch64-apple-darwin` |
| Windows x64 | CPython 3.12 to 3.15 | CPython 3.12 to 3.15 | R 4.2 or later | R 4.5 and 4.6 | `x86_64-pc-windows-msvc` |

- The Linux wheels are `manylinux_2_28`, for RHEL 8, Ubuntu 20.04, Debian 10
  or later; older systems build the Python source archive.
- The source packages carry their crates and build offline with Rust 1.82 or
  later, Cargo and a C compiler; an offline Python build needs `maturin`
  installed (`pip install --no-build-isolation --no-index`), and a Windows R
  build the Rtools of its R series and the `x86_64-pc-windows-gnu` target.
- Each R binary package serves one R series, R-release or R-oldrel
  (#3030 D48), and installs without Rust, Rtools or a network; the macOS
  ones need macOS 11. Other R series and Linux use the R source package.
- The command-line binaries are static on Linux (musl) and Windows, need
  macOS 11 on macOS, and ship unsigned (#3030 D52).
- macOS x86_64, free-threaded Python and the Python and R packages on musl
  systems such as Alpine Linux are not supported (#3030 D49).

Saved files are qualified with these readers at these minimums, which the
Python `test` extra and the R package's `Suggests` declare: Polars 1.35.2
(2.0.0 on CPython 3.15) and PyArrow 23.0.1 (26.0.0 on CPython 3.15) for CSV
and Parquet; R arrow 23.0.1 for CSV and Parquet; Python's standard library and
R jsonlite 2.0.0, with `bigint_as_char = TRUE`, for Dataset-JSON 1.1; and lxml
6.1.3 for Define-XML 2.1.

## Known issues

The [known issues of 0.6.0](https://github.com/elong0527/yamaa/blob/yamaa-v0.6.0/docs/releases/0.6.0.md#known-issues)
still apply: the command-line binaries are unsigned and not notarized, and
the YAML reader is a vendored copy of saphyr-parser 0.2.1 with reviewed
fixes (#3969).

zstd advisories in 0.6.2 and earlier. Those releases link zstd 0.13.3 and
zstd-safe 7.3.0, which RUSTSEC-2026-0391 and RUSTSEC-2026-0395 to 0406 name; this
release links zstd 0.14.3 and zstd-safe 8.2.0, which fix them. yamaa decodes a
ZSTD Parquet page with a new `DCtx` and its one-shot `DCtx::decompress` alone,
with no dictionary and no stream. Every advisory but RUSTSEC-2026-0400 names
functions that yamaa does not call, and RUSTSEC-2026-0400, which names
`DCtx::decompress`, needs a stream left open on the same context and a
dictionary, so the earlier releases are not known to be exposed (#4066).

## Changes since 0.6.2

Each change since 0.6.2 that users can observe has one line below.
[Upgrading](#upgrading) comes first, then the other changes by area: the
language, inputs, submission metadata, diagnostics, files and saving, the
lint and the command line, the packages and platforms, and the Rust facade.

### Upgrading

Each change that breaks a file, call or saved output that works with 0.6.2
has one line here, starting with **Break**, which says what to change. The
other lines are steps an upgrade needs although nothing broke. A file that
0.6.2 already refuses may now report another diagnostic: code that matches
diagnostics finds each such change, with the diagnostic it replaces, under
[Diagnostics](#diagnostics) and [Submission metadata](#submission-metadata).

- **Break: lint returns a result.** Read `result.findings` in Python or
  `result$findings` in R; `status` fails while findings remain, `paths` lists
  rewritten files, and printing gives the summary (#4064 D300, #4078).
- **Break: invalid ODM limits carry a diagnostic.** Catch the package refusal
  for negative, fractional, Boolean and missing limits, and read
  `value_not_permitted` at the argument in its issues table (#4064 D299,
  #4077).
- **Break: operation, state and argument refusals share one error hierarchy.**
  Update Python handlers that catch `RuntimeError`, `TypeError` or
  `NotImplementedError` from yamaa calls to catch `yamaa.Error` or its
  `StateError` subclass, and R handlers to catch `yamaa_error` or its
  `yamaa_state_error` subclass (#4077).
- **Break: a refusal always carries an issues table.** Handle an empty R data
  frame instead of `NULL` issues, including for conversion failures and calls
  before negotiation (reverses D258, #4077).

- **Break: a `Submission` section declares a transport.** Composing Define-XML
  under `context: Submission`, the default, now fails with
  `missing_required_field` at the section's `transport` when the section
  declares none. Add `transport` (`xpt`, `dataset_json` or `dataset_ndjson`),
  or set `context: Other` for a document that is not a submission (DEFINE-4,
  #4064 D295, #4050).
- **Break: an empty column is marked in Define-XML 2.1.** When the section
  requests a transport, the `ItemRef` of a column that no published row holds a
  value in, such as `DTHDTC` when no subject died, and of a value-level entry
  none of whose rows holds one, now carries `def:HasNoData="Yes"`, so such a
  document's bytes change; regenerate a saved copy. Validated metadata never
  declares a column's or entry's `has_no_data`, refused with
  `value_not_permitted`; historical metadata declares it, which a 2.0 document
  refuses (SUB-28, DEFINE-30, #4064 owner decision, #4082).
- **Break: lint reports a restated inherited value.** `lint()` now reports
  `restated_inherited_value` at a value a layer writes exactly as it inherits
  it, such as an unchanged label or derivation, which stops following the
  parent once written, so `yamaa lint` exits 1 on such a layer. Remove the
  value to keep inheriting it, or suppress the finding with a reason; it has no
  fix (LAYER-6, LAYER-9, #4100).

- **Break: a layer's `output` and `submission` compose field by field.** A
  layer that writes `output` or the dataset's `submission` block now keeps
  every field it leaves out from its parents, as a column does, instead of
  replacing the block whole, so a child that writes `output` keeps the
  inherited `report`, `order_by`, `decimals` and `relative_to`. Write only the
  fields a layer changes, and clear an inherited field to drop it (LAYER-5,
  LAYER-9, #4102).

- **Break: built text holds at most 1 MiB.** A text value that `str_pad`,
  `str_decimal`, `str_template`, `str_replace` or `STR_JOIN` would build longer
  than 1,048,576 bytes now refuses the run before it grows past that, as
  `engine_rejected` with `resource` `text_bytes` at the verb's path (TEXT-2,
  #4103).

- **Re-lock project functions.** A project function's lock pins the installed
  yamaa, so after upgrading yamaa every build that calls a project function
  fails with `runtime_artifact_mismatch` until its lock is made again.
  Regenerate each `environments.<host>.lock`, for example with `uv lock
  --upgrade-package yamaa` or `renv::snapshot()`, and re-run each function
  package's own tests (FUNC-3, #4047).
- **Join keys of a converted 0.5 file.** 0.5 chose the key of an intermediate,
  or of an implicitly joined input, on each run from the inputs' headers, while
  1.0 uses the key written in the file. A key written when converting a 0.5
  file therefore fixes a join that 0.5 decided per run, so check it against the
  inputs the study reads (#3030 D23, #4047).

### Language

- Backward `row_value` reads can carry calculated values through causal
  column groups in one independently ordered window (WINDOW-12, #4233).

- A project may name a `parent` and `clear` inherited fields, composing
  sections by name and resolving every relative path from the file that
  declares it (PROJECT-16, #4101).

- A later codelist source replaces an earlier codelist of its `id` whole,
  including its name and items; the composed set still requires unique names
  (CT-1, #4101).

- An intermediate's `order_by` or a window's order over an untyped derivation
  choosing an `int` or a `float` orders by exact value instead of failing the
  run with `engine_rejected`. An order term, a `baseline_flag` date included,
  whose types do not compare, such as `str` or `int`, or `date` or `datetime`,
  now fails `check()` and `run()` with `incompatible_input_type` at the term;
  give the derivation a `type` (VALUE-22, #4068).
- An intermediate's `unique` verification compares values as its key matches
  them, so an `int` and a `float` of equal value, such as `1` and `1.0` of an
  untyped derivation, repeat: such a key now fails the run with
  `duplicate_intermediate_records` before any row is built, or warns under
  `severity: warning`, instead of passing and failing the lookup with
  `multiple_matches` (LOOKUP-17, #4069).
- Each origin `resolve()` returns for a value a layer wrote now carries the
  `line` and `column` where that layer wrote it and the exclusive `end_line`
  and `end_column`, counted from 1, beside its
  `declaring_source`; a schema default and a composed value carry neither, and
  `artifact_version` stays `1` (LAYER-1, #4099).
- The verb `decode`, written `decode: {source: PARAMCD, codelist: PARAMCD}`,
  returns the `decode` of the item, in a codelist the project file declares,
  whose value equals its source, as SAS `put(PARAMCD, $PARAM.)` does, so a
  specification no longer restates a codelist's decodes in a `mapping`. It
  takes `mapping`'s `missing` and `unmapped` answers and a source of the type
  the codelist's `data_type` is held in; a codelist the project does not
  declare fails as `unknown_codelist`, one without decodes as the new
  `codelist_without_decodes`, and a specification checked or run without its
  project file as `project_binding_missing` (EXPR-15, CT-13, #4089).

- **Two reservations withdrawn.** The rename table no longer reserves a
  dataset's `submission.split` or an ODM input's `transactions: replay`:
  split datasets stay several specifications (#3824), and transactional ODM
  stays refused (#3818) (#4085).

### Inputs

- R `spec$run(inputs = list(DM = df))` reads owned data-frame snapshots by input alias, including factors, missing values and whole Date/POSIXct values, without an R Arrow dependency (#4086).

- Python `spec.run(inputs={"DM": frame})` reads Arrow PyCapsule frames,
  including pandas through pyarrow, in place of declared input files;
  unsupported physical types give an input diagnostic (#4064 D303, #4086).

- A correlated filter may read a donor-record derivation through its lookup
  alias, including while the filter is rebased into a donor plan (LOOKUP-16,
  #4098).

- Every lookup's `between` accepts `closed: both | left | right | neither`
  to include the stated endpoints, defaulting to `both`; adjacent windows
  can share an endpoint without matching it twice (LOOKUP-9, #4090).

- A `parquet` output whose page, one column's values of 1,024 consecutive rows,
  passes 2,147,483,647 bytes, or whose footer passes 4,294,967,295, is refused
  as the limit `parquet_page_bytes` or `parquet_footer_bytes` instead of saving
  a file no reader can read (PARQUET-4, #4075).

- `read_odm()` and direct XML inputs accept US-ASCII declarations only with
  ASCII source bytes; other encodings remain unsupported (#4064 D296, #4060).
- Blank lines after the last record of a CSV input are no record: a one-column
  input no longer gains a row with a missing value, and an input of several
  columns is no longer refused with `source_record_width`. A blank line before
  the last record is still a record (CSV-11, #4076).
- A Parquet timestamp in milliseconds or nanoseconds, as pandas and pyarrow
  write by default, now reads as `datetime` when each value is a whole second,
  and a `FLOAT` field reads as `float`, its exact value; a timestamp adjusted
  to UTC, as R arrow writes a `POSIXct`, and a `BOOLEAN` field are still
  refused (PARQUET-7, PARQUET-9, #4087).


- A `.sas7bdat` encoding declaration that contradicts its stored encoding now
  fails ingestion as `source_sas_invalid`, cause `encoding_mismatch`, at the
  encoding entry, naming both encodings (SAS-2, #4084).
- `source_encoding_required` no longer requires an encoding declaration for
  `.sas7bdat`: its stored encoding supplies the decoding. XPT still requires
  a declaration because Transport stores no encoding (SAS-2, #4084).

### Submission metadata

- A submission section's `define_version` selects the Define-XML release it
  writes: `2.0.0`, or any published 2.1 release from `2.1.0` to `2.1.11`, which
  the document keeps in `def:DefineVersion`. Omitting it keeps 2.1.11 and its
  bytes. A 2.0 document refuses with `value_not_permitted` a fact that 2.0
  cannot represent, and an unpublished version is refused (DEFINE-29, #4064
  D292, #4030, #4037).
- A dataset's `submission.mode: historical` reproduces received metadata as a
  literal record in a Define-XML 2.0 document, under `context: Other` and with
  no transport. Its declarations, among them a `key_sequence` and a literal
  `artifact` link, bind no execution, and composing it reads no run report,
  artifact or input. `validated`, the default, keeps every existing check and
  refuses `key_sequence` and `artifact` (DEFINE-30, #4064 D292, #4030).
- An SDTM or SEND dataset that no implementation guide defines, such as a
  custom domain, declares `submission.non_standard: true`, and a 2.1 document
  writes `def:IsNonStandard="Yes"` in place of its `def:StandardOID`. Such a
  dataset declares no `standard`; an ADaM dataset never declares the flag, and
  a 2.0 document refuses it, each with `value_not_permitted` (SUB-4, SUB-5,
  DEFINE-29, #4064 D293, #4038).
- From 1.0.0, new CDISC conformance checks are opt-in through a new optional
  field; the refusing checks are those of 0.7.0, and every condition remains
  error severity (#4064 D298, #4083).

- A column whose `Predecessor` origin names a predecessor column may copy it
  through a plain lookup of the predecessor's input: with `SUBJ` a lookup of
  `ADSL`, `SUBJ.AGE` copies `ADSL.AGE`. A description that writes a where
  clause needs a `filter` on the lookup or on the `source` that reads through
  it. A lookup of another dataset, a pair relation, or a lookup whose `absent`
  answers with a value still fails with `origin_contradicts_derivation`
  (SUB-20, #4059).
- A `text` column or value-level entry may omit `length` when every section
  that lists its specification requests a `transport`, and the document then
  gives the longest published value's length (SUB-24). Only the project file
  says whether a section requests one, so the omission is checked when a
  document composes the specification: a section without a transport fails with
  `submission_length_missing` at
  `<section>.specs[<n>].columns.<column>.submission`, and checking the
  specification on its own no longer reports it. An `integer` or `float` column
  still declares `length` (SUB-7, #4062).
- The [Supported
  standards](https://elong0527.github.io/yamaa/articles/supported-standards/)
  page lists the implementation guides for which yamaa generates datasets,
  Define-XML and SAS Transport version 5 files: SDTMIG 3.3 and 3.4, and ADaMIG
  1.1, 1.2 and 1.3. New benchmarks compare the rows, Define-XML documents and
  transport bytes of SDTMIG 3.3 and ADaMIG 1.1 and 1.2 datasets (#4042, #4043,
  #4045).
- The supported standards now list SENDIG 3.1.1 for nonclinical tabulation,
  shown end to end by the `send-bw-sendig311` benchmark: a `send` section
  composing body weights into Define-XML and SAS transport (#4095).

### Diagnostics

- A failing progress callback adds `host_error` and `host_message` to
  `engine_rejected` context, names the exception in its message, and retains it
  as the refusal's Python `__cause__` or R `parent` condition; Python pickling
  requires the cause and added state to be picklable (#4064 D301, #4080).

- An intermediate other than a pair relation that nothing reads and that
  declares no `key` keeps no input live, so an input that only it names is
  pruned (LAYER-11). `check()` then reports the intermediate's own
  `missing_required_field` at `intermediates.<id>.key` (LOOKUP-3), where it
  reported `missing_required_field` at a field the input lacks, such as
  `input.VS.path` (SCHEMA-13) (#4048).
- A specification that a project section lists and that cannot be prepared,
  such as one with a validation finding, is named by the `domain` its own
  file writes. It is among the project's names, selecting it by that name
  reports its own findings where selecting it failed with
  `unknown_specification_name`, and a project run names it by that domain
  rather than by its listed path. A `domain` that only a parent layer
  supplies still gives it no name (PROJECT-5, PROJECT-6, #4049).
- `unknown_codelist`'s message starts with the field that names the
  codelist, such as `columns.SEX.submission.codelist`, where it named the
  column, so that it reads the same for a `decode`, which has no column
  (CT-1, EXPR-15, #4089).
- A `source_sas_invalid` refusal of a field adds its `field` (an empty or
  undecodable name by its position), and one of a value also its `record`; an
  empty field name fails as `field_name` rather than `header`, and cause
  `field_type` reports at `input.<dataset>.types.<field>` rather than the
  input's path (SAS-7, #4084).

### Rust facade

- `SpecRequest::inputs` replaces declared inputs by alias for one request, over
  the configured resolver; declared types still apply, and run reports label
  those inputs `memory:<alias>` (#4064 D302, #4086).

- `Table::import` restores a public result table from an Arrow C stream, including diagnostic list columns (#4077).

- The stability contract now states that the facade's public items carry
  Arrow's types, so from 1.0.0 its Arrow major, 55, is part of its
  contract, and moving to another is a facade major release. The native
  Parquet writer's 55.2.0-compatible saved bytes are frozen separately;
  production builds do not depend on the `parquet` crate. Building the facade
  without its default `arrow` feature leaves that surface out (#4081).

### Packages and platforms

- R table accessors reuse the data frame already converted for a held table; a
  save that refreshes the run report still returns the refreshed report
  (#4071).

- Host layers and native modules negotiate boundary version 8, refusing mixed builds that lack native refusal classes or Python/R input-frame arguments (#4077, #4086).
- Python tables and `yamaa.Error` can be pickled, including diagnostic list columns and empty-table schemas, so process workers can return tables and raise yamaa refusals (#4077).

- GitHub release assets have descriptive labels and a download chooser
  grouped into Python, R, CLI and developer resources (#4154).

- A Python call, such as `check()`, `run()`, `save()` or a read of a streamed
  run's output, releases the global interpreter lock while the engine works,
  where it held it for the whole call, so other threads run meanwhile and two
  threads can run two specifications at once; the `progress` function and
  project functions still run on the calling thread (#4072).

- Ctrl+C during a yamaa call, or an interrupt in a progress callback or a
  project function, now reaches R as its interrupt condition, which only an
  `interrupt =` handler takes, instead of an error that `tryCatch(error = )`
  caught and the console printed as "bad error message" (#4070).
- In R, the paths of `yamaa_spec()`, `yamaa_project()`, `yamaa_read_odm()`
  and `spec$check(parent = )` take named, `fs::path()` and `glue::glue()`
  strings, as `yamaa_lint()` did, and all five expand a leading `~` to the
  home directory as base R's file functions do, so a relative path into a
  directory named `~` is written `./~/` (#4091).
