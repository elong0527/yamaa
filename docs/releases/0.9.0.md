# yamaa 0.9.0

0.9.0 runs the command line from the Python and R packages, adds a time-of-day
type, analysis results metadata and the received identifiers that reproduce a
submitted Define-XML document, reads lookups through relations that pivot,
repeat or derive their records once, and removes the fixed limits on a table's
rows, columns and cells and on a specification's inputs. The specification
language remains 1.0. Like 0.8.0, this release precedes the stability contract
that starts at yamaa 1.0.0; the breaks and the other changes a program may
notice are listed under [Upgrading](#upgrading). The
[0.8.0 notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.8.0/docs/releases/0.8.0.md)
cover the previous release.

After publication, 0.9.0 is available on GitHub and PyPI. It is not submitted
to CRAN (#4844); R users install the source package or a binary from the
GitHub release.

## Install

Install the Python package from PyPI with `python -m pip install yamaa` (#3030
D57). The wheels cover CPython 3.12 to 3.15 on Linux x86_64 and aarch64 with
glibc 2.28 or later, macOS arm64 and Windows x64; elsewhere pip builds the
source archive, which needs Rust 1.82 or later and a C compiler. Each GitHub
release carries the same Python files, and also R binary packages for Windows
x64 and macOS arm64, for R 4.6 and R 4.5, which install without Rust, Rtools or
a network; the R source package, for Linux and any other R from 4.2.0; and the
standalone `yamaa` command line for Linux, Windows and macOS, which needs no
Python, R or Rust and ships unsigned (#3030 D52). Install the R package from
the GitHub release. The
[Python](https://github.com/elong0527/yamaa/blob/main/python/README.md#installation)
and
[R](https://github.com/elong0527/yamaa/blob/main/R/yamaa/README.md#installation)
package pages give the commands, [Supported platforms](#supported-platforms)
lists every platform, and [Installing in a restricted
environment](https://elong0527.github.io/yamaa/articles/restricted-environments/)
covers machines without internet access.

## Upgrading

- **Break: `submission.mode: historical` is now `reproduced`.** The schema
  refuses the old spelling. The mode's rules, fields and define.xml bytes are
  unchanged, and a refusal's `detail` names the mode `reproduced` (DEFINE-30,
  #4757 D351).
- **Break: R `run(inputs = ...)` refuses a `POSIXct` column whose `tzone` is
  not `"UTC"` or `"GMT"`**, including the session's zone, where it shifted the
  clock times to UTC; convert with `lubridate::force_tz(x, "UTC")`. A project
  function's datetime result now also accepts `"GMT"` (#4882 D384).
- **Break: in a specification that declares `rows`, a `source` binding with
  nothing to select among refuses `order_by` and `keep`, and an unfiltered
  one refuses `absent`.** On a read of the row's own driver record, an output
  column or a named intermediate they changed nothing; they now fail as
  `prohibited_construct`. A specification without `rows` accepts the same
  read as before (LOOKUP-10, LOOKUP-24, #4856 D381).
- **A filtered `source` read that keeps no record answers its `absent`.**
  On a read of the row's own driver records, a row template's included, a
  `filter` that keeps none of them now gives the binding's declared `absent`
  value and counts it under `absent`, where it gave missing and counted
  nothing. In `first_available` that answer is present, so a later source
  is no longer read (NAME-6, COLUMN-12, LOOKUP-24, EXPR-9, #4922 D392).
- **A zero is never negative**: a result such as `100 * 0 / -5` is held as
  positive zero, so csv, `str` conversion, Dataset-JSON, Parquet and the host
  frames give `0` where they gave `-0` (VALUE-4, VALUE-8, #4862 D387).
- **Numeric text beyond binary64 fails to parse**: `1e400` in an `int` or
  `float` field fails with `field_parse_failed` where it read as missing, and
  converts to neither number: a `str` value `1e400` that a `float` or `int`
  column takes now fails the run with `conversion_failed` (VALUE-3), where it
  gave missing (VALUE-6, INPUT-7, #4863 D388).
- **Rounded values change for written ties of large values.** The normal
  binary64 that a tie of at most fifteen significant digits reads as (its
  nearest, the even one at a midpoint) now rounds as that tie, away from zero,
  wherever the one rounding applies: `8753033.315` at two places is
  `8753033.32`, where it was `8753033.31`. The `prohibited_function` hint for
  `ROUND` states the rounding's tie rule (FORMULA-16, CSV-9, TEXT-15, #4864
  D383).
- **`duration_text` rounds a `float` amount's seconds** to its new
  `decimals` field, six places when undeclared, by the one rounding, so `1.1`
  hours is `PT1H6M` where it was `PT1H6M0.0000000000005S` (TIME-21, #4860
  D385).
- **A number wider than its declared width warns.** A `length`,
  `significant_digits` or `w.d` `display_format` that understates an `int` or
  `float` column's values, which was published unchecked, is now a violated
  `warning` row of the run report, named `numeric_width`, whose finding is
  the new condition `numeric_width_failed`; the run still publishes its
  output (SUB-29, #4884 D378).
- **An output may no longer name a file its specification reads.**
  `output.path` or `output.report` naming an input's `path` or `schema`, the
  specification's own file, a layer, a dictionary or a project file now fails
  `check` and `run` with `artifact_path_collision` before anything is written,
  where a run replaced that file (OUTPUT-9, #4851 D376).
- **On macOS an output that differs from an input only by case is refused.**
  Two locations that differ only in case are now one file on macOS, as on
  Windows, so `output.path: DM.csv` beside an input `dm.csv` fails `check`
  and `run` with `artifact_path_collision`, where a run replaced `dm.csv`; a
  transport or Define file collides the same way (OUTPUT-9, JSON-2, #4923,
  D396).
- **Published values change for a constant group.** A group whose non-missing
  values are all equal now gives `MEAN` that value and `STDDEV` and `VARIANCE`
  exactly `0`, where the ordered sum could leave a last-place error: six
  values of 4.1 gave a mean of `4.1000000000000005` and a `STDDEV` near
  `1e-15`, so a `NULLIF(sd, 0)` guard never fired (FORMULA-19, FORMULA-24,
  #4859 D373).
- **A datetime made from text without seconds is collected to the minute.**
  `2025-03-04T08:30` converted, ingested or written as a literal `datetime` now
  has collected precision `minute` and time imputation flag `S`, as `impute`
  gives it, where it was `second` with no flag (TIME-7, VALUE-16, #4879
  D375).
- **Reproduced define.xml bytes change** for a value-level entry that declares
  fewer fields than its column, which now writes only what it declares
  (DEFINE-30, #4734).
- **A column's free-form `metadata` map may no longer carry a key named
  `omitted` or `order`**, which `submission` now declares (SUB-2, #4751,
  #4752, #4757).
- **A dataset's root `metadata` map may no longer carry a key named
  `codelists`**, which `submission` now declares (SUB-2, #4887 D393).
- **A Dataset-JSON `time` column reads as `time`**, not `str`; declare it
  `str` to keep its text (DSJSON-2, #4267).
- **Numeric text such as `.5` and `5.` converts** to a number where it was
  `unconvertible` (VALUE-6, INPUT-7, #4461 D310).
- **The fixed table and input limits and their refusals are gone**, with the
  `table_limit` code and the `engine_rejected` codes such as `table_rows` and
  `output_columns` (LIMIT-2, LIMIT-3, #4462 D311, #4773).
- **The condition `redundant_long_form` is retired**: validation accepts a
  long form that restates its shorthand, and only the lint reports it
  (SCHEMA-15, #4463).
- **`transport_text_invalid` reports one finding per dataset**, its
  `column`, `row`, `key_values`, `value` and `cause` moved into the entries of
  `values` (XPT-7, #4734).
- **An intermediate `key` written as a bare string other than `none` fails as
  `value_not_permitted`**, where it failed as `invalid_field_type`
  (LOOKUP-5, #4271).
- **A fraction of a second in an in-memory input is refused with the code
  `temporal`**, where it was `array_type` (SCHEMA-12, #4780).
- **A Define-XML 2.0 origin refusal is located at `origins[N].type` or
  `origins[N].source`**, with the declared value as its `value` (DEFINE-25,
  DEFINE-29, #4749).
- **A project finding about an inherited input names its layer** in
  `context.source`, where it named the entry (PROJECT-10, PROJECT-11, #4733).
- **Some files that ran are refused**: a submission that requests a transport
  rechecks mandatory columns and keys (SUB-11, #4816), and a pair relation's
  side read as a lookup fails before the run as `missing_required_field`
  (LOOKUP-3, #4673).
- **`check` refuses a lookup derivation that reads a name its own map
  derives**, as `unknown_field`. Every run already refused such a file; where
  the input stores the name, a run now adds the `unknown_field` row after its
  `duplicate_derivation` (LOOKUP-15, #4754 D350).
- **`yamaa lint` exits 1 on more files**: each of the five new findings,
  `unused_declaration`, `uncalled_function`, `number_for_text`,
  `empty_text_comparison` and `window_tie`, alone fails a file 0.8.0 passed.
  The `number_for_text` fix changes a published value: `derivation: 012`
  published `12`, and `lint --fix` writes `'012'`, which publishes `012`
  (LAYER-11, FUNC-12, #4325 D336, #4326 D337, #4858 D382, #4877 D390).
- **A layer that writes `output` without `columns` keeps its parent's copied
  columns' submission metadata.** `resolve()` and the submission metadata of
  such a child give the columns a copy entry declares their `Predecessor`
  origin, `length` and `display_format`, where they had no `submission`
  (SPEC-9, #4324).
- **A declared lock must be regenerated.** A project's
  `environments.<host>.lock` pins yamaa, so after the upgrade every build that
  calls a project function fails with `runtime_artifact_mismatch` of `yamaa`
  until the lock is made again, such as with `uv lock --upgrade-package yamaa`
  or `renv::snapshot()`; then re-run each function package's tests
  ([API](https://elong0527.github.io/yamaa/articles/api/)).
- **A predicate over an empty input is typed too.** A root or row template
  `filter`, or a verification, that compares a field declared `str` with a
  number ran over an input with no records; it now fails `check` and `run`
  with `incompatible_input_type`. Compare it with text, such as `'1'`
  (FORMULA-5, #4854 D386).
- **An in-memory column of another type than declared fails as
  `incompatible_input_type`** at `inputs.<alias>`, with `column`, `declared`
  and `found`, where it failed as `engine_rejected` with `code`
  `result_projection` and `step` `build`; an unsupported Arrow type reports
  `column` and `type` where it reported `value` (INPUT-5, SCHEMA-12, #4881
  D377).
- **A run that orders date texts by text warns.** An unchanged file whose
  comparison or lookup `order_by` orders two collected date texts of which one
  begins with the other now saves a violated `warning` row, `text_date_order`,
  in its run report, and its printed summary adds `, 1 warning` (CHECK-27,
  CHECK-2, #4516 D315).
- **An empty where value fails as `value_level_where_invalid`**, or
  `analysis_dataset_invalid`, with reason `empty_value`, where it failed as
  `minimum_length` (SUB-12, #4849 D325).
- **An expression past the depth limit reports `compiler_limit`**: its
  `engine_rejected` context `code` is `compiler_limit`, with `step` `prepare`,
  at its specification path and line, where it was `resource_limit` in an
  `inheritance_` phase (LIMIT-1, #4890 D391).
- **`project.check()` refuses an origin a Define-XML 2.0 section cannot
  record**, such as `Other` under ADaM, with `value_not_permitted` at the
  origin's `type` or `source`, where it passed (PROJECT-7, DEFINE-29, #4825
  D370).
- **An empty block scalar at the end of a file reads `""`**, where it read a
  single line break, so a final `description: |` with no content lines
  changes the text it gives (#4939 D395).

## Changes

### Command line

- **The packages run the command line as themselves.** `yamaa.cli(arguments)`
  and `python -m yamaa` in Python, and `yamaa_cli(arguments)` in R, run one
  command of the `yamaa` command line over the package's own engine: a run of
  a specification that calls a project function verifies the project's lock
  and calls the functions installed in that interpreter. The standalone binary
  starts a worker of the package for a project's run instead, as the next
  entry says; a run of a specification alone, or of a project that names no
  one language, that calls a project function fails as
  `unsupported_operation`, and one that calls none runs. Each prints what the binary
  prints on the package's standard streams and returns the binary's exit
  status, and `--version` and `selftest` name the host and its version, which
  the text form prints on a `host version:` line. The commands moved from the
  binary into the facade's `cli` module, over a `Runtime` each client
  configures (D328).
- **The standalone binary runs project functions through an interpreter's
  worker.** `yamaa run` of a project that calls project functions starts
  `python -m yamaa._worker` or the R package's worker in `Rscript`, in the
  interpreter `--interpreter` names or the one found on `PATH`, and runs the
  functions there as the package's own `run()` runs them, verifying the
  lock first. `--host python|r` names the language; without it, the one
  language the project names an `environments` entry for, or else the one
  its function files implement, runs them, and a project that names both
  runs none, as before. The run's JSON document gains `host`. The worker's
  package must carry the binary's engine version, which a declared lock's
  verification checks as `runtime_artifact_mismatch` of `yamaa`. The
  command-line conformance runs still start no worker (D329).

### Values and types

- **A file may declare UTF-8 to write non-ASCII text literally.** A
  specification, project file, codelist file, analysis results file or
  function file that writes
  `encoding: utf-8` beside `yamaa` and `type` may hold curly quotes, dashes
  and other non-ASCII characters as written, such as method descriptions
  copied from a submitted Define-XML document; define.xml carries them
  unchanged. ASCII stays the default and the recommended form, the
  declaration is never inherited, and even a UTF-8 file escapes a byte-order
  mark or a bidirectional control. A refusal of a non-ASCII character in an
  undeclared file now carries a `hint` naming both remedies, and bytes that
  are not UTF-8 in a declared file fail as the new `invalid_source_encoding`
  (SPEC-8, #4750, D352).
- **An empty literal or folded block at the end of a file is an empty
  string.** A file whose last value is a block indicator with no content
  lines, such as a final `description: |` or `description: >`, now reads
  that value as `""`, as YAML 1.2 does; before, it read a single line break.
  With keep chomping (`|+`), only the blank lines after the header remain.
  The same block followed by another key already read `""` (#4939 D395).
- **Numeric text may have digits on one side of its decimal point only.**
  `.5`, `5.` and `-.5` now parse as numbers when text converts to `int` or
  `float` and when a typed input reads a field, as SAS reads them; before,
  they failed to parse, so `unconvertible` replaced them alongside text such
  as `abc`. Formula literals are unchanged (VALUE-6, INPUT-7, #4461 D310).
- **A date can become a datetime at a named time of day.** `impute` with
  `type: datetime` now also takes a `date` source and supplies its time of day
  from `time: first` (`00:00:00`) or `time: last` (`23:59:59`). The result
  keeps the date's collected precision, so the time imputation flag reads `H`.
  A date still never converts to a datetime implicitly (TIME-8, VALUE-18,
  #4270 D330).
- **Two dates give an ISO 8601 calendar duration.**
  `calendar_duration: {start, end}` writes the calendar time from one date to
  another as text such as `P1M1D`: the whole months `diff` counts, as years
  and months, then the remaining days. Equal dates give `P0D`, an earlier
  `end` a leading `-` and a missing date missing, and an operand that is not a
  `date` fails as `incompatible_input_type`. `str_template` joins it with a
  date's text, a `str` column, into interval text such as
  `P1M1D/2007-09-27`; a `date` operand of `str_template` fails as
  `incompatible_input_type` (TEXT-1) (TIME-24, #4505 D341).
- **A time of day is a column type.** A column, an input field and a project
  function parameter or result may declare `time`, a time of day to the whole
  second with no date and no zone. Text `hh:mm` or `hh:mm:ss` parses into it,
  it writes as `hh:mm:ss`, and it compares only with another `time`. `to_time`
  takes a datetime's time of day, and `TIME '08:30'` writes one in an
  expression. CSV and Dataset-JSON carry its text, Parquet a zone-free
  microsecond `Time` (and reads milliseconds and nanoseconds), a SAS
  transport file seconds since midnight under `ADaM` with `TIME8.`, Python a
  `datetime.time` and R an `hms`. A Dataset-JSON `time` column now reads as
  `time` rather than `str`; declare it `str` to keep its text. An `SDTM` or
  `SEND` dataset refuses a `time` output column as it refuses a `datetime`
  one (VALUE-1, TIME-23, PARQUET-1, DSJSON-2, SUB-25, SUB-27, #4267 D334).
- **An in-memory input keeps the unit its library gives a datetime or a
  time.** Python `spec.run(inputs=...)` reads a zone-free timestamp or time of
  day in milliseconds, microseconds or nanoseconds as well as in seconds, so
  the datetime and time columns of a pandas, Polars or PyArrow frame, and of
  one read back from a Parquet file, are read as the file's are. Each value
  must fall on a whole second, as a stored one must (PARQUET-9). A fraction of
  a second is still refused, now with the code `temporal` where it was
  `array_type`, and a timestamp with a zone is refused as before (SCHEMA-12,
  #4780 D360).
- **A csv artifact may write a missing value as `.`.** `output.missing: "."`
  writes every missing value of the artifact as a bare dot, as a NONMEM data
  file expects, in place of the empty field; the columns stay typed, so
  `output.decimals` still applies. It is refused on a Parquet output, on an
  artifact a consumer links or a transport reads, both as
  `missing_text_not_applicable`, and when a `str` value is the dot, as
  `missing_text_collision` (CSV-17, #4631 D343).
- **A csv source reads a carriage return inside a quoted field as part of
  the value.** A field such as `"line1` CR LF `line2"`, which a csv artifact
  writes for free text typed on Windows, was refused as
  `source_carriage_return`, so a specification could not read the artifact
  another one published; it now reads back exactly as written. A carriage
  return outside quotes that does not begin a line ending is still refused
  (CSV-11, #4852, D374).
- **A csv input may be read as positional text.** An input whose `path`
  ends in `.csv` and that declares `fixed_width`, each field's name and its first and last character
  positions, reads every line as fields at those positions, with no
  separator, quoting or header; each field is trimmed of spaces and missing
  when blank, and `skip` drops leading lines such as a banner. A line shorter
  than its fields fails as the new `source_record_short`, and positions that
  overlap or run out of order as the new `fixed_width_columns_invalid`; a
  file of another extension, such as `typed.dat`, still fails as
  `source_profile_unknown` (INPUT-1) (CSV-18, #4902, D394).
- **An in-memory input names the column it refuses.** An unsupported type or
  a refused value reports the frame's `column`, its Arrow `type` and a value's
  `record` where it reported a `value`; a column of another type than the
  input declares fails as `incompatible_input_type` at `inputs.<alias>`, where
  it failed as `engine_rejected`; and a column with no value is missing in its
  declared type (SCHEMA-12, INPUT-5, #4881, D377).
- **`to_date` reads the date of a `--DTC` with a fractional second or an
  offset.** `2025-03-15T10:30:15.250` gives `2025-03-15` and
  `2025-03-16T10:30+01:00` gives `2025-03-16`, the date as written, with no
  zone arithmetic; such text still converts to no `datetime` (TIME-2, D379).
- **`shift` moves a date by calendar months or years.** With `type: date`, an
  integer `amount` in `unit: month` or `unit: year` replaces `days`, its day
  clamped to its month's length as `diff` counts anniversaries; a datetime
  refuses `month` and `year` as `value_not_permitted` (TIME-14, D380).
- **R `run(inputs = ...)` converts a character or factor column without a
  per-value R call**, under a second for a million rows, and a refused value
  names its column, row and bytes (#4883).
- `dtc` takes `placeholders: true` to write the SDTM placeholder form, a `-`
  for each missing part before a present one, so a year and a day give
  `2025---15`; the default truncated form is unchanged (TIME-19, #4878 D389).

### Rows, lookups and relations

- **A column whose row templates derive it differently admits `Derived`.**
  When a column's `rows` entries are of different derivation kinds, such as a
  bare read in one template and a literal in another, the column now admits
  a `Derived` origin besides the types every entry admits, since choosing per
  row between the templates derives the value; before, `Derived` failed as
  `origin_contradicts_derivation`. A value-level entry over such rows admits
  it too. `Predecessor` is still refused unless every entry is a bare read,
  and a column whose entries are all of one kind admits what it did (SUB-19,
  SUB-13, #4734, #4064 D318).
- **A row failing before its template's filter says so.** When one of a row
  template's own derivations fails on a candidate row whose keys are all
  derived, before the template's `filter` runs, the finding's context names
  that filter as `template_filter`, and a `missing_input` finding explains
  that the filter runs only after the row's derivations (COLUMN-9, #4272
  D331).
- **A one-record table is read without a join key.** A named intermediate may
  write `key: none`, so every row reads every record of its dataset: one record
  is read by every row, none gives the absence answer, and several fail as
  `multiple_matches` unless `keep` chooses one. A study-level settings table
  no longer needs a constant column derived on both sides to join on. An
  intermediate `key` written as a bare string other than `none`, such as
  `key: USUBJID`, now fails as `value_not_permitted` rather than
  `invalid_field_type` (LOOKUP-5, #4271 D332).
- **Several supplemental qualifiers are read through one lookup.** A named
  intermediate may write `pivot: {name, value, fields}`: each listed name
  becomes a field of its selection, holding the `value` of the one candidate
  whose `name` equals it, selected per name by `order_by` and `keep` or
  `nearest`, missing or the `absent` value when there is none, and failing as
  `multiple_matches` when there are several. A candidate whose name is not
  listed fails the read as `unlisted_pivot_name`, so a qualifier the
  specification forgot stops the run instead of leaving a column empty. The
  qualifiers of a SUPP-- dataset no longer need one lookup per `QNAM`
  (LOOKUP-28, #4310 D339).
- **An aggregate narrows on a value it derives for each record.** A qualified
  aggregate's `filter` and `between` bounds may now name a variable its
  `derivations` bind, as its reducer and `order_by` already could, so a count
  of the records dated on or before a subject's anchor date, whose date is
  derived from collected text, needs no staged specification. The bindings
  then evaluate on every record whose keys match, before the range and the
  filter, as a named intermediate's derivations do; an aggregate whose filter
  and range read only stored fields evaluates them as before, on the records
  they keep (LOOKUP-22, #4309 D335).
- **A lookup reads the current row's columns by the output domain.** A named
  intermediate's `filter` and `derivations` may read a column of the current
  row qualified by the output `domain`, such as `ADLES.SDAGE`, as its `key`
  already reads columns; a bare name there still reads the lookup's own
  records. A value the whole output reduces, such as a study's standard
  deviation, now reaches a donor's distance from one specification, so the
  nearest donor of a missing outcome is chosen without a staged producer. A
  reducer written in a lookup's derivations is still refused as
  `prohibited_function`, now with a `hint` naming that column route
  (NAME-3, LOOKUP-8, LOOKUP-15, #4506 D313).
- **Several lookups can read one intermediate's derived fields.** A named
  intermediate's `dataset` may name another named intermediate that a row
  template could drive on, a record relation: its records, those its filter
  keeps with its derivations complete, are built once and read as an input's,
  with a `key` of its own, so a dose record's imputed start, interval and
  span are declared once and read by the dose rows, the first-dose lookup and
  the prior-dose lookup alike. A keyed qualified aggregate reads them the same
  way. A record relation that declares a `key` or a selection, reads no input,
  or whose filter or derivations read the current row, is refused as
  `invalid_intermediate_driver` at the reader's `dataset` (LOOKUP-3,
  #4630 D344).
- **A record builds one row for each unit of its count.** A named
  intermediate may write `repeat: {count, index}`: each record of its
  `dataset` is kept once for each whole number from 1 to its `count`, an
  `int` the record's own fields give, and `index` names that number for the
  relation's `filter` and `derivations`. A row template drives on the
  relation, and it is looked up and aggregated as a pair relation is. A count
  of zero builds no record, a missing or negative count fails the run as
  `invalid_repeat_count`, and a count that is not an `int` is refused at
  validation. An exposure record for a span of days becomes one row
  per administration without a table of day numbers, which could run short
  or leave a day out. No existing specification changes meaning (LOOKUP-29,
  ROW-7, #4628 D316).
- **A pair relation's side read as a lookup is refused before the run.** In
  a dataset built at its key grain, a column, formula, `case` or dataset
  verification that reads a pair relation's side, which declares no `key`,
  now fails as `missing_required_field` at the side's `key`, as LOOKUP-3
  states; before, it read every record of the side and failed during the run
  as `multiple_matches`, or read the only one (#4673).
- **A lookup derivation that reads a name its own map derives is refused
  before data.** Within a lookup's `derivations:`, a name the map derives
  names that derivation, so a read of it in that derivation or an earlier
  one, such as `STUDYID: SRC.STUDYID`, fails as `unknown_field` whether or
  not the input stores the name, and `check()` reports it. A stored namesake
  still adds its `duplicate_derivation`, reported first (LOOKUP-15, #4754
  D350).
- **Calculated history runs over rows built from different inputs.** A
  feedback group of backward `row_value` reads is admitted when the row
  templates that leave its columns to the column phase read different inputs,
  and one history runs through each partition across all of their rows,
  where the group was refused as `dependency_cycle` (WINDOW-12, #4744)
  (D347).

### Limits

- **A specification reads any number of inputs.** The limit of 16 inputs to
  one specification is gone, so a subject-level dataset need not be split into
  producer specifications to stay under it; each input is still bounded as a
  file (LIMIT-2, #4462 D311).
- **A table has no fixed maximum of rows, columns or cells.** The limits of
  10,000,000 rows, 640,000,000 cells and 1,024 columns are gone, with every
  `engine_rejected` refusal they gave (`table_rows`, `table_cells`, `columns`,
  `output_rows`, `output_cells`, `output_columns`, `source_fields`,
  `projected_columns` and the like), and the `table_limit` code, so a run over
  6,500,000 driver rows of 100 columns builds instead of being refused; a
  table memory cannot hold fails as the process runs out of it. A SAS Transport
  file refuses more than 9,999 variables, which its header cannot count
  (LIMIT-2, LIMIT-3, #4773 D356).
- **A count no memory holds is refused at its relation.** A counted relation
  whose count memory cannot hold now fails the run as `engine_rejected` at
  `repeat.count` with `step` `execute` and the new `code` `allocation`, which
  any reservation memory refuses reports, instead of `step` `build` and
  `code` `result_projection` with no path (LOOKUP-29, LIMIT-2, #4783 D362).
- **A run reserves the records an input frame without columns claims.** Such
  a frame claims its records without holding them. A run now reserves the
  generated `ordinal` field and a row template's records before it builds
  them, so memory that refuses either fails the run as `engine_rejected` with
  `step` `execute` and `code` `allocation`, at `input.<dataset>.ordinal` for
  the field. A frame whose batches claim more records together than the
  platform counts is refused when it is given, with the table code
  `representation` (LIMIT-2, #4782 D364).
- **A SAS Transport member holds at most 2,147,483,647 records.** A member of
  more, which a file of one-byte records can hold, fails as
  `source_sas_invalid` with cause `malformed` (SAS-7, #4782).

### Projects

- **A cleared output report or schema link is not read.** A project now
  composes a specification whose layer clears an inherited `output.report`
  or `input.<name>.schema` as `resolve()` shows it. A submission no longer
  fails with `resource_path_missing` at the `clear` entry because the cleared
  report does not exist, and an input whose schema link is cleared reads a
  listed artifact without a link, `unlinked_producer`, instead of passing the
  project check and then failing its run (LAYER-9, PROJECT-10, PROJECT-15,
  #4733).
- **A project finding names the layer it is located in.** An
  `unlinked_producer` or `producer_not_completed` finding about an input a
  parent layer writes is located in that layer, and its `context.source` now
  names that layer, as a finding located above the entry does elsewhere,
  where it named the entry; `context.entry` still names the listed
  specification (PROJECT-10, PROJECT-11, #4733 D346).

### Submissions and Define-XML

- **A value-level where clause can order a column against one value.** A
  where column that is not `str` may be written `{comparator: LT, values:
  ['2026-03-01']}`, or with `LE`, `GT` or `GE`, so the rows before a date and
  those from it, or the rows below and above a threshold, get their own
  metadata without a text column added only to select them. The value
  converts to the column's type before any data is read, a missing value is
  never selected, and define.xml writes the comparator in its `RangeCheck`,
  with an `ADaM` date's value as its SAS number, as the item is typed. A
  `str` column ordered fails as `value_level_where_invalid`, reason
  `ordered_str`, and a value that does not convert with reason `value_type`
  (SUB-12, DEFINE-27, #4064 D314, #4526).
- **Reproduced metadata can leave a received column out of the document.**
  A column whose `submission` declares `omitted: true`, and nothing else,
  stays in the output dataset, while define.xml writes no `ItemRef` or
  `ItemDef` for it and numbers the others from 1. A where clause that names
  such a column fails as `value_level_where_invalid`, reason `omitted`, and a
  dataset that omits every column as `value_not_permitted`. Validated
  metadata refuses the field, and a column's free-form `metadata` map may no
  longer carry a key named `omitted` (DEFINE-30, SUB-12, SUB-2, #4757
  D357, #4751).
- **Reproduced metadata can keep a received `ItemRef` order.** A column's
  `submission.order` sets its `ItemRef`'s `OrderNumber`, and define.xml lists
  the `ItemRef`s in that order while the dataset keeps `output.columns` order.
  It is optional, but once one described column of a dataset declares it,
  every one does; a missing one fails as `submission_metadata_missing`, and a
  repeated or non-positive one as `value_not_permitted`. Validated metadata
  refuses the field, and a column's free-form `metadata` map may no longer
  carry a key named `order` (DEFINE-18, DEFINE-30, SUB-2, #4752 D358).
- **A reproduced value-level entry writes only what it declares.** Under
  `submission.mode: reproduced`, a per-value definition takes from its column
  only the name, and the `data_type` and `mandatory` it does not declare
  itself; its description, codelist, length, display format, significant
  digits, origins, method and comment appear only when the entry declares
  them, so a received 2.0 value list is reproduced as it was. Reproduced
  define.xml bytes change for entries that declared fewer fields than their
  column (DEFINE-30, DEFINE-27, #4734, #4064 D319).
- **A reproduced where clause may name its own column.** A reproduced value
  list keyed by the column it describes, such as entries of `PARAMCD`
  selected by `PARAMCD`, composes; validated metadata still refuses it with
  reason `self` (SUB-12, DEFINE-30, #4734, #4064 D320).
- **A reproduced method or comment keeps its received OID.** Under
  `submission.mode: reproduced`, a method or comment written in full may
  declare `oid`, such as `MT.SAFFL` or `COM.TRT01PN`, and the document writes
  it in place of the generated `MT.<dataset>.<column>` or `COM.` identifier.
  Elements that declare one `oid` with the same definition share one
  `MethodDef` or `def:CommentDef`; a different definition under one `oid`, or
  an `oid` equal to a generated one, fails as `duplicate_define_identifier`.
  Validated metadata refuses `oid` as `value_not_permitted` and keeps one
  definition per element (DEFINE-9, DEFINE-10, DEFINE-26, DEFINE-30, #4747
  D348).
  A method `oid` stays printable ASCII, so a received OID ending in a
  non-breaking space (U+00A0), which no NCName admits, fails as
  `pattern_mismatch` and is declared without it (DEFINE-9, #4935 D398).
- **A codelist `id` may join segments with periods.** A codelist may be
  declared as `ADSL.ARMCD`, and `submission.codelist` and `decode` name it
  so, giving the Define-XML `CodeList` the dataset-qualified OID
  `CL.ADSL.ARMCD` that submitted documents commonly carry. A leading,
  trailing or doubled period still fails as `pattern_mismatch`, and every
  other identifier is unchanged (CT-1, DEFINE-9, #4746 D349).
- **A value-level entry `id` may hold periods and hyphens.** An entry may be
  declared as `PARAMCD.IN.2feab8`, which its per-value `ItemDef`,
  `def:WhereClauseDef`, `MethodDef` and `def:CommentDef` end in, so a received
  per-value OID such as `IT.ADVS.AVAL.PARAMCD.IN.2feab8` is written as
  received. A finding names such an entry `value_level['PARAMCD.IN.2feab8']`.
  A received per-value method OID that ends otherwise, such as
  `MT.ADVS.AVAL.FEVER`, is still declared only by a reproduced method's `oid`
  (SUB-12, DEFINE-9, DEFINE-30, #4801 D366).
- **A supporting document `id` may hold periods and hyphens.** A document
  may be declared as `Table_14-3.01`, and its `def:leaf` is
  `LF.Table_14-3.01`, so a received leaf ID is written as received; a
  document reference names it with the same spelling. The `LF.` prefix is
  generated, so the received `LF.t1402010101` is the document `t1402010101`
  (DEFINE-9, DEFINE-13, #4824 D371).
- **Codelists may share a `name`.** Two codelists of different `id`s may
  carry one `name`, and a Define-XML document writes each under its own
  `CodeList` OID, as Define-XML requires only the OID to be unique. A
  repeated `name` no longer fails as `duplicate_define_identifier`; a
  repeated `id` within one source still does (CT-1, #4787 D363).
- **A section may declare its Study OID.** `study_oid` on `sdtm`, `adam` or
  `send` is the Define-XML `Study` OID and the Dataset-JSON `studyOID`, written
  as declared, such as a received document's OID that repeats its `FileOID`;
  omitted, both stay `STDY.<study.id>` (D354).
- **A section may name its source system.** `source_system` sets the
  `SourceSystem` that Define-XML's `ODM` header carries and the
  `sourceSystem.name` of each Dataset-JSON file, beside
  `source_system_version`, so a document naming another generator can be
  reproduced. Omitted, the name is `yamaa` as before (DEFINE-12, JSON-7,
  #4768 D355).
- **A submission's `created` may end with `Z`.** `created="2021-04-30T19:31:53Z"`
  marks the creation time as UTC, as submitted Define-XML documents commonly
  write it, where it was refused as `value_not_permitted`. define.xml's
  `CreationDateTime` and each Dataset-JSON `datasetJSONCreationDateTime`
  carry it as given, and an XPT header writes its civil time. A numeric
  offset such as `+01:00` is still refused, and an omitted `created` still
  writes the UTC time without `Z` (DEFINE-3, #4767 D353).
- **An `adam` section declares analysis results metadata.**
  `adam.analysis_results` lists sources, each written inline or as the path
  of a `type: analysis_results` file, the fifth file type: result displays,
  the analysis results each shows with a `reason` and a `purpose`, the
  datasets, where clause and variables each result reads, how its datasets
  are joined, and its documentation and programming code. Composition
  resolves every dataset, column and document they name, with the new
  conditions `unknown_dataset` and `analysis_dataset_invalid`, derives
  `ParameterOID`, and writes `arm:AnalysisResultDisplays` (ARM v1.0) under
  every Define-XML release. A where value is written as text, as
  `AVISITN: ['24']`, and converts to its column's type. A variable or where
  column that names a column reproduced metadata omits fails with reason
  `omitted`, and such a `PARAMCD` is not a result's parameter. The new file
  type is a host surface too: `schema("analysis_results")` gives its JSON
  Schema, and an `unexpected_file_type` finding now lists five types. Nothing
  breaks: a document without the field keeps its bytes (DEFINE-31, DEFINE-32,
  SCHEMA-2, #4756 D359).
- **A result display or an analysis result may declare its received OID.**
  `oid` on a display or a result is its `arm:ResultDisplay` or
  `arm:AnalysisResult` OID, written as declared, such as a received
  document's `RD.Table 14.2.2.1.3.1.1` or `AR.Table1`; it keeps its `RD.` or
  `AR.` prefix and may hold spaces. Omitted, the OIDs stay `RD.<id>` and
  `AR.<display>.<id>`, and the `id`s still build the where clause and join
  identifiers (DEFINE-9, #4812 D365).
- **A Define-XML 2.0 document writes sponsor-extended codelist items.** A
  2.0 section now admits the terminology standard a codelist source names,
  which it does not write, as 2.0 has no place for it; an `extended: true`
  item of an extensible published codelist then writes
  `def:ExtendedValue="Yes"`, in validated and reproduced mode alike, where the
  section was refused before. A second implementation guide is still refused
  (CT-6, DEFINE-29, #4734, #4064 D321).
- **A Define-XML 2.0 origin refusal names the origin it refuses.** An origin
  type or source a 2.0 document cannot carry, such as `Other` under SDTM or
  ADaM, is reported at `origins[N].type` or `origins[N].source` with the
  declared type or source as its `value`, where it was reported at `origins`

- **A Define-XML 2.0 document writes an eDT origin.** Under SDTM and ADaM, a
  `Collected` origin with `source: Vendor` is written as
  `<def:Origin Type="eDT"/>` in a 2.0 document, in validated and reproduced
  mode alike, where it was refused; `Collected` from `Subject` is still
  refused (DEFINE-29, #4817) (D368).
- **A project check reports origins a Define-XML 2.0 document cannot
  record.** In a section with `define_version: 2.0.0`, `project.check()`
  reports each such origin, such as `Other` under ADaM, with the
  `value_not_permitted` refusal composition makes (DEFINE-25). It reports it
  at the origin's `type` or `source` in the specification, before any
  document is composed (PROJECT-7, DEFINE-29, #4825) (D370).
- **One transport refusal lists every column of a dataset.**
  `transport_text_invalid` now reports one finding per dataset whose `values`
  list every column holding text the transport cannot carry, each with its
  first such row, key values, value and cause, so one run finds them all; the
  context's `column`, `row`, `key_values`, `value` and `cause` move into those
  entries (XPT-7, #4734, #4064 D317).
- **A submission rechecks the published rows against the keys and mandatory
  columns it states.** A section that requests a transport now refuses an
  artifact holding a missing value in a column or value-level entry the
  document declares `Mandatory`, as `not_missing_failed`, and one whose key
  values are missing or repeated, as `missing_key` or `duplicate_key`, before
  any file is written. Before, an artifact saved under an earlier
  specification, or left by a failed run, was packaged with 0 issues
  (JSON-5, SUB-11, OUTPUT-3, #4816 D367).
- **A reproduced value-level entry keeps its received `ItemDef` OID and
  `Name`.** Under `submission.mode: reproduced`, an entry may declare `oid`,
  beginning `IT.`, written on its per-value `ItemDef` and the value-list
  `ItemRef` that cites it, and `name`, the `ItemDef` `Name` in place of the
  column's; `SASFieldName` stays the column's. Validated metadata refuses both
  as `value_not_permitted` (DEFINE-9, DEFINE-30, #4847 D323).
- **Reproduced where clauses keep their received OID and share it.** An entry
  may declare `where_oid`, beginning `WC.`, and an analysis dataset over a
  reproduced dataset may too; where clauses that declare one `where_oid` with
  the same range checks share one `def:WhereClauseDef`, across columns and
  analysis results, and a different condition under one `where_oid` fails as
  `duplicate_define_identifier`. Validated metadata refuses it as
  `value_not_permitted` (DEFINE-9, DEFINE-10, DEFINE-30, DEFINE-32, #4848
  D324).
- **A where condition may state `EQ` or `IN`, and reproduced metadata records
  a one-value `IN` or `NOTIN` and an empty value.** `comparator` also takes
  `EQ`, with one value, and `IN`, which writes that comparator with the values
  listed; in reproduced metadata `IN` and `NOTIN` take one value or more and a
  where value may be `''`, written as an empty `CheckValue`. Validated metadata
  keeps two or more for `IN` and `NOTIN`, and an empty where value, which
  failed as `minimum_length`, now fails as `value_level_where_invalid` or
  `analysis_dataset_invalid` with reason `empty_value` (SUB-12, DEFINE-27,
  DEFINE-30, #4849 D325).
- **A codelist item may declare its `OrderNumber`.** `order` on a codelist
  item writes `OrderNumber` on its `EnumeratedItem` or `CodeListItem`; a

- **A section may leave `xml:lang` out.** `xml_lang_scope` on `sdtm`, `adam`

### Refusals that say what to fix

- **A refused read of a driver's derived field names its remedy.** A
  column-level derivation that reads a field a row-driving intermediate
  derives is still refused as `unsupported_operation`, and its context now
  carries a `hint`: derive the field into a column in each row template the
  intermediate drives, then read that column (ROW-2, #4269 D333).
- **Three refusals say what to fix.** A static comparison that fails because one
  operand is a field of a delimited input that `types` leaves undeclared, and
  so reads as `str`, carries a `hint` naming the field and saying that its
  input's `types` declare no type for it, and its message names both
  operands' types instead of only the right one's (FORMULA-5, INPUT-5). A result wrapper's `value` and
  `unconvertible` written where only an expression fits, such as a case's
  `otherwise`, carries a `hint` that says where the wrapper goes (SCHEMA-7,
  COLUMN-13, LOOKUP-15). A limit refusal's message names the resource, its
  limit and, when known, the size found, which its context already held
  (LIMIT-1, #4458, #4459, #4460 D309).
- **Two more refusals say what to write instead.** A call of a function that
  another SQL dialect or SAS has and the grammar refuses, such as `UPPER`,
  `COALESCE`, `ROUND` or `LOG`, carries a `hint` naming the registered
  expression, such as `str_case` with `to: upper` (noting that it changes
  ASCII letters only), or the functions that replace it; in a predicate it
  says to write that expression in a derivation, and in an aggregate where it
  goes for a reduced value and for the result; the names are listed under
  `replaced` in the expression grammar (FORMULA-13). A number or Boolean
  written as the last of `first_available`'s `sources` carries a `hint` to
  write it as `missing` (EXPR-9). The `prohibited_function` and
  `invalid_field_type` messages now print a finding's `hint`, so a list
  written at `parent` prints its hint too, and the hint of a retired `ROUND`,
  `COALESCE`, `GREATEST` or `LEAST` call calls its replacement an expression
  rather than an operation (#4463, #4064 D312).
- **Four more refusals say what to write instead.** A text verb's source of
  type `int`, `float`, `date`, `datetime` or `time` records `convert_to: str`,
  and the message says to derive it with that type first (TEXT-1). A lookup
  `filter` field qualified by another intermediate that the lookup's
  `derivations` can read carries a `hint` to read that field there (LOOKUP-7,
  LOOKUP-16). A key written beside an
  operation that belongs inside it, such as `severity` beside a short-form
  `unique`, carries a `hint` naming the operation's fields (SCHEMA-7). A
  qualified name in a column's formula says to bind it to a column first
  (FORMULA-9, #4517 D342).
- **Four refusals met writing an ADPPK say what to write instead.** An
  operation whose class requires one field, written with that field's value
  in place of its mapping, such as `to_date: PC.PCDTC`, carries a `hint`
  naming the mapping, `{source: PC.PCDTC}` (SCHEMA-12). The message of a
  column that some row templates leave without a value names those
  templates, which its context already held, and says to derive it `null`
  there or on the column (SPEC-5). The message of a key that reads an output
  column that is not an earlier key names that column, also already in its
  context (COLUMN-7). A refused intermediate whose records a row template, a pair
  relation or a lookup reads no longer reads as one that drives rows
  (ROW-2, LOOKUP-3, LOOKUP-27, #4629 D345).
- **A long form that only restates its shorthand runs.** A mapping that holds
  nothing but what its shorthand fills, such as `aggregate: {expr: E}`,
  `str_template: {template: T}`, `D: {path: d.csv}`, `{source: {variable: X}}`
  or `- not_missing: {}`, means what the shorthand means, so validation now
  accepts it instead of refusing the run. `yamaa lint` still reports it as the
  finding `redundant_long_form` and `lint --fix` writes the shorthand. The
  validation condition `redundant_long_form` is retired in 0.9.0, and the
  catalogue lists it with `retired_in` 0.9.0 (SCHEMA-15, #4463 D340).
- **`check` types every predicate field.** A comparison whose operand types
  cannot be compared in a dataset or column verification's `require`, `when`
  or `filter`, the root `filter`, a row template's `filter`, a window
  `filter`, a structured `source` `filter` or an `aggregate` `filter` is now
  refused by `check` with the `incompatible_input_type` issue a run reports,
  and a run refuses it before any record is read, so a root or row filter
  over an empty input fails as it does over records. `check` no longer
  reports `incompatible_input_type` for a `case` or `flag` predicate, or an
  intermediate's filter, comparing an undeclared input field with a number:
  only the records decide whether the field is `str` or absent, and a run
  still refuses it (FORMULA-5, P9, D195, D199, #4854 D386). `check` still
  refuses arithmetic over such a field, typed `str` (FORMULA-12), even where
  the input does not store it and a run reports `unknown_field` instead
  (#4924 D397).
- The `duplicate_key` and `unique_failed` messages name the unit they count,
  repeated key combinations, not rows: "the output keys repeat for 1 of their
  distinct combinations" (OUTPUT-3, CHECK-10, #4857 D372).
- **An expression nested past the depth limit is refused at its field.** A
  derivation, predicate or aggregate text, or the pattern inside one, deeper
  than 128 levels reports `compiler_limit` at its specification path and line,
  as a verb's `pattern` already did, where it reported `resource_limit` in an
  `inheritance_` phase with no path or line (LIMIT-1, #4890 D391).

### Run report

- **Text order between date texts is reported.** A comparison (`<`, `<=`,
  `>`, `>=`, `BETWEEN`) or a lookup's `order_by` that orders two collected
  date texts of which one begins with the other, such as `2025-03-11` and
  `2025-03-11T07:30`, is decided by text order, not by time. A successful
  run now reports each place where that happened as a `warning` check,
  `text_date_order`, with the least such pair in its `DETAILS`; it changes no
  value and fails nothing (CHECK-27, #4516, #4064 D315).
- **A printed run counts its warnings.** The summary line of a run, and a
  project run's line for each specification, add `, 1 warning` or
  `, <n> warnings` when the
  run report holds a violated `warning` check, a declared verification's
  included (CHECK-2, #4516, #4064 D315).

### Lint

- **A pruned declaration is reported.** `lint()` now reports
  `unused_declaration` at an input, a named intermediate, a column or a row
  template's derivation that a specification writes and that the resolved
  specification prunes, since nothing the artifact needs reads it, naming
  what reads it. A layer reports only what it writes, an inherited column it
  relabels among it, so `yamaa lint` exits 1 on a file that declares such a
  member. Delete it, list it in `output.columns`, or suppress the finding with
  a reason; it has no fix (LAYER-11, LAYER-12, #4325 D336).
- **A listed function no specification calls is reported.** `lint()` now
  reports `uncalled_function` at the entry of a project file's `functions`
  that lists a function file whose function no specification of the project
  calls once resolved, whose tests a build therefore never runs. Only the
  project file that writes `functions` is read, and only when its project
  lists a specification; it has no fix (FUNC-2, FUNC-12, PROJECT-16, #4326
  D337).
- `lint` reports `number_for_text`, a YAML number a `str` column takes whose
  spelling differs from the text it converts to, which `fix` quotes, and
  `empty_text_comparison`, a comparison with `''` of a field that never holds
  an empty string (D382, #4858).
- The lint reports `window_tie`: a `locf`, `row_value` or `row_number` window
  whose `group_by` and `order_by` terms leave out a declared key, so a carried
  or neighbouring value depends on the order of the input records (#4877,
  D390). Runs are unchanged.

### Resolved specification

- **`resolve()` lists what pruning removed.** Each entry of the resolved
  specification gains `pruned`: every input, named intermediate, column and
  row template's derivation that composition wrote and that the resolved
  model no longer holds, then each value another layer wrote inside one, such
  as a study layer's label for a template column it leaves out, each with the
  file, line and column that wrote it (LAYER-1, LAYER-11, #4325 D338).

## Known issues

The command-line binaries are unsigned and not notarized. The YAML reader
remains a vendored copy of saphyr-parser 0.2.1 with reviewed fixes (#3969),
as described in the
[0.7.0 notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.7.0/docs/releases/0.7.0.md#known-issues).
That reader keeps one line break more than YAML 1.2 for a clipped block
scalar whose last line holds only indentation and that ends with no final
line break: `"a\n\n"` where YAML 1.2 gives `"a\n"`. saphyr-parser 0.4.1
fixes it upstream.
