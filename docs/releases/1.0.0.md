# yamaa 1.0.0

yamaa 1.0.0 is in development. These notes are written as it is built, and
become the notes of the 1.0.0 release.

## Upgrading

- **ASCII-declared ODM.** `read_odm()` and direct XML inputs accept US-ASCII
  declarations only with ASCII source bytes; other encodings remain unsupported
  (#4060).
- **Re-lock project functions.** A project function's lock pins the installed
  yamaa, so after upgrading yamaa every build that calls a project function
  fails with `runtime_artifact_mismatch` until its lock is made again.
  Regenerate each `environments.<host>.lock`, for example with
  `uv lock --upgrade-package yamaa` or `renv::snapshot()`, and re-run each
  function package's own tests (FUNC-3, #4047).
- **Join keys of a converted 0.5 file.** 0.5 chose the key of an
  intermediate, or of an implicitly joined input, on each run from the
  inputs' headers, while 1.0 uses the key written in the file. A key written
  when converting a 0.5 file therefore fixes a join that 0.5 decided per run,
  so check it against the inputs the study reads (#3030 D23, #4047).
- **A `Submission` section declares a transport.** Composing Define-XML under
  `context: Submission`, the default, now fails with `missing_required_field`
  at the section's `transport` when the section declares none. Add
  `transport` (`xpt`, `dataset_json` or `dataset_ndjson`), or set
  `context: Other` for a document that is not a submission (DEFINE-4, #4050).
- **A new lint finding.** `lint()` now reports `restated_inherited_value` at
  a value a layer writes exactly as it inherits it, such as an unchanged
  label or derivation, which stops following the parent once written, so
  `yamaa lint` exits 1 on such a layer. Remove the value to keep inheriting
  it, or suppress the finding with a reason; it has no fix (LAYER-6,
  LAYER-9, #4100).
