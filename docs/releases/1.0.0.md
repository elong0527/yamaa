# yamaa 1.0.0

yamaa 1.0.0 is in development. These notes are written as it is built, and
become the notes of the 1.0.0 release. The
[0.9.0 notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.9.0/docs/releases/0.9.0.md)
cover the changes released before it.

## Upgrading

- **Break: R `run(inputs = ...)` refuses a `POSIXct` column whose `tzone` is
  not `"UTC"` or `"GMT"`**, including the session's zone, where it shifted the
  clock times to UTC; convert with `lubridate::force_tz(x, "UTC")`. A project
  function's datetime result now also accepts `"GMT"` (#4882 D-next).
- **Rounded values change for written ties of large values.** The normal
  binary64 that a tie of at most fifteen significant digits reads as (its
  nearest, the even one at a midpoint) now rounds as that tie, away from zero,
  wherever the one rounding applies: `8753033.315` at two places is
  `8753033.32`, where it was `8753033.31`. The `prohibited_function` hint for
  `ROUND` states the rounding's tie rule (FORMULA-16, CSV-9, TEXT-15, #4864
  D-next).
- **A number wider than its declared width warns instead of failing the
  run:** a `length`, `significant_digits` or `w.d` `display_format` that
  understates an `int` or `float` column's values is a violated `warning`
  row of the run report, named `numeric_width`, and the run publishes its
  output; `numeric_width_failed` is no longer an issue (SUB-29, #4884
  D-next).
- **An output may no longer name a file its specification reads.**
  `output.path` or `output.report` naming an input's `path` or `schema`, the
  specification's own file, a layer, a dictionary or a project file now fails
  `check` and `run` with `artifact_path_collision` before anything is written,
  where a run replaced that file (OUTPUT-9, #4851 D-next).
- **Published values change for a constant group.** A group whose non-missing
  values are all equal now gives `MEAN` that value and `STDDEV` and `VARIANCE`
  exactly `0`, where the ordered sum could leave a last-place error: six
  values of 4.1 gave a mean of `4.1000000000000005` and a `STDDEV` near
  `1e-15`, so a `NULLIF(sd, 0)` guard never fired (FORMULA-19, FORMULA-24,
  #4859 D-next).
- **Break: a `source` binding with nothing to select among refuses
  `order_by` and `keep`, and an unfiltered one refuses `absent`.** On a read
  of the row's own driver record, an output column or a named intermediate
  they changed nothing; they now fail as `prohibited_construct` (LOOKUP-10,
  LOOKUP-24, #4856 D-next).
- **A datetime made from text without seconds is collected to the minute.**
  `2025-03-04T08:30` converted, ingested or written as a literal `datetime` now
  has collected precision `minute` and time imputation flag `S`, as `impute`
  gives it, where it was `second` with no flag (TIME-7, VALUE-16, #4879
  D-next).

## Changes

- The `duplicate_key` and `unique_failed` messages name the unit they count,
  repeated key combinations, not rows: "the output keys repeat for 1 of their
  distinct combinations" (OUTPUT-3, CHECK-10, #4857 D-next).
- `dtc` takes `placeholders: true` to write the SDTM placeholder form, a `-`
  for each missing part before a present one, so a year and a day give
  `2025---15`; the default truncated form is unchanged (TIME-19, #4878 D-next).
- **R `run(inputs = ...)` converts a character or factor column without a
  per-value R call**, under a second for a million rows, and a refused value
  names its column, row and bytes (#4883).
- `lint` reports `number_for_text`, a YAML number a `str` column takes whose
  spelling differs from the text it converts to, which `fix` quotes, and
  `empty_text_comparison`, a comparison with `''` of a field that never holds
  an empty string (D-next, #4858).

### Inputs

- **A csv source reads a carriage return inside a quoted field as part of
  the value.** A field such as `"line1` CR LF `line2"`, which a csv artifact
  writes for free text typed on Windows, was refused as
  `source_carriage_return`, so a specification could not read the artifact
  another one published; it now reads back exactly as written. A carriage
  return outside quotes that does not begin a line ending is still refused
  (CSV-11, #4852, D-next on #4064).
- **An in-memory input names the column it refuses.** An unsupported type or
  a refused value reports the frame's `column`, its Arrow `type` and a value's
  `record` where it reported a `value`; a column of another type than the
  input declares fails as `incompatible_input_type` at `inputs.<alias>`, where
  it failed as `engine_rejected`; and a column with no value is missing in its
  declared type (SCHEMA-12, INPUT-5, #4881, D-next on #4064).

### Language

- **`to_date` reads the date of a `--DTC` with a fractional second or an
  offset.** `2025-03-15T10:30:15.250` gives `2025-03-15` and
  `2025-03-16T10:30+01:00` gives `2025-03-16`, the date as written, with no
  zone arithmetic; such text still converts to no `datetime` (TIME-2, D-next
  on #4064).
- **`shift` moves a date by calendar months or years.** With `type: date`, an
  integer `amount` in `unit: month` or `unit: year` replaces `days`, its day
  clamped to its month's length as `diff` counts anniversaries; a datetime
  refuses `month` and `year` as `value_not_permitted` (TIME-14, D-next on
  #4064).
