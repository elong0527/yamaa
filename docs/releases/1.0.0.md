# yamaa 1.0.0

yamaa 1.0.0 is in development. These notes are written as it is built, and
become the notes of the 1.0.0 release. The
[0.8.0 notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.8.0/docs/releases/0.8.0.md)
cover the changes released before it, including the Parquet saved-output
change and concurrent execution.

## Changes

### Command line

- **The packages run the command line as themselves.** `yamaa.cli(arguments)`
  and `python -m yamaa` in Python, and `yamaa_cli(arguments)` in R, run one
  command of the `yamaa` command line over the package's own engine: a run of
  a specification that calls a project function verifies the project's lock
  and calls the functions installed in that interpreter, where the standalone
  binary refuses it as `unsupported_operation`. Each prints what the binary
  prints on the package's standard streams and returns the binary's exit
  status, and `--version` and `selftest` name the host and its version, which
  the text form prints on a `host version:` line. The commands moved from the
  binary into the facade's `cli` module, over a `Runtime` each client
  configures (D-next on #4064).
- **The standalone binary runs project functions through an interpreter's
  worker.** `yamaa run` of a project that calls project functions starts
  `python -m yamaa._worker` or the R package's worker in `Rscript`, in the
  interpreter `--interpreter` names or the one found on `PATH`, and runs the
  functions there as the package's own `run()` runs them, verifying the
  lock first. `--host python|r` names the language; without it, the one
  language the project names an `environments` entry for, or else the one
  its function files implement, runs them, and a project that names both
  runs none, as before. The run's JSON document gains `host`. The worker's
  package must carry the binary's engine version, which a declared lock's
  verification checks as `runtime_artifact_mismatch` of `yamaa`. The
  command-line conformance runs still start no worker (D-next on #4064).

### Specification language

- **Numeric text may have digits on one side of its decimal point only.**
  `.5`, `5.` and `-.5` now parse as numbers when text converts to `int` or
  `float` and when a typed input reads a field, as SAS reads them; before,
  they failed to parse, so `unconvertible` replaced them alongside text such
  as `abc`. Formula literals are unchanged (VALUE-6, INPUT-7, #4461 D310).
- **A date can become a datetime at a named time of day.** `impute` with
  `type: datetime` now also takes a `date` source and supplies its time of day
  from `time: first` (`00:00:00`) or `time: last` (`23:59:59`). The result
  keeps the date's collected precision, so the time imputation flag reads `H`.
  A date still never converts to a datetime implicitly (TIME-8, VALUE-18,
  #4270 D-next).
- **Two dates give an ISO 8601 calendar duration.**
  `calendar_duration: {start, end}` writes the calendar time from one date to
  another as text such as `P1M1D`: the whole months `diff` counts, as years
  and months, then the remaining days. Equal dates give `P0D`, an earlier
  `end` a leading `-` and a missing date missing, and an operand that is not a
  `date` fails as `incompatible_input_type`. `str_template` joins it with a
  date into interval text such as `P1M1D/2007-09-27` (TIME-24, #4505 D-next).
- **A value-level where clause can order a column against one value.** A
  where column that is not `str` may be written `{comparator: LT, values:
  ['2026-03-01']}`, or with `LE`, `GT` or `GE`, so the rows before a date and
  those from it, or the rows below and above a threshold, get their own
  metadata without a text column added only to select them. The value
  converts to the column's type before any data is read, a missing value is
  never selected, and define.xml writes the comparator in its `RangeCheck`,
  with an `ADaM` date's value as its SAS number, as the item is typed. A
  `str` column ordered fails as `value_level_where_invalid`, reason
  `ordered_str`, and a value that does not convert with reason `value_type`
  (SUB-12, DEFINE-27, #4064 D314, #4526).
- **A historical value-level entry writes only what it declares.** Under
  `submission.mode: historical`, a per-value definition takes from its column
  only the name, and the `data_type` and `mandatory` it does not declare
  itself; its description, codelist, length, display format, significant
  digits, origins, method and comment appear only when the entry declares
  them, so a received 2.0 value list is reproduced as it was. Historical
  define.xml bytes change for entries that declared fewer fields than their
  column (DEFINE-30, DEFINE-27, #4734, D-next on #4064).
- **A historical where clause may name its own column.** A historical value
  list keyed by the column it describes, such as entries of `PARAMCD`
  selected by `PARAMCD`, composes; validated metadata still refuses it with
  reason `self` (SUB-12, DEFINE-30, #4734, D-next on #4064).
- **A column whose row templates derive it differently admits `Derived`.**
  When a column's `rows` entries are of different derivation kinds, such as a
  bare read in one template and a literal in another, the column now admits
  a `Derived` origin besides the types every entry admits, since choosing per
  row between the templates derives the value; before, `Derived` failed as
  `origin_contradicts_derivation`. A value-level entry over such rows admits
  it too. `Predecessor` is still refused unless every entry is a bare read,
  and a column whose entries are all of one kind admits what it did (SUB-19,
  SUB-13, #4734, D-next on #4064).
- **A row failing before its template's filter says so.** When one of a row
  template's own derivations fails on a candidate row whose keys are all
  derived, before the template's `filter` runs, the finding's context names
  that filter as `template_filter`, and a `missing_input` finding explains
  that the filter runs only after the row's derivations (COLUMN-9, #4272
  D-next).
- **A one-record table is read without a join key.** A named intermediate may
  write `key: none`, so every row reads every record of its dataset: one record
  is read by every row, none gives the absence answer, and several fail as
  `multiple_matches` unless `keep` chooses one. A study-level settings table
  no longer needs a constant column derived on both sides to join on. An
  intermediate `key` written as a bare string other than `none`, such as
  `key: USUBJID`, now fails as `value_not_permitted` rather than
  `invalid_field_type` (LOOKUP-5, #4271 D-next).
- **Several supplemental qualifiers are read through one lookup.** A named
  intermediate may write `pivot: {name, value, fields}`: each listed name
  becomes a field of its selection, holding the `value` of the one candidate
  whose `name` equals it, selected per name by `order_by` and `keep` or
  `nearest`, missing or the `absent` value when there is none, and failing as
  `multiple_matches` when there are several. A candidate whose name is not
  listed fails the read as `unlisted_pivot_name`, so a qualifier the
  specification forgot stops the run instead of leaving a column empty. The
  qualifiers of a SUPP-- dataset no longer need one lookup per `QNAM`
  (LOOKUP-28, #4310 D-next).
- **A refused read of a driver's derived field names its remedy.** A
  column-level derivation that reads a field a row-driving intermediate
  derives is still refused as `unsupported_operation`, and its context now
  carries a `hint`: derive the field into a column in each row template the
  intermediate drives, then read that column (ROW-2, #4269 D-next).
- **Three refusals say what to fix.** A static comparison that fails because one
  operand is a field of a delimited input that `types` leaves undeclared, and
  so reads as `str`, carries a `hint` naming the field and saying that its
  input's `types` declare no type for it, and its message names both
  operands' types instead of only the right one's (FORMULA-5, INPUT-5). A result wrapper's `value` and
  `unconvertible` written where only an expression fits, such as a case's
  `otherwise`, carries a `hint` that says where the wrapper goes (SCHEMA-7,
  COLUMN-13, LOOKUP-15). A limit refusal's message names the resource, its
  limit and, when known, the size found, which its context already held
  (LIMIT-1, #4458, #4459, #4460 D309).
- **Two more refusals say what to write instead.** A call of a function that
  another SQL dialect or SAS has and the grammar refuses, such as `UPPER`,
  `COALESCE`, `ROUND` or `LOG`, carries a `hint` naming the registered
  expression, such as `str_case` with `to: upper` (noting that it changes
  ASCII letters only), or the functions that replace it; in a predicate it
  says to write that expression in a derivation, and in an aggregate where it
  goes for a reduced value and for the result; the names are listed under
  `replaced` in the expression grammar (FORMULA-13). A number or Boolean
  written as the last of `first_available`'s `sources` carries a `hint` to
  write it as `missing` (EXPR-9). The `prohibited_function` and
  `invalid_field_type` messages now print a finding's `hint`, so a list
  written at `parent` prints its hint too, and the hint of a retired `ROUND`,
  `COALESCE`, `GREATEST` or `LEAST` call calls its replacement an expression
  rather than an operation (#4463 D-next).
- **Four more refusals say what to write instead.** A text verb's source of
  type `int`, `float`, `date`, `datetime` or `time` records `convert_to: str`,
  and the message says to derive it with that type first (TEXT-1). A lookup
  `filter` field qualified by another intermediate that the lookup's
  `derivations` can read carries a `hint` to read that field there (LOOKUP-7,
  LOOKUP-16). A key written beside an
  operation that belongs inside it, such as `severity` beside a short-form
  `unique`, carries a `hint` naming the operation's fields (SCHEMA-7). A
  qualified name in a column's formula says to bind it to a column first
  (FORMULA-9, #4517 D-next).
- **Four refusals met writing an ADPPK say what to write instead.** An
  operation whose class requires one field, written with that field's value
  in place of its mapping, such as `to_date: PC.PCDTC`, carries a `hint`
  naming the mapping, `{source: PC.PCDTC}` (SCHEMA-12). The message of a
  column that some row templates leave without a value names those
  templates, which its context already held, and says to derive it `null`
  there or on the column (SPEC-5). The message of a key that reads an output
  column that is not an earlier key names that column, also already in its
  context (COLUMN-7). A refused intermediate whose records a row template, a pair
  relation or a lookup reads no longer reads as one that drives rows
  (ROW-2, LOOKUP-3, LOOKUP-27, #4629 D-next).
- **A long form that only restates its shorthand runs.** A mapping that holds
  nothing but what its shorthand fills, such as `aggregate: {expr: E}`,
  `str_template: {template: T}`, `D: {path: d.csv}`, `{source: {variable: X}}`
  or `- not_missing: {}`, means what the shorthand means, so validation now
  accepts it instead of refusing the run. `yamaa lint` still reports it as the
  finding `redundant_long_form` and `lint --fix` writes the shorthand. The
  validation condition `redundant_long_form` is retired in 1.0.0, and the
  catalogue lists it with `retired_in` 1.0.0 (SCHEMA-15, #4463 D-next).
- **A specification reads any number of inputs.** The limit of 16 inputs to
  one specification is gone, so a subject-level dataset need not be split into
  producer specifications to stay under it; each input is still bounded as a
  file and a table (LIMIT-2, #4462 D311).
- **A time of day is a column type.** A column, an input field and a project
  function parameter or result may declare `time`, a time of day to the whole
  second with no date and no zone. Text `hh:mm` or `hh:mm:ss` parses into it,
  it writes as `hh:mm:ss`, and it compares only with another `time`. `to_time`
  takes a datetime's time of day, and `TIME '08:30'` writes one in an
  expression. CSV and Dataset-JSON carry its text, Parquet a zone-free
  microsecond `Time` (and reads milliseconds and nanoseconds), a SAS
  transport file seconds since midnight under `ADaM` with `TIME8.`, Python a
  `datetime.time` and R an `hms`. A Dataset-JSON `time` column now reads as
  `time` rather than `str`; declare it `str` to keep its text. An `SDTM` or
  `SEND` dataset refuses a `time` output column as it refuses a `datetime`
  one (VALUE-1, TIME-23, PARQUET-1, DSJSON-2, SUB-25, SUB-27, #4267 D-next).
- **An aggregate narrows on a value it derives for each record.** A qualified
  aggregate's `filter` and `between` bounds may now name a variable its
  `derivations` bind, as its reducer and `order_by` already could, so a count
  of the records dated on or before a subject's anchor date, whose date is
  derived from collected text, needs no staged specification. The bindings
  then evaluate on every record whose keys match, before the range and the
  filter, as a named intermediate's derivations do; an aggregate whose filter
  and range read only stored fields evaluates them as before, on the records
  they keep (LOOKUP-22, #4309 D-next).
- **A lookup reads the current row's columns by the output domain.** A named
  intermediate's `filter` and `derivations` may read a column of the current
  row qualified by the output `domain`, such as `ADLES.SDAGE`, as its `key`
  already reads columns; a bare name there still reads the lookup's own
  records. A value the whole output reduces, such as a study's standard
  deviation, now reaches a donor's distance from one specification, so the
  nearest donor of a missing outcome is chosen without a staged producer. A
  reducer written in a lookup's derivations is still refused as
  `prohibited_function`, now with a `hint` naming that column route
  (NAME-3, LOOKUP-8, LOOKUP-15, #4506 D313).
- **Several lookups can read one intermediate's derived fields.** A named
  intermediate's `dataset` may name another named intermediate that a row
  template could drive on, a record relation: its records, those its filter
  keeps with its derivations complete, are built once and read as an input's,
  with a `key` of its own, so a dose record's imputed start, interval and
  span are declared once and read by the dose rows, the first-dose lookup and
  the prior-dose lookup alike. A keyed qualified aggregate reads them the same
  way. A record relation that declares a `key` or a selection, reads no input,
  or whose filter or derivations read the current row, is refused as
  `invalid_intermediate_driver` at the reader's `dataset` (LOOKUP-3,
  #4630 D-next).
- **A pair relation's side read as a lookup is refused before the run.** In
  a dataset built at its key grain, a column, formula, `case` or dataset
  verification that reads a pair relation's side, which declares no `key`,
  now fails as `missing_required_field` at the side's `key`, as LOOKUP-3
  states; before, it read every record of the side and failed during the run
  as `multiple_matches`, or read the only one (#4673).
- **A csv artifact may write a missing value as `.`.** `output.missing: "."`
  writes every missing value of the artifact as a bare dot, as a NONMEM data
  file expects, in place of the empty field; the columns stay typed, so
  `output.decimals` still applies. It is refused on a Parquet output, on an
  artifact a consumer links or a transport reads, both as
  `missing_text_not_applicable`, and when a `str` value is the dot, as
  `missing_text_collision` (CSV-17, #4631 D-next).
- **One transport refusal lists every column of a dataset.**
  `transport_text_invalid` now reports one finding per dataset whose `values`
  list every column holding text the transport cannot carry, each with its
  first such row, key values, value and cause, so one run finds them all; the
  context's `column`, `row`, `key_values`, `value` and `cause` move into those
  entries (XPT-7, #4734, D-next on #4064).

- **A record builds one row for each unit of its count.** A named
  intermediate may write `repeat: {count, index}`: each record of its
  `dataset` is kept once for each whole number from 1 to its `count`, an
  `int` the record's own fields give, and `index` names that number for the
  relation's `filter` and `derivations`. A row template drives on the
  relation, and it is looked up and aggregated as a pair relation is. A count
  of zero builds no record, a missing or negative count fails the run as
  `invalid_repeat_count`, and a count that is not an `int` is refused at
  validation. An exposure record for a span of days becomes one row
  per administration without a table of day numbers, which could run short
  or leave a day out. No existing specification changes meaning (LOOKUP-29,
  ROW-7, #4628 D316).

- **A cleared output report or schema link is not read.** A project now
  composes a specification whose layer clears an inherited `output.report`
  or `input.<name>.schema` as `resolve()` shows it. A submission no longer
  fails with `resource_path_missing` at the `clear` entry because the cleared
  report does not exist, and an input whose schema link is cleared reads a
  listed artifact without a link, `unlinked_producer`, instead of passing the
  project check and then failing its run (LAYER-9, PROJECT-10, PROJECT-15,
  #4733).
- **A project finding names the layer it is located in.** An
  `unlinked_producer` or `producer_not_completed` finding about an input a
  parent layer writes is located in that layer, and its `context.source` now
  names that layer, as a finding located above the entry does elsewhere,
  where it named the entry; `context.entry` still names the listed
  specification (PROJECT-10, PROJECT-11, P-ISSUE-1, #4733 D-next).
- **A Define-XML 2.0 document writes sponsor-extended codelist items.** A
  2.0 section now admits the terminology standard a codelist source names,
  which it does not write, as 2.0 has no place for it; an `extended: true`
  item of an extensible published codelist then writes
  `def:ExtendedValue="Yes"`, in validated and historical mode alike, where the
  section was refused before. A second implementation guide is still refused
  (CT-6, DEFINE-29, #4734) (D-next on #4064).

### Run report

- **Text order between date texts is reported.** A comparison (`<`, `<=`,
  `>`, `>=`, `BETWEEN`) or a lookup's `order_by` that orders two collected
  date texts of which one begins with the other, such as `2025-03-11` and
  `2025-03-11T07:30`, is decided by text order, not by time. A successful
  run now reports each place where that happened as a `warning` check,
  `text_date_order`, with the least such pair in its `DETAILS`; it changes no
  value and fails nothing (CHECK-27, #4516 D-next).
- **A printed run counts its warnings.** The summary line of a run, and a
  project run's line for each specification, add `, <n> warnings` when the
  run report holds a violated `warning` check, a declared verification's
  included (CHECK-2, #4516 D-next).

### Lint

- **A pruned declaration is reported.** `lint()` now reports
  `unused_declaration` at an input, a named intermediate, a column or a row
  template's derivation that a specification writes and that the resolved
  specification prunes, since nothing the artifact needs reads it, naming
  what reads it. A layer reports only what it writes, an inherited column it
  relabels among it, so `yamaa lint` exits 1 on a file that declares such a
  member. Delete it, list it in `output.columns`, or suppress the finding with
  a reason; it has no fix (LAYER-11, LAYER-12, #4325 D-next).
- **A listed function no specification calls is reported.** `lint()` now
  reports `uncalled_function` at the entry of a project file's `functions`
  that lists a function file whose function no specification of the project
  calls once resolved, whose tests a build therefore never runs. Only the
  project file that writes `functions` is read, and only when its project
  lists a specification; it has no fix (FUNC-2, FUNC-12, PROJECT-16, #4326
  D-next).

### Resolved specification

- **`resolve()` lists what pruning removed.** Each entry of the resolved
  specification gains `pruned`: every input, named intermediate, column and
  row template's derivation that composition wrote and that the resolved
  model no longer holds, then each value another layer wrote inside one, such
  as a study layer's label for a template column it leaves out, each with the
  file, line and column that wrote it (LAYER-1, LAYER-11, #4325 D-next).
