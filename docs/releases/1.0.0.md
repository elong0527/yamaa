# yamaa 1.0.0

yamaa 1.0.0 is in development. These notes are written as it is built, and
become the notes of the 1.0.0 release. The
[0.9.0 notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.9.0/docs/releases/0.9.0.md)
cover the changes released before it.

## Changes

### Command line

- **`run` names its violated warnings.** The command line prints each
  violated warning of a run after its issues, as `warning: ` and the line an
  issue prints, located at the declaration, such as `warning: dm.yaml:36:7:
  the length 1 of column AGE understates its values: 2 of the rows hold a
  longer number [numeric_width_failed, SUB-29]`, where it printed only a
  count. `--format json` adds a `warnings` list of issue-shaped records of
  `warning` severity and a member's `warning_count` (CHECK-2, #4979 D409).

### Rows, lookups and relations

- **Break: in a specification without `rows`, an unfiltered `source` read
  of the base records refuses `absent`.** A row is built from at least one
  base record, so the `absent` answered nothing; it now fails as
  `prohibited_construct`, as it does in a specification that declares `rows`.
  The refusal of `absent`, `require_match` or `between` on such a read now
  says the read "always finds a value" (LOOKUP-24, #4995 D405).
- **A selection over a row's base records that chose nothing is a warning
  of the run report.** In a specification without `rows`, a `source`
  binding's `order_by` and `keep` that met no row whose records read two
  values, as when the keys are at the grain of the base's records, is
  reported as an `unchosen_selection` warning row; the run still succeeds
  and no value changes (LOOKUP-10, #4995 D405).
- **`output.filter` keeps the completed rows it holds for.** It reads the
  declared columns after the window pass, before every column verification,
  the keys and every dataset verification, so a part of a dataset keeps the whole dataset's sequence
  numbers (OUTPUT-13, #5004 D-next).
- **Parentheses around a name or a literal in an expression field keep it
  that name or literal.** `derivation: "(USUBJID)"`, `"('DM')"` or
  `"(DATE '2025-06-01')"` copies the column or returns the literal with its
  own type, where it passed `check` and failed the run as a number. A float
  literal beyond binary64 written as text is missing in a field of any type,
  and a dangling escape in a parenthesized `LIKE` pattern fails validation as
  `invalid_expression` (EXPR-5, FORMULA-7, #5076 D-next).
- **A driver read beside an aggregate of the output rows reads the record
  that built the row.** A column-level derivation that pairs an unqualified
  aggregate with a read of its intermediate driver's field is no longer
  refused as `intermediate_driver_column_read`; only a qualified aggregate
  binds the column over the whole dataset (LOOKUP-18, #5076 D-next).

### Refusals that say what to fix

- **The first slips on 0.9.0's new features say what to write instead.**
  Each refusal below keeps its condition, rule and path, and adds a `hint`
  or the context that names the remedy: a record relation whose filter or
  derivations read the current row names that read as `current`
  (LOOKUP-3); `key: PHASE` says to write `key: [PHASE]` (LOOKUP-5); a lookup
  derivation that reads a name its own map derives says to delete the entry
  or declare it earlier (LOOKUP-15); a key or range value spelled
  `ADLES.USUBJID` or `SELF.USUBJID` names the bare column (LOOKUP-5,
  LOOKUP-9); inside a pair or counted relation, a bare side field is
  qualified and another relation's field is sent to the row template
  (LOOKUP-27); a field written beside `pivot`, `inner_join` or `repeat` says
  so (LOOKUP-27, LOOKUP-28, LOOKUP-29); an aggregate entry's `unconvertible`
  beside `type` shows where the handler goes (LOOKUP-22); a date `shift` in
  `day` names `days` (TIME-14); a refused `fixed_width` or `skip`, a
  `columns` written `4`, and a positional `.txt` input each name their fix
  (CSV-18, INPUT-1); a header `encoding: UTF-8` is named as the misspelling
  (SPEC-8); a time compared with `'09:00'` names `TIME '09:00'` (FORMULA-5);
  a refused temporal literal keeps `literal_type` and `temporal_error`
  (FORMULA-3); and `STR_JOIN(S, ',')` names `separator` (FORMULA-18)
  (#4978 D-next).
- **A typed field that does not parse names its record.**
  `field_parse_failed` carries `record`, counted as the source's other
  reading findings count it, with the header as record 1, and a `date`,
  `datetime` or `time` field names its text form; a counted relation's count
  that no memory holds names its relation, record and count (INPUT-7,
  LOOKUP-29, #4978 D-next).
- **A refused relation no longer refuses its readers.** A record relation
  whose filter reads the current row, a key spelled by the output domain,
  and a pivot that lists its own `value` or a stored field are each one
  finding; the lookups and columns that read them report only their own
  faults. `check()` reports a pivot field that names the pivot's `value` as
  `duplicate_derivation`, as a run does, where it reported `unknown_field`
  at `pivot.value` (LOOKUP-3, LOOKUP-5, LOOKUP-28, #4978 D-next).
- **A Parquet time adjusted to UTC shows the adjustment.** Its
  `source_field_type_unsupported` `stored_type` is read from the footer's
  annotation, as in `time64[us, tz=UTC]`, where it read `time64[us]`, and a
  legacy `TIME_MILLIS` field reads `time32[ms, tz=UTC]` (PARQUET-7, #5021
  D-next).
- **A reproduced-only field on validated metadata is refused at that field.**
  `order`, `key_sequence`, `has_no_data`, `omitted`, a method's or comment's
  `oid`, and a value-level entry's `oid`, `name` and `where_oid` are each
  reported at their own key, such as `columns.AESEQ.submission.order`, where
  the path was the `submission` or the entry (DEFINE-30, #5021 D-next).
- **A refused frame value names its cause.** The `value_not_permitted`
  finding of a host frame's value adds `reason`, one of `encoding`,
  `fraction`, `day` and `calendar`, and its message says what to fix, as in
  `... with a fraction of a second; round the column to whole seconds`
  (SCHEMA-12, #5021 D-next).
- **A caller's path under a directory named with `\` is read on Unix.**
  A project file or `--parent` whose directory name holds a backslash was
  refused as `resource_path_not_normalized`; it now follows ordinary host
  path resolution, while a `\` written in a document is still refused
  (FILE-1, FILE-5, #5041).
- **A caller's file whose own name holds `\` is read on Unix.** An entry or
  a project file named with a backslash, such as `yamaa check 'p\q.yaml'`,
  was refused as `resource_path_not_normalized`; it is now read as the host
  names it (FILE-1, FILE-5, #5044).
- **A caller's file whose own name holds `:` is read on Unix.** An entry or
  a project file named with a colon, such as `yamaa check 'file:spec.yaml'`,
  was refused as `resource_path_uri_scheme`; it is now read as the host names
  it, while a scheme written in a document is still refused (FILE-1, FILE-5,
  #5047).

### Submissions and Define-XML

- **A project check reports what a submission refuses without data.** When
  `project.check()` finds no error in the specifications or the project
  findings, it composes each section that names `define` as `submission`
  does, stopping before the first published artifact is read, and reports
  what that composition refuses: a field the metadata's `mode` does not
  admit, an analysis result naming an unknown dataset or document, a
  repeated codelist item `order`, a fact Define-XML 2.0 cannot record, or a
  label a transport file cannot carry. A project that `check` passed no
  longer fails `submission` on its metadata alone (PROJECT-7, #4979 D406).
- **A Define-XML 2.0 refusal names the field it refuses.** A guide status,
  a second guide, a subclass, a dataset's or column's `has_no_data` and a
  non-standard dataset that a 2.0 document cannot record are reported at
  the declaring field in the project file or specification, such as
  `sdtm.standards[0].status` or `sdtm.specs[0].submission.non_standard`,
  with the declared value, such as `Draft` or `true`, as `value`, where
  they were reported at an unlocated path with a sentence as their value;
  an origin's refusal is located the same way (DEFINE-25, DEFINE-29, #4979
  D407).
- **A finding inside an analysis results or codelists file is located at
  its field.** A path that names a list item by its `name` where the item
  also declares an `id`, such as `displays['Table 14.3.01'].results.R1` or
  `codelists['Reason for Discontinuation from Study'].items[1].order`, is
  located at that field, where it was located at the file's first key
  (#4979).
- **A reproduced section writes the received `MetaDataVersion` OID.** A
  section that lists reproduced metadata may declare
  `metadata_version.oid`, written as declared in place of
  `MDV.<metadata_version.id>`, so a received OID holding a comma, such as
  `MDV.SYNTH-Acme,-Inc.ADaM-IG.1.1`, is reproduced; a section listing only
  validated metadata refuses it (DEFINE-9, DEFINE-30, #5024 D-next).
- **A reproduced codelist may number its items from 0.** In a section that
  lists reproduced metadata, a codelist item's `order` of 0 is written as
  the received `OrderNumber`; validated metadata still numbers from 1, and
  a repeated `order` stays refused in both modes, since the ODM schema
  makes `OrderNumber` unique within a codelist (DEFINE-20, owner decision
  on #5022). A negative `order` there is refused as `non-negative order`
  (#5062 D-next).
- **A declared document identity is refused at its field.** A tab or
  control character in `study_oid`, `file_oid` or
  `metadata_version.oid` is reported at that field, such as
  `sdtm.metadata_version.oid`, where it was reported at the element path
  `study` or `metadata_version` (DEFINE-24, DEFINE-25, #5059 D-next).

### Packages

- **The R and Python source packages are smaller.** The vendored Rust crates
  leave out the sources of the features that no supported build enables:
  the `windows-sys` modules of the Windows APIs that yamaa does not call, and
  zstd's legacy, dictionary-builder, seekable and CMake sources. Parquet's
  Brotli pages are decoded by `brotli-decompressor` alone, without the
  `brotli` encoder. The R source package shrinks from about 9.7 MB to 7.6 MB;
  the engine's results do not change.

### Refusals that say what to fix

- **A submission before any dataset was saved says to run it first.** An
  artifact a section lists that has not been saved is still refused as
  `producer_contract_mismatch` (INPUT-11), now with `unpublished: true` and
  the message `the artifact dm.csv of DM has not been saved: run the
  specification that writes it, then compose its submission`, where it said
  the artifact did not match its specification (#4979 D408).
- **A reproduced dataset under `context: Submission` names the context it
  needs.** A section without a transport that lists reproduced metadata is
  refused for that specification's `mode`, which requires `context: Other`
  and no transport, at its `submission`, where it asked for the `transport`
  reproduced metadata may not have (DEFINE-4, DEFINE-30, #4979 D408).

- **A save into a missing directory names the directory.** The
  `resource_path_missing` refusal of a file a save cannot reach because its
  directory does not exist adds `directory`, as in `out/report.csv cannot be
  saved: its directory out does not exist`, and a write the operating system
  refuses, such as one into a read-only directory, adds its reason as
  `cause` (FILE-11, OUTPUT-8, #4979 D408).
- **An output file written as a URI or with a backslash is refused where it
  is written.** An `output.path` or `output.report` with a URI scheme, such
  as `q:out.csv`, fails `check()`, and a run before it reads any data, as
  `resource_path_uri_scheme` at its field; one with a backslash, an empty
  segment or a trailing separator, such as `C:\out.csv`, fails there as
  `resource_path_not_normalized`, as an input path does. A run used to fail
  on each as `engine_rejected` at no field (FILE-5, FILE-11, #5049 D-next).
- **A Define-XML target written as a URI or not normalized fails `check()`.**
  A submission section's `define`, such as `q:define.xml` or
  `out\define.xml`, is refused by `check()` as `resource_path_uri_scheme` or
  `resource_path_not_normalized` at its field, as a listed function file is,
  where only composing the document refused it. Composing or saving the
  document still refuses it at that field, and its context now carries
  `source`, `entry` and `environment_path` beside `path`, as every other
  project path's refusal does (FILE-5, FILE-11, #5061 D-next).
