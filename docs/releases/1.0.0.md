# yamaa 1.0.0

yamaa 1.0.0 is in development. These notes are written as it is built, and
become the notes of the 1.0.0 release. The
[0.9.0 notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.9.0/docs/releases/0.9.0.md)
cover the changes released before it.

## Changes

### Submissions and Define-XML

- **A project check reports what a submission refuses without data.** When
  `project.check()` finds no error in the specifications or the project
  findings, it composes each section that names `define` as `submission`
  does, stopping before the first published artifact is read, and reports
  what that composition refuses: a field the metadata's `mode` does not
  admit, an analysis result naming an unknown dataset or document, a
  repeated codelist item `order`, a fact Define-XML 2.0 cannot record, or a
  label a transport file cannot carry. A project that `check` passed no
  longer fails `submission` on its metadata alone (PROJECT-7, #4979 D406).
- **A Define-XML 2.0 refusal names the field it refuses.** A guide status,
  a second guide, a subclass, a dataset's or column's `has_no_data` and a
  non-standard dataset that a 2.0 document cannot record are reported at
  the declaring field in the project file or specification, such as
  `sdtm.standards[0].status` or `sdtm.specs[0].submission.non_standard`,
  with the declared value, such as `Draft` or `true`, as `value`, where
  they were reported at an unlocated path with a sentence as their value;
  an origin's refusal is located the same way (DEFINE-25, DEFINE-29, #4979
  D407).
- **A finding inside an analysis results or codelists file is located at
  its field.** A path that names a list item by its `name` where the item
  also declares an `id`, such as `displays['Table 14.3.01'].results.R1` or
  `codelists['Reason for Discontinuation from Study'].items[1].order`, is
  located at that field, where it was located at the file's first key
  (#4979).
