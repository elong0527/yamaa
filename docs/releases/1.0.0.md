# yamaa 1.0.0

These notes are written as 1.0.0 is built (#3030) and are not yet the notes
of a release. 1.0.0 freezes the user interface after its release candidates
(#3030 D1). Each change since 0.5.0 that users can observe gets one line here,
as AGENTS.md asks; #3030 Phase 5 completes the page, states the break and
links the rename table.

## Changes since 0.5.0

### Controlled terminology

- A `text` codelist's `format_name` must begin with `$`, as Define-XML 2.1
  requires of a text codelist's `SASFormatName`: one that does not fails
  validation with `value_not_permitted` at its `format_name`, wherever the
  project's codelists are read and before any data (CT-12, #3172).

### Diagnostics

- Every refusal carries a registered issue: asking a project run for a name it
  did not build reports `unknown_specification_name`, and saving a project run
  or a submission that built nothing reports the new condition
  `nothing_to_save` (#3144).
- A cancelled call ends with an error and no result; the unregistered
  `cancelled` issue row is gone (#3144).
- A raw NUL character in a specification, project file or environment file
  fails with `invalid_yaml`; it no longer silently ends the file and drops
  what follows (#3125).

- In a specification that declares `parent`, a `dependency_cycle` names its
  closed loop in `context.cycle`, such as `[A, B, A]`, as a single-file
  specification's does, instead of every column the cycle leaves unscheduled;
  and an aggregate `derive` binding that reads a later binding reports
  `unknown_derive_variable`, as it does without `parent` (#3134).
- Define publication's engine refusals carry a `stage` and a closed `code` in
  their `context`: an output or table bound reports `define` with
  `output_limit` or `resource_limit` and its `resource`, `limit` and `actual`
  alongside the existing `detail` text, a transport value the writer cannot
  represent reports `output_projection`, and a refused Define target adds the
  `code` of its cause, such as `invalid_target` (#3145).
- A `parent` written with a backslash, an empty segment or a trailing
  separator, such as `std//base.yaml`, `base.yaml/` or
  `//server/share/base.yaml`, fails validation with
  `resource_path_not_normalized` at `parent`, naming the path as written,
  instead of `engine_rejected` (FILE-5, LAYER-2, #3201).

### Files and paths

- Windows network shares (UNC paths) and mapped drives are admitted for
  specifications, projects, inputs, outputs and `read_odm`; symbolic links,
  junctions and other reparse points stay refused (#3030 D15, #3147).
- `read_odm` refuses a source file that is a symbolic link, as every other
  input does (#3147).
- On a network share, a link is refused where the file server reports it as
  one, as Windows servers do; a parent on a share the entry is not on is
  refused when it declares relative input or output paths; and saves from two
  computers into one share folder are not serialized (#3177).
- A parent specification on another drive than the entry reads its relative
  inputs beside itself instead of failing (#3177).

- Two names that reach one file read the same bytes (FILE-9): a file
  rewritten between the captures of two of its hard links fails with
  `resource_path_content_changed`, where 0.5.0 read both versions (#3177).
- A file rewritten between the captures of two of its hard links also fails
  with `resource_path_content_changed` when the name read first was renamed
  or removed in between. A new file to which the file system gives a removed
  file's identity during a run fails the same way when its bytes differ
  (FILE-9, #3201).

### Inputs

- A CSV input linked to its producer through `schema` takes the producer's
  declared types before any data is read: a specification that applied a typed
  operation, such as `study_day`, to a non-text field of such an input was
  refused with `incompatible_input_type`, and now checks and runs (#3135).

### Lint

- `yamaa.lint(paths, fix=False)` and `yamaa_lint(paths, fix = FALSE)` check
  specification files against the style guide in Rust and return one row per
  finding, with the columns `file`, `line`, `column`, `finding`, `spec_path`
  and `message`; with `fix`, the layout fixes the lint proves safe are applied
  first (#3030 D40, #3176).
- `python -m yamaa.style` and the Python package's `style` extra are removed:
  lint with `lint()`. A suppression comment is spelled
  `# yamaa-lint: allow <finding> -- <reason>`, and `literal_form` is no longer
  reported (#3176).

### Packages

- The Python source archive builds offline: it carries the crates.io crates
  that its lock selects and only the engine and Python binding crates, without
  tests, examples or a toolchain file (#3030 D55, #3105).
- The R source package builds from the same kind of bundle, with only the
  engine and R binding crates and their trimmed lock, and neither source
  archive carries a toolchain file anywhere, its vendored crates included, so
  an offline installation never makes rustup select or download another
  toolchain (#3030 D55, #3105).
- The Python wheels' native module no longer carries its symbol table, about
  4.5 MB of its 20.6 MB on Linux, so a Rust backtrace from a wheel names no
  functions; the R package keeps its symbols, as CRAN's Repository Policy asks
  (#3106).
- The installed R package no longer carries the inputs of its tests: they
  move from `inst/` to the source package's `tests/`, which `R CMD check`
  reads and R does not install, so an installation is about 8 MB smaller
  (#3105).

### Rust facade

- An embedder's `ResolverFailure::from_code("directory" | "file" | "other" |
  "unreadable")` now raises the file-rule conditions instead of `rejected`
  (#3147).
- `Engine::read_odm` through a resolver reports a source over the 10 GiB
  per-file source bound as `ODM source exceeds 10737418240 bytes`, still with
  the code `limit`, instead of as an ODM XML size; such a source is held
  whole before `max_expanded_bytes` applies (#3201).
- `Engine::spec_check` and `Engine::project_check` return a `Check`, whose
  `issues()` is the former table, and `Check`, `Run`, `ProjectRun` and
  `Submission` report `status()`: `succeeded`, `failed`, or `skipped` for a
  project-run member whose producer did not complete (#3030 D36, #3148).
