# yamaa 1.0.0

yamaa 1.0.0 is a breaking redesign of the language rules and of the engine
that runs them. The rules are rewritten as short rule cards under ten
principles, and the language now has one way to state each thing: one
rounding, one expression grammar, one result type per expression, one lookup
model, one parent chain and one spelling per meaning. Python and R still run
the one shared Rust engine. 1.0.0 keeps no compatibility with 0.4.0, and most
0.4.0 specifications need edits before they validate. Read
[Migration](#migration) before you upgrade.

<!-- confirm: python/pyproject.toml, R/yamaa/DESCRIPTION and rust/Cargo.toml still say 0.4.0 on release/1.0.0; move all three to 1.0.0 before tagging -->

What changes for statistical programmers:

- **Some results move without an error.** A missing value now sorts lowest,
  so it comes first in an ascending order unless the order term declares
  `nulls`. CSV display rounding treats near ties as ties: 2.675 written with
  two decimals is now `2.68`. An imputation bound outside the collected month
  or year is ignored instead of giving a missing date. `impute` and
  `precision` with `type: date` read a `--DTC` value that carries a time
  instead of rejecting it. Step 21 of the [Migration](#migration) lists what
  to compare.
- **Many 0.4.0 spellings fail validation, each with a named condition:**
  `parents`, a handler written as `null`, the `date_*` and `datetime_*`
  verbs, `previous_non_missing`, `str_concat`, a verification not written in
  a list, a long form that only restates its shorthand, and a declaration
  that repeats another one, such as a `unique` check on the keys.
- **Declared metadata is enforced in the domain build.** A mandatory column
  may hold no missing value, and a bound codelist that lists its items limits
  the column's values even when the list is extensible.
- **An absent record or a missing input gives missing by default**, and
  `require_match: true` states where a missing match must stop the run.
  <!-- pending #2971 -->
- **One run report** replaces the warning log and the verification log, and
  every host returns it. <!-- pending #2912 -->
- **Submission output changes.** Each submission section chooses one
  `transport`, SAS XPORT version 5 or Dataset-JSON; text lengths come from the
  data; and ADaM dates are SAS numeric dates. Value-level metadata is keyed by
  a where clause. <!-- pending #2963 -->

## Language

The rules index opens with one sentence: a yamaa specification has exactly
one execution, and where it would have two, yamaa fails instead of choosing.
0.4.0 did not keep that promise everywhere: it had two roundings, two
int/float comparisons, three expression grammars, several tables of result
types and several spellings of one value. 1.0.0 keeps one of each. The
decisions behind these changes are recorded in #2855.

### Rules as cards, and the principles

The 0.4.0 contracts, about 12,000 lines holding 1,243 numbered requirements,
are now short rule cards (#2869, #2876). A card has an ID such as
`LOOKUP-10`, a title that states the rule, a statement of at most 90 words,
the conditions it raises and the benchmarks or tests that prove it, then
detail for implementers. Ten principles open the
[rules index](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/README.md),
each naming the cards that enforce it: everything is declared, values never
convert silently, missing is a value, ambiguity fails, order is data, values
are exact, vocabularies are closed, inheritance is deterministic, faults are
found before data, and artifacts are reproducible. The site page
[rules at a glance](https://elong0527.github.io/yamaa/reference/rules-summary/)
lists every card's title and statement.

Language rules live in `rules/*.md`. File formats and file handling moved to
`rules/reference/`, and submission metadata, controlled terminology,
Define-XML, Dataset-JSON, SAS Transport and project functions to
`rules/profiles/`. The specification style guide is no longer a rule: it is
the [style guide page](https://elong0527.github.io/yamaa/articles/style/),
and style findings carry names only. A diagnostic's `requirement` names the
card that owns the failure, such as `SCHEMA-15`, instead of a `REQ-NNNN`
number.

### Values, rounding and order

**One rounding.** Every rounding is half away from zero, and a value within
`2^-26 * 10^-digits` below a tie counts as the tie: the SAS-compatible rule
the rounding verb already used. The same rule now serves CSV display
precision (`output.decimals`), project-function result comparison and the
whole seconds of a datetime `shift`. Display precision used to round only
exact binary ties, so 2.675 written with two decimals is now `2.68` (it was
`2.67`). A float `shift` amount is rounded to whole seconds before it is
added. Rules:
[FORMULA-16](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/formulas.md#formula-16),
[CSV-9](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/reference/csv.md#csv-9)
(#2877).

**Exact int/float comparison.** Predicates and `NULLIF` compare an `int` with
a `float` by exact value, as keys, ordering, `MIN`, `MAX` and ranges already
did, so `9007199254740993 = 9007199254740992.0` is `FALSE`. Only integers
beyond 2^53 are affected. Rule:
[VALUE-19](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/values.md#value-19)
(#2877).

**Regular expressions in linear time.** A pattern is a portable ECMA-262
subset without lookahead, lookbehind, backreferences, property escapes or
flags, matched leftmost-first in time linear in the subject. A pattern
outside the subset fails validation as `invalid_regex`, or as
`invalid_expression` inside `str_contains`. Matching is never refused, so the
per-match step limit is gone; a pattern whose compiled program exceeds 10 MiB
is refused when it compiles. A capture group inside a repetition keeps the
value of the last iteration that entered it. Rules:
[TEXT-6](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/text.md#text-6),
[TEXT-12](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/text.md#text-12)
(#2877).

**Missing sorts lowest.** An order term that omits `nulls` sorts a missing
value lowest, as SAS PROC SORT does: first under `direction: asc`, which a
bare variable means, and last under `direction: desc`. 0.4.0 sorted it last
in both directions. A declared `nulls: first` or `nulls: last` places missing
values there in either direction. This applies to every order term: a
window's `order_by`, `order_by` with `keep`, `output.order_by` and the
`tie_break` of `baseline_flag`. Rule:
[VALUE-22](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/values.md#value-22)
(#2881).

### Expressions and the one grammar

One grammar now reads predicates (`filter`, `when`, `require`, `condition`),
`compute.expr` and `aggregate.expr`; string templates keep their own (#2914).
The field an expression is written in decides what it may contain. A
predicate may use arithmetic and the numeric functions inside a comparison,
such as `ALT > 3 * ULN`; `compute` takes no comparison or Boolean; and only
`aggregate` takes the reducers `SUM`, `COUNT`, `MIN`, `MAX`, `MEAN` and
`ONLY`. Keywords and function names are case-insensitive, identifiers
case-sensitive. `CASE`, `WHEN`, `THEN`, `ELSE`, `END` and `OVER` are ordinary
names everywhere, and `DATE`, `DATETIME` and `ESCAPE` are ordinary names in
predicates. Every text that was valid keeps its meaning and result.

A syntax error is `invalid_expression` in every field, replacing
`invalid_predicate`, `invalid_numeric_expression` and
`invalid_aggregate_expression`, and an integer literal out of range fails at
validation. A date in arithmetic, such as `ASTDT <= TRTEDT + 30`, now parses
and fails as `incompatible_input_type`: dates move with `shift` and differ
with `diff`. Rules:
[FORMULA-1](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/formulas.md#formula-1),
[FORMULA-27](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/formulas.md#formula-27).

Fewer verbs and functions do the same work (#2857, #2878):

- `locf` with `include_current: false` replaces `previous_non_missing`
  ([WINDOW-8](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/windows.md#window-8)).
- `str_template` replaces `str_concat`: a template such as
  `"{DM_RAW.STUDYID}-{DM_RAW.SITEID}-{DM_RAW.SUBJID}"` states the join
  ([TEXT-4](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/text.md#text-4)).
- The `compute` functions `GREATEST`, `LEAST`, `COALESCE` and
  `ROUND_HALF_AWAY_FROM_ZERO` are removed; the `greatest`, `least`,
  `first_available` and `round_half_away_from_zero` expressions stay
  ([FORMULA-13](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/formulas.md#formula-13)).
  `aggregate` shares the function list, so `COALESCE(SUM(x), 0)` is refused
  too.
- The `str_contains` verb is removed: its Boolean result fit no column type.
  The `str_contains(source, pattern)` predicate function stays
  ([FORMULA-8](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/formulas.md#formula-8)).
- `duration_text` is removed; `duration_value` stays.

### One result type per expression

Every expression has one result type, decided before any data is read: fixed
by the expression (`str_pad` gives `str`, `row_number` gives `int`), set by a
declared parameter (`impute` and `shift` give their `type`), or taken from
what it reads (`source`, `case`, `compute`). Key matching, intermediate
fields, derive bindings, range bounds, operand checks and column conversion
all read that one type
([EXPR-14](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/expressions.md#expr-14)).
`compute: "A + B"` over two `int` columns is now `int`, where it was always
`float`; `/` and functions such as `SQRT` still give `float`.
`duration_value` gives `float` in every unit.

A derivation whose result can never convert to its column's type, such as a
Boolean literal in an `int` column, fails validation as `conversion_failed`
before any data is read, in `domain` and in `check`, unless it declares
`unconvertible`
([VALUE-24](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/values.md#value-24)).
`check` now also reports a date used in arithmetic (#2952).

### Missing values and `require_match`

<!-- pending #2971 -->

A missing input or an absent record gives missing by default, and that
default is counted and reported like a declared handler. A specification
states where a match must exist (#2971).

- A missing source to a single-input verb, `mapping`, `cut`, `str_extract`,
  `str_replace` or `str_case`, gives missing, counted at the verb's `missing`
  path; 0.4.0 failed with `missing_input`. A declared literal still
  substitutes.
- `str_template` still fails on a missing part unless `missing` is declared,
  so text assembled from parts never drops a collected value silently.
- A named intermediate without `no_match` gives missing for a row with no
  record or a missing key, counted at the reading column's `no_match`; 0.4.0
  failed with `unmatched_key`. An implicit join with no record still gives
  missing, now counted, or its binding's `absent` value when one is declared.
- `require_match: true` makes a miss or a missing key fail as
  `unmatched_key`. It can be declared on a named intermediate, on a structured
  `source:` binding, or on an `input`, where it covers every implicit-join read
  of that input. Beside `no_match`, or beside `absent` on the same binding, it
  fails as `conflicting_absence_policy`.
- An intermediate that declares only `id` and `dataset` reads exactly what an
  implicit join reads and is refused as rename-only, unless it declares
  `require_match: true`.
- Invalid text, unmapped values, unresolved multiple matches, failed
  conversion and a regex that matches nowhere on present text stay fatal
  unless their own handler is declared.

`impute` and `precision` already give missing for a missing source, counted,
and their `missing` handlers are removed; `impute` takes a `fallback` instead
(#2893). Rule:
[COLUMN-10](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/columns.md#column-10).

### One lookup model

<!-- pending #2981 -->

An implicit join (`DATASET.VARIABLE`), a named intermediate and a qualified
aggregate are one lookup that runs the same four steps for each row: match
the keys and any `between` range, narrow the matched records with `filter`,
select one with `order_by` and `keep` (an aggregate reduces them instead),
and answer absence (#2981).

- The filter runs after the match for every kind. A filter that would fail on
  a record that no row matches no longer stops the run. Results are
  unchanged.
- Key types are checked for every kind: a record value that cannot compare
  with its match value fails as `incompatible_input_type`. In 0.4.0 an
  implicit join or an aggregate silently matched nothing.
- `between` also works on an implicit join written as a structured `source:`
  binding or a filtered source operand. The range value must be a value of
  the current row.
- An aggregate whose `key` is empty fails as `invalid_field_type`, and one
  with no applicable key as `no_applicable_keys`; `missing_aggregate_keys` is
  gone.

Rules:
[LOOKUP-1](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/lookup.md#lookup-1),
[LOOKUP-9](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/lookup.md#lookup-9),
[LOOKUP-10](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/lookup.md#lookup-10).

### Temporal verbs and imputation flags

`diff`, `shift`, `impute` and `precision` replace the eight `date_*` and
`datetime_*` verbs. Each declares `type: date` or `type: datetime`, which is
never inferred from the data. A field the type needs and lacks fails as
`missing_required_field`, and one it does not take as `unknown_field`: for
example, `shift` takes `days` for a date and `amount` with `unit` for a
datetime. Rule:
[TIME-1](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/temporal.md#time-1)
(#2893).

- **One precision ladder.** Collected precision is `none`, `year`, `month`,
  `day`, `hour`, `minute` or `second` for both types, and a date is at most
  `day`. `precision` returns these words instead of the 0.4.0 letters
  ([VALUE-16](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/values.md#value-16),
  [TIME-7](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/temporal.md#time-7)).
- **`impute` reads SDTM `--DTC` text.** Any right-truncated ISO 8601 value
  from `YYYY` to `YYYY-MM-DDThh:mm:ss` is accepted for both types. With
  `type: date`, text carrying a complete date gives that date whatever time
  follows; 0.4.0 rejected a `--DTC` value with a time as invalid.
  `minimum_source_precision` takes `year`, the default, `month` or `day`.
  `month` is declared exactly when it is `year`, `day` exactly when it is
  `year` or `month`, and `time` exactly for a datetime
  ([TIME-8](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/temporal.md#time-8),
  [TIME-10](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/temporal.md#time-10)).
- **Bounds.** `not_before` and `not_after` apply to both types and move only
  the fields imputation supplied. A bound outside the interval the collected
  fields admit is ignored, where 0.4.0 gave a missing result. Crossed bounds
  give `min(max(completed, not_before), not_after)` and are counted, and
  bounds never make a result missing
  ([TIME-9](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/temporal.md#time-9)).
- **Missing and invalid sources.** A missing source gives missing, counted,
  unless `impute` declares `fallback`, a column of the declared type whose
  value is returned with precision `none`. Text that is not collected date
  text fails as `invalid_date_text` for both types, which replaces
  `invalid_datetime_text`, unless `invalid` answers it
  ([TIME-13](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/temporal.md#time-13)).
- **`imputation_flag`** returns the ADaM `*DTF` and `*TMF` values from the
  imputed value's precision. With `part: date`, `none` gives `Y`, `year`
  gives `M` and `month` gives `D`. With `part: time`, `none` to `day` give
  `H`, `hour` gives `M` and `minute` gives `S`, which is missing with
  `seconds_collected: false`. A part that was collected gives missing, and a
  bound that moves an imputed day keeps `D`
  ([TIME-18](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/temporal.md#time-18)).
- **`to_date`** returns the date of any text carrying a complete date. Year or
  year-month text gives missing, counted as `partial`, instead of failing
  ([TIME-2](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/temporal.md#time-2)).

Two benchmark values moved because a bound fell outside the collected month:
`adam-adae-partial-dates` now completes the start `2025-02` to `2025-02-15`,
and `adam-adcm-end-date-bound` completes the end `2024-05` to `2024-05-31`.

<!-- pending #2978 -->

Three more temporal changes (#2978):

- `dtc` writes `--DTC` text from separate `year` to `second` parts, given as
  `str` digits or as `int`, and stops before the first missing part, so it
  replaces a `case` ladder of templates. A day collected without its month
  keeps the year alone, where such a ladder failed.
- `time_of_day` returns a datetime's whole seconds since midnight as an `int`,
  for ADaM `*TM` columns displayed with `TIME8.`.
- `precision`, `impute` and `to_date` read SDTM text with an unknown middle
  field by its prefix: `2025---15` reads as `2025`, and `2025-03-15T-:30` as
  `2025-03-15`. Such text used to be invalid. ISO 8601 intervals and
  durations fail with their own condition, `interval_or_duration_text`.

### Windows: `locf` and `baseline_flag`

`locf` takes `include_current`, default `true`; with `false` it returns the
closest strictly earlier non-missing value, which is what
`previous_non_missing` did
([WINDOW-8](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/windows.md#window-8),
#2878).

`baseline_flag` follows the ADaM baseline, the last non-missing value on or
before the reference date (#2881):

- `value` is required, and a row is eligible only when its analysis value is
  present.
- `inclusive`, default `true`, admits a date equal to `reference_date`;
  `false` means strictly before.
- `tie_break` order terms rank the eligible rows that share the latest date.
  Rows still tied fail with `ambiguous_baseline`, as before.
- `date` and `reference_date` may both be `datetime` columns.

Rule:
[WINDOW-9](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/windows.md#window-9).
One benchmark value moved: in `schema-window-functions`, subject 02's
baseline moved to visit 1, because its latest visit before treatment has no
result.

### Inheritance

Layers form one chain and merge by one rule (#2896):

- **One parent chain.** `parent: <path>` replaces `parents`. Each layer names
  at most one parent, the layers form one chain contributed from the root
  ancestor to the entry, and reaching a layer twice fails as
  `inheritance_cycle`. A null `parent` makes the layer standalone
  ([LAYER-2](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/inheritance.md#layer-2),
  [LAYER-3](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/inheritance.md#layer-3)).
- **One merge rule.** Every keyed member (`input`, `intermediates`,
  `columns`, `rows`, `windows`) merges the same way: a class field by field, a
  mapping key by key, a registry value only when both name the same keyword,
  and scalars and lists by replacement. Two 0.4.0 exceptions are gone: a named
  window merges field by field instead of being replaced whole, and a lookup
  `key` written as a mapping merges key by key
  ([LAYER-6](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/inheritance.md#layer-6),
  [LAYER-8](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/inheritance.md#layer-8)).
- **Null means absent.** YAML null makes a field absent in every
  specification and at every depth; over an inherited value it removes it, so
  a layer can drop one dictionary entry and keep the rest. Null never means
  the missing value. A handler, a `flag` value, a `mapping` dictionary entry
  and a function argument substitute missing as `{literal: null}`
  ([LAYER-9](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/inheritance.md#layer-9),
  [COLUMN-10](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/columns.md#column-10)).

### One spelling

Every value has one spelling (#2939):

- **A list stays a list.** A field that takes one or more values takes a
  list, even for one value: column and dataset `verifications`, a lookup or
  aggregate `key` written as columns, and the ODM `event`, `form` and
  `item_group`
  ([SCHEMA-10](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/reference/schema-language.md#schema-10)).
- **No restated long forms.** A mapping that holds only the field its
  shorthand fills fails as `redundant_long_form`, and the finding names the
  shorthand to write: `aggregate: {expr: E}`, `flag: {condition: P}`,
  `str_template: {template: T}`, `unique: {columns: [A, B]}`, an input
  written `D: {path: p}`, and `{source: X}` where a bare name means the same.
  A long form that adds anything, such as `group_by`, an `id` or a `filter`,
  stays
  ([SCHEMA-15](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/reference/schema-language.md#schema-15)).
- **No hidden calls.** A bare derivation string is only a source reference.
  `to_date(DM.BRTHDTC)` used to run as a `to_date` call; it now fails as
  `pattern_mismatch`
  ([EXPR-5](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/expressions.md#expr-5)).

### Verification and the run report

A declaration that restates a fact the specification already states fails
as `redundant_declaration`, and the finding names the declaration that
already states it (#2884):

- a `not_missing` check on a key column, or on a column that is mandatory on
  every row
  ([CHECK-5](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/verification.md#check-5));
- a `unique` check whose columns are the keys
  ([CHECK-10](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/verification.md#check-10));
- an `allowed_values` check beside a column codelist that lists its items

`codelist_values_conflict` and `mandatory_not_enforced` are retired.

<!-- pending #2912 -->

One run report replaces the warning log and the verification log (#2912).
Every run of an admitted specification builds it, whether the run succeeds or
fails, and every host returns it. `output.report` writes it to a CSV or
Parquet file chosen by the extension and must differ from `output.path`. A
specification that declares a `warning` verification must declare
`output.report`, or it fails as `missing_report`, which replaces
`missing_warning_log`. A failed run writes only its report, which is
diagnostic output and never an accepted artifact.

The report has a row for the run; one per input dataset, with its declared
path, profile, file bytes, records read and, for a schema-linked input, its
producing specification; one per row template; one per handler path, zero
counts and default substitutions included; one per output column of a
successful run, with its missing count and longest value; and one per
evaluated check, with every offending key. Its fourteen columns are
`ARTIFACT`, `KIND`, `SPEC_PATH`, `NAME`, `ID`, `TARGET`, `RULE`, `SEVERITY`,
`OUTCOME`, `CONDITION`, `COUNT`, `TOTAL`, `KEYS` and `DETAILS`. It carries no
version and no timestamp, so the same specification and inputs give the same
bytes.

### Inputs and producers

### Submission

#### Mandatory columns

The domain build resolves each column's `mandatory` without a study document
(#2884). A key column is mandatory, and `mandatory: false` on one fails.
Otherwise a declared `mandatory` wins, and an `adam` dataset must declare
one. Otherwise a column is mandatory exactly when its dataset's `class` is a
tabulation class and its `core` is `Req`. A mandatory column that is not a key
is checked for missing values in every build and fails as `not_missing` does;
a value-level `mandatory` applies to its own rows. 0.4.0 required a
`not_missing` check beside `mandatory: true`, and 1.0.0 refuses it as
redundant. A document refuses a dataset whose `class` belongs to the other
family group. Rules:
[SUB-10](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/submission.md#sub-10),
[SUB-11](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/submission.md#sub-11).

#### Codelists

A bound codelist that lists its items restricts the column's present values
whether or not it is `extensible`; 0.4.0 checked only lists that were not
extensible (#2884). Declare a sponsor addition to an extensible published list
as an item with `extended: true`. An extended item has no NCI code, so it
declares no `alias` (`codelist_extended_alias`), and `context: Submission` no
longer asks it for one (#2975). External dictionaries such as MedDRA and
WHODrug are still not enforced, and a value-level binding decides its own
rows. Rules:
[CT-6](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/terminology.md#ct-6),
[CT-7](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/terminology.md#ct-7).

#### Origins

A derivation now refutes only the origins it disproves (#2906, #2975):

| Derivation | Refuted `origin.type` |
| --- | --- |
| A bare read: `source`, `odm`, an `aggregate` that is exactly `ONLY` of one variable, or a plain lookup through a named intermediate over an input with no `derivations` | none |
| A bare `literal` | `Derived`, `Predecessor` |
| A recode of collected values: `mapping`, `case`, `first_available`, `str_case`, `str_pad`, `str_replace`, `str_extract`, `str_template` or `to_date` | `Protocol`, `Predecessor` |
| Anything else | `Collected`, `Protocol`, `Predecessor` |

So controlled-terminology recoding, case normalization and ISO 8601 assembly
of collected parts can stay `Collected`, a value pre-printed on the CRF and
written as a literal can be `Collected`, and a value computed upstream and
read as stored can be `Derived`.

- `sdtm` admits `Not Available` with a description, and `send` takes no
  source or any source the `sdtm` table admits for the type.
- A `Predecessor` description is `<dataset>.<column>`, optionally followed by
  ` where ` and a condition for reviewers, such as
  `SUPPDM.QVAL where QNAM = 'RACEOTH'`. Labels must be equal only when the
  column and its predecessor share a name (`predecessor_label_mismatch`), and
  the check spans every submission section.
- Under `context: Submission`, a `Collected` origin from `Investigator` or
  `Subject` declares `documents` with a `pages` reference into the annotated
  CRF, or fails with `origin_document_missing`.
- Inventory-vocabulary values such as `SRCDOM` resolve against the datasets
  of every submission section.

Rules:
[SUB-15](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/submission.md#sub-15)
to
[SUB-17](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/submission.md#sub-17),
[SUB-19](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/submission.md#sub-19),
[SUB-20](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/submission.md#sub-20),
[CT-11](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/terminology.md#ct-11).

#### Value-level metadata by a where clause

<!-- pending #2963 -->

A column's `submission.value_level` entries replace `rows[].submission`
(#2963). A literal `--TESTCD` per row template could not describe ADaM BDS
metadata by `PARAMCD`, SUPPQUAL by `QNAM`, trial summary by `TSPARMCD`, or a
test repeated across specimens. Each entry has an `id`, unique within the
column and used in the generated OIDs, a `where` clause and the metadata that
overrides the column's on the rows it selects. `where` maps declared `str`
output columns, other than the column itself, to lists of values; one value is
written as `EQ` and several as `IN`, and several columns must all match.

- Two entries that can select the same row fail validation as
  `value_level_overlap`; a row two entries select fails the build as
  `value_level_multiple_matches`; an entry that selects no row is a
  `value_level_unmatched` warning.
- Value-level `mandatory`, codelists, the dataset inventory and transport
  lengths apply to the rows each entry selects.
- Define-XML carries one `def:ValueListDef` per column and one
  `def:WhereClauseDef` per entry, with a `RangeCheck` for each where column.
  Per-value definitions, methods and comments end their OIDs with the entry
  `id`.
- The five test-code conditions, such as `value_metadata_requires_testcd`,
  are retired.

#### One transport per section, and SAS XPORT version 5

A submission section writes Define-XML and, optionally, one transport file
per dataset (#2913, merged in #2975):

- `transport: xpt` or `transport: dataset_json` on the section replaces
  `dataset_json: true`; without it, only the Define-XML document is written.
- Each composed dataset gets `<lowercase dataset name>.xpt` or `.json` in the
  directory of `define.xml`, and its `def:leaf` names that file. 0.4.0 wrote a
  Dataset-JSON file beside each artifact under the artifact's own base name.
  With a transport, the `define` target must be named exactly `define.xml`,
  and every transport file has one writer (`transport_path_collision`).
- A dataset declared `has_no_data` gets no transport file; 0.4.0 refused
  Dataset-JSON for such a section. A dataset with no rows that does not
  declare `has_no_data` fails as `transport_dataset_empty`.
- With a transport, a text column's length is its longest published value in
  bytes, at least 1, across the section's datasets that carry that column; a
  SUPP-- dataset is measured on its own. The Define-XML `Length` and the
  Dataset-JSON `length` carry it, and the declared `length` stays the bound
  every value must meet. In `sdtm-dm-metadata`, `STUDYID` went from the
  declared 20 to 4, the length of `CATH`.
- Under `adam`, a `date` column is submitted as SAS days since 1960-01-01 with
  `DATE9.`, and a `datetime` column as seconds with `DATETIME20.`. Define-XML
  describes them as `DataType="integer"` with `Length` 8, with or without a
  transport, and Dataset-JSON keeps the ISO text with `targetDataType`
  `integer`. Under `sdtm` and `send`, dates stay ISO 8601 text.
- A SAS Transport file is the fixed TS-140 layout of 80-byte records, with
  numbers converted exactly to IBM floating point and the same bytes for the
  same inputs and creation time. Values it cannot carry are refused, never
  truncated: names outside `^[A-Z][A-Z0-9_]{0,7}$` (no underscore in a dataset
  name), labels over 40 characters or outside printable ASCII, text over 200
  bytes, non-ASCII text, trailing blanks, present empty strings, integers
  beyond 2^53 in magnitude, numbers outside the IBM range, ADaM dates before
  1582, a `display_format` that is not a SAS format, a last row of blanks
  only, and files over 5,000,000,000 bytes.
- Under `context: Submission`, every dataset and column name must fit those
  name patterns and every label 40 printable ASCII characters, and with
  either transport every published text value must be printable ASCII of at
  most 200 bytes.
- A composed specification declares no `output.decimals` when its section
  requests a transport (`decimals_not_applicable`), so display rounding never
  becomes the submitted value.

The retired `define.yaml` study document is removed; the environment's
`sdtm`, `adam` and `send` sections are the only Define-XML route (#2857).
Rules:
[JSON-1](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/dataset-json.md#json-1),
[JSON-3](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/dataset-json.md#json-3),
[JSON-5](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/dataset-json.md#json-5),

#### ISO 8601 data types

<!-- pending #2978 -->

Declared ISO 8601 types are checked against the data (#2978):

- A `str` column whose submission `data_type` is a date or time type
  (`date`, `datetime`, `time`, the `partial` and `incomplete` types,
  `durationDatetime` or `intervalDatetime`) has each present value checked
  against that type's ISO 8601 form, failing as `data_type_failed`.
  `datetime` means complete to the second, so text collected to the minute is
  `partialDatetime`.
- An `sdtm` or `send` dataset carries no `datetime` output column, which
  would write seconds that were never collected; its dates and times are `str`
  columns. Such a column fails validation as `value_not_permitted`.

## Migration

### From 0.4.0

Work through the steps in order. Most steps name the condition that reports
the old form, and `check` reports those findings without reading study data,
so run it after each step. The examples come from the benchmarks of this
release, with the 0.4.0 form taken from the same benchmark before the change.

#### 1. Install 1.0.0 and regenerate project locks

Install the 1.0.0 packages wherever you build studies. A declared project
`lock` that pins 0.4.0 fails as `runtime_artifact_mismatch` on every build
that calls a project function: regenerate it for 1.0.0
([FUNC-3](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0/rules/profiles/functions.md#func-3)).

#### 2. Chain inherited layers with `parent`

`parents` fails as `unknown_field`. Rewrite a list of parents as a chain with
the same contribution order: the entry names its last parent, which names the
one before it, up to the root. From `schema-inheritance`, 0.4.0:

```yaml
# spec_study.yaml
parents: [spec_organization.yaml, spec_compound.yaml]

# spec_compound.yaml
parents: spec_organization.yaml
```

1.0.0:

```yaml
# spec_study.yaml
parent: spec_compound.yaml

# spec_compound.yaml
parent: spec_organization.yaml
```

#### 3. Write the missing value as `{literal: null}`

A YAML null now declares nothing, so a handler written as `null` leaves its
condition unanswered. Respell every substituted missing value as
`{literal: null}`: the handlers `absent`, `missing`, `unmapped`, `no_match`,
`invalid` and `unconvertible`, a `flag`'s `true_value`, `false_value` and
`missing`, the `missing` of `first_available`, an inline `mapping` dictionary
entry and a function argument. Left as null, a dictionary entry is removed, a
function argument is omitted and a `true_value` takes its default `Y`. The
derivation `{literal: null}` is unchanged. From `adam-adae-severity-rank`,
0.4.0:

```yaml
mapping:
  source: ASEV
  missing: null
```

1.0.0:

```yaml
mapping:
  source: ASEV
  missing: {literal: null}
```

#### 4. Rename the temporal verbs and declare their `type`

| 0.4.0 | 1.0.0 |
| --- | --- |
| `date_diff`, `datetime_diff` | `diff` with `type: date` or `type: datetime` |
| `date_shift`, `datetime_shift` | `shift` with `type: date` or `type: datetime` |
| `date_impute` | `impute` with `type: date` |
| `datetime_impute` | `impute` with `type: datetime` and `minimum_source_precision: day` |
| `date_precision`, `datetime_precision` | `precision` with `type: date` or `type: datetime` |

A 0.4.0 verb name fails as `unknown_operation`. Remove the `missing` handler
from `impute` and `precision`: a missing source gives missing, and `fallback`
names a column to use instead. Add `minimum_source_precision: day` to every
former `datetime_impute`, which completed only text carrying a whole date;
without it, the default `year` asks for `month` and `day` rules and
validation fails as `month_required` and `day_required`. From
`adam-adae-partial-times`, 0.4.0:

```yaml
datetime_impute:
  source: AESTDTC
  time: first
  missing: null   # handlers are explicit: an omitted one is fatal
  invalid: null
```

1.0.0:

```yaml
impute:
  type: datetime
  source: AESTDTC
  minimum_source_precision: day
  time: first
  invalid: {literal: null}
```

The flow form changes the same way, from `adam-adae-post-dose-window`:

```yaml
WINEND: {datetime_shift: {source: EXSTDTC, amount: 24, unit: hour}}
```

```yaml
WINEND:
  shift: {type: datetime, source: EXSTDTC, amount: 24, unit: hour}
```

`precision` returns words, so a condition that compared letters compares
words. `M` meant month for a date and minute for a datetime.

| Type | 0.4.0 | 1.0.0 |
| --- | --- | --- |
| `date` | `Y`, `M`, `D` | `year`, `month`, `day` |
| `datetime` | `D`, `H`, `M`, `S` | `day`, `hour`, `minute`, `second` |

From `adam-adae-post-dose-window`, 0.4.0:

```yaml
- when: "ASTTPR IN ('M', 'S')"
```

1.0.0:

```yaml
- when: "ASTTPR IN ('minute', 'second')"
```

```yaml
case:
  - when: "ASTDTPR = 'D'"
    then: {literal: H}
  - when: "ASTDTPR = 'H'"
    then: {literal: M}
  - when: "ASTDTPR = 'M'"
    then: {literal: S}
```

1.0.0:

```yaml
imputation_flag:
  source: ASTDTM
  part: time
```

#### 16. Replace the logs with `output.report`

<!-- pending #2912 -->

`output.warning_log` and `output.verification_log` are unknown fields. Name

declares a `warning`. From `schema-verification-log`, 0.4.0:

```yaml

  path: adsl.csv
  columns: [USUBJID, AGE]
```

```yaml
  path: adsl.csv
  columns: [USUBJID, AGE]
```

#### 18. Add `require_match` where a missing match must fail

<!-- pending #2971 -->

A named intermediate without `no_match` now gives missing when no record
matches. Where an absent record must stop the run, as it did in 0.4.0, add
`require_match: true`. From `adam-adpp-accumulation-ratio`, 0.4.0:

```yaml
# The subject's planned arm. No `no_match`: a PP subject missing from ADSL
# stops the run instead of losing its ratios.
intermediates:
  - id: SUBJARM
    dataset: ADSL
    key: [STUDYID, USUBJID]
    columns: [ARMCD]
```

1.0.0:

```yaml
# The subject's planned arm. A match is required: a PP subject missing from
# ADSL stops the run instead of losing its ratios.
intermediates:
  - id: SUBJARM
    dataset: ADSL
    key: [STUDYID, USUBJID]
    columns: [ARMCD]
    require_match: true
```

An intermediate that declares only `id` and `dataset` needs it too, or it is
refused as rename-only. To require a match on every implicit-join read of an
input, declare it on the input:

```yaml
input:
  ADSL: {path: adsl.csv, require_match: true}
```

A `mapping`, `cut`, `str_extract`, `str_replace` or `str_case` with a missing
source now gives missing instead of failing. Where a missing value must stop
the run, state it with a `not_missing` check or `mandatory: true` on the
column that must be present.

#### 20. Give lookup keys comparable types

<!-- pending #2981 -->

An implicit join or an aggregate whose key values cannot compare with the
current row's, such as text against an integer, now fails as
`incompatible_input_type` instead of matching nothing. Declare the input
field's type in `types` so that both sides compare. An aggregate with an
empty `key` fails as `invalid_field_type`.

#### 21. Compare results that can move without an error

Rebuild each study and compare its outputs with the 0.4.0 outputs. These
changes can move values or metadata while the run still succeeds:

- **Order.** Missing values sort first in an ascending term without `nulls`
  (step 10).
- **CSV display precision.** A value within the near-tie window rounds away
  from zero: 2.675 at two decimals is `2.68`, not `2.67`. Parquet output is
  not rounded.
- **Imputation bounds.** A bound outside the collected interval is ignored,
  so a partial date that 0.4.0 left missing is now completed.
- **Date text with a time.** With `type: date`, `impute` reads
  `2025-03-04T08:30` as `2025-03-04` and `precision` reads it as `day`, where
  0.4.0 treated the text as invalid and an `invalid` handler supplied its
  literal.
- **Defaults for missing inputs and absent records.** They give missing where
  0.4.0 failed. <!-- pending #2971 -->
- **SDTM text with an unknown middle field.** `2025---15` reads as the year
  `2025`, where an `invalid` handler used to supply its literal.
  <!-- pending #2978 -->
- **Define-XML.** Text lengths come from the data when a transport is
  requested, and ADaM dates are `integer` with `DATE9.` or `DATETIME20.`.

#### 22. Update code that reads diagnostics

The `issues` table and `diagnostics` records keep their shape. Code that
matches conditions or requirements needs these changes:

| 0.4.0 condition | 1.0.0 |
| --- | --- |
| `invalid_predicate`, `invalid_numeric_expression`, `invalid_aggregate_expression` | `invalid_expression` |
| `invalid_datetime_text` | `invalid_date_text` |
| `dataset_json_path_collision` | `transport_path_collision` |
| `dataset_json_without_data` | gone: a `has_no_data` dataset gets no transport file |
| `codelist_values_conflict`, `mandatory_not_enforced` | gone: `redundant_declaration` refuses the restatement |
| `producer_output_path_mismatch`, `producer_workflow_cycle` | gone: producers are never run |
| `unsupported_regex_engine`, `unsupported_text_contract` | gone |
| `missing_warning_log` | `missing_report` <!-- pending #2912 --> |
| `value_metadata_requires_testcd` and the other test-code conditions | `value_level_where_invalid`, `value_level_overlap` and the other value-level conditions <!-- pending #2963 --> |
| `missing_aggregate_keys` | `invalid_field_type` or `no_applicable_keys` <!-- pending #2981 --> |

New conditions include `redundant_declaration`, `redundant_long_form`,
`day_required`, `day_not_permitted`, `predecessor_label_mismatch`,
`codelist_extended_alias`, the `transport_*` and `xpt_*` conditions, and,
with the open changes, `conflicting_absence_policy`, `data_type_failed` and
`interval_or_duration_text`. `conversion_failed` can now be raised at
validation, `decimals_not_applicable` also refuses display decimals beside a
transport, and `missing_input` is raised only by a template once #2971 lands.
A `requirement` holds a rule card ID, such as `LOOKUP-10`, not a `REQ-NNNN`
number.
