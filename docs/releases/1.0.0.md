# yamaa 1.0.0

yamaa 1.0.0 is in development. These notes are written as it is built, and
become the notes of the 1.0.0 release. The
[0.8.0 notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.8.0/docs/releases/0.8.0.md)
cover the changes released before it, including the Parquet saved-output
change and concurrent execution.

## Changes

### Command line

- **The packages run the command line as themselves.** `yamaa.cli(arguments)`
  and `python -m yamaa` in Python, and `yamaa_cli(arguments)` in R, run one
  command of the `yamaa` command line over the package's own engine: a run of
  a specification that calls a project function verifies the project's lock
  and calls the functions installed in that interpreter, where the standalone
  binary refuses it as `unsupported_operation`. Each prints what the binary
  prints on the package's standard streams and returns the binary's exit
  status, and `--version` and `selftest` name the host and its version, which
  the text form prints on a `host version:` line. The commands moved from the
  binary into the facade's `cli` module, over a `Runtime` each client
  configures (D-next on #4064).
- **The standalone binary runs project functions through an interpreter's
  worker.** `yamaa run` of a project that calls project functions starts
  `python -m yamaa._worker` or the R package's worker in `Rscript`, in the
  interpreter `--interpreter` names or the one found on `PATH`, and runs the
  functions there as the package's own `run()` runs them, verifying the
  lock first. `--host python|r` names the language; without it, the one
  language the project names an `environments` entry for, or else the one
  its function files implement, runs them, and a project that names both
  runs none, as before. The run's JSON document gains `host`. The worker's
  package must carry the binary's engine version, which a declared lock's
  verification checks as `runtime_artifact_mismatch` of `yamaa`. The
  command-line conformance runs still start no worker (D-next on #4064).

### Specification language

- **Numeric text may have digits on one side of its decimal point only.**
  `.5`, `5.` and `-.5` now parse as numbers when text converts to `int` or
  `float` and when a typed input reads a field, as SAS reads them; before,
  they failed to parse, so `unconvertible` replaced them alongside text such
  as `abc`. Formula literals are unchanged (VALUE-6, INPUT-7, #4461 D-next).
- **A date can become a datetime at a named time of day.** `impute` with
  `type: datetime` now also takes a `date` source and supplies its time of day
  from `time: first` (`00:00:00`) or `time: last` (`23:59:59`). The result
  keeps the date's collected precision, so the time imputation flag reads `H`.
  A date still never converts to a datetime implicitly (TIME-8, VALUE-18,
  #4270 D-next).
- **A row failing before its template's filter says so.** When one of a row
  template's own derivations fails on a candidate row whose keys are all
  derived, before the template's `filter` runs, the finding's context names
  that filter as `template_filter`, and a `missing_input` finding explains
  that the filter runs only after the row's derivations (COLUMN-9, #4272
  D-next).
- **A one-record table is read without a join key.** A named intermediate may
  write `key: none`, so every row reads every record of its dataset: one record
  is read by every row, none gives the absence answer, and several fail as
  `multiple_matches` unless `keep` chooses one. A study-level settings table
  no longer needs a constant column derived on both sides to join on. An
  intermediate `key` written as a bare string other than `none`, such as
  `key: USUBJID`, now fails as `value_not_permitted` rather than
  `invalid_field_type` (LOOKUP-5, #4271 D-next).
- **Several supplemental qualifiers are read through one lookup.** A named
  intermediate may write `pivot: {name, value, fields}`: each listed name
  becomes a field of its selection, holding the `value` of the one candidate
  whose `name` equals it, selected per name by `order_by` and `keep` or
  `nearest`, missing or the `absent` value when there is none, and failing as
  `multiple_matches` when there are several. A candidate whose name is not
  listed fails the read as `unlisted_pivot_name`, so a qualifier the
  specification forgot stops the run instead of leaving a column empty. The
  qualifiers of a SUPP-- dataset no longer need one lookup per `QNAM`
  (LOOKUP-28, #4310 D-next).
- **A refused read of a driver's derived field names its remedy.** A
  column-level derivation that reads a field a row-driving intermediate
  derives is still refused as `unsupported_operation`, and its context now
  carries a `hint`: derive the field into a column in each row template the
  intermediate drives, then read that column (ROW-2, #4269 D-next).
- **Three refusals say what to fix.** A static comparison that fails because one
  operand is a field of a delimited input that `types` leaves undeclared, and
  so reads as `str`, carries a `hint` naming the field and saying that its
  input's `types` declare no type for it, and its message names both
  operands' types instead of only the right one's (FORMULA-5, INPUT-5). A result wrapper's `value` and
  `unconvertible` written where only an expression fits, such as a case's
  `otherwise`, carries a `hint` that says where the wrapper goes (SCHEMA-7,
  COLUMN-13, LOOKUP-15). A limit refusal's message names the resource, its
  limit and, when known, the size found, which its context already held
  (LIMIT-1, #4458, #4459, #4460 D309).
- **A time of day is a column type.** A column, an input field and a project
  function parameter or result may declare `time`, a time of day to the whole
  second with no date and no zone. Text `hh:mm` or `hh:mm:ss` parses into it,
  it writes as `hh:mm:ss`, and it compares only with another `time`. `to_time`
  takes a datetime's time of day, and `TIME '08:30'` writes one in an
  expression. CSV and Dataset-JSON carry its text, Parquet a zone-free
  microsecond `Time` (and reads milliseconds and nanoseconds), a SAS
  transport file seconds since midnight under `ADaM` with `TIME8.`, Python a
  `datetime.time` and R an `hms`. A Dataset-JSON `time` column now reads as
  `time` rather than `str`; declare it `str` to keep its text. An `SDTM` or
  `SEND` dataset refuses a `time` output column as it refuses a `datetime`
  one (VALUE-1, TIME-23, PARQUET-1, DSJSON-2, SUB-25, SUB-27, #4267 D-next).
- **An aggregate narrows on a value it derives for each record.** A qualified
  aggregate's `filter` and `between` bounds may now name a variable its
  `derivations` bind, as its reducer and `order_by` already could, so a count
  of the records dated on or before a subject's anchor date, whose date is
  derived from collected text, needs no staged specification. The bindings
  then evaluate on every record whose keys match, before the range and the
  filter, as a named intermediate's derivations do; an aggregate whose filter
  and range read only stored fields evaluates them as before, on the records
  they keep (LOOKUP-22, #4309 D-next).

### Lint

- **A pruned declaration is reported.** `lint()` now reports
  `unused_declaration` at an input, a named intermediate, a column or a row
  template's derivation that a specification writes and that the resolved
  specification prunes, since nothing the artifact needs reads it, naming
  what reads it. A layer reports only what it writes, an inherited column it
  relabels among it, so `yamaa lint` exits 1 on a file that declares such a
  member. Delete it, list it in `output.columns`, or suppress the finding with
  a reason; it has no fix (LAYER-11, LAYER-12, #4325 D-next).
- **A listed function no specification calls is reported.** `lint()` now
  reports `uncalled_function` at the entry of a project file's `functions`
  that lists a function file whose function no specification of the project
  calls once resolved, whose tests a build therefore never runs. Only the
  project file that writes `functions` is read, and only when its project
  lists a specification; it has no fix (FUNC-2, FUNC-12, PROJECT-16, #4326
  D-next).

### Resolved specification

- **`resolve()` lists what pruning removed.** Each entry of the resolved
  specification gains `pruned`: every input, named intermediate, column and
  row template's derivation that composition wrote and that the resolved
  model no longer holds, then each value another layer wrote inside one, such
  as a study layer's label for a template column it leaves out, each with the
  file, line and column that wrote it (LAYER-1, LAYER-11, #4325 D-next).
