# yamaa 1.0.0

yamaa 1.0.0 is in development. These notes are written as it is built, and
become the notes of the 1.0.0 release.

## Upgrading

- **Break: Parquet output bytes change; values do not.** A saved Parquet file
  is now Zstandard-compressed and dictionary-encoded, in row groups of 131,072
  rows, so it is much smaller and its bytes differ from 0.7.0's; it reads back
  with the same fields, rows, nulls and values, every float bit for bit.
  Compare Parquet outputs by what they read back as, not by their bytes, or
  save `csv` where bytes must match (PARQUET-4, #4184 D305, #4186).

## Changes

- **A build that reads other inputs through lookups runs by partition.** A
  specification whose other inputs, such as ADSL, are read only by their
  declared key, a qualified source read or an intermediate that derives
  nothing now reads them whole first and its CSV or Parquet driver input by
  partition, so its row and cell limits bound each partition of the driver
  input. A build refused past 10,000,000 driver records now succeeds, with
  the same output (LIMIT-3, #4184 D-next, #4191).
- **A partitioned run derives up to four partitions at once.** Each derives
  on a thread of its own, or fewer when the process may use fewer cores;
  `threads` on every R and Python call that takes `progress`, and `--threads`
  on `check`, `run` and `submission`, set the number, and `threads = 1` gives
  the serial run. A project run also builds its specifications at once,
  each once the specifications whose outputs it reads have finished, its
  specifications and their partitions sharing those threads. Output, issues,
  report and the order of progress events do not change; on several threads,
  a partition's events arrive once it has been derived, and a specification's
  once it has built (#4184 D-next, #4193).
