# yamaa 0.6.1

yamaa 0.6.1 fixes the build of the R source package on Windows with a Rust
toolchain for the GNU host, which CRAN's Windows machines use, and is the
first release submitted to CRAN after that build failed CRAN's checks of
0.6.0. Its interface is 0.6.0's: the language, the Python, R and
command-line calls, the diagnostics and the saved files are unchanged, so
upgrading from 0.6.0 needs no change. A change that CRAN asks for after a
release moves every host to the same patch version, so the Python packages
and the command line are 0.6.1 too, and the 0.6.0 GitHub release stays as
published (#3030 D51).

The [0.6.0 notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.6.0/docs/releases/0.6.0.md)
describe the 1.0 interface that 0.6 releases for testing, the break from
0.5.0 and every change up to 0.6.0. Like 0.6.0, 0.6.1 is outside the
stability contract, which starts at 1.0.0 (#3673 D289). Report what you find
through the [issue forms](https://github.com/elong0527/yamaa/issues/new/choose):
the 0.6.0 feedback form, which covers 0.6.1, for what you tried and how the
interface felt, the bug report for a defect.

## Install

Install the Python package from PyPI with `python -m pip install yamaa`
(#3030 D57). The wheels cover CPython 3.12 and later on Linux x86_64 and
aarch64 with glibc 2.28 or later, macOS arm64 and Windows x64; elsewhere pip
builds the source archive, which needs Rust 1.82 or later and a C compiler.
Each GitHub release carries the same Python files, and also R binary packages
for Windows x64 and macOS arm64, for R 4.6 and R 4.5, which install without
Rust, Rtools or a network; the R source package, for Linux and any other R
from 4.2.0; and the standalone `yamaa` command line for Linux, Windows and
macOS, which needs no Python, R or Rust and ships unsigned (#3030 D52). The R
source package also goes to CRAN, and once CRAN accepts it,
`install.packages("yamaa")` installs it from there (#3673 D289). The
[Python](https://github.com/elong0527/yamaa/blob/main/python/README.md#installation)
and [R](https://github.com/elong0527/yamaa/blob/main/R/yamaa/README.md#installation)
package pages give the commands,
[Supported platforms](https://elong0527.github.io/yamaa/release/#supported-platforms)
lists every platform, and
[Installing in a restricted environment](https://elong0527.github.io/yamaa/articles/restricted-environments/)
covers machines without internet access.

## Known issues

The [known issues of 0.6.0](https://github.com/elong0527/yamaa/blob/yamaa-v0.6.0/docs/releases/0.6.0.md#known-issues)
still apply: the command-line binaries are unsigned and not notarized, and
the YAML reader is a vendored copy of saphyr-parser 0.2.1 with reviewed
fixes.

## Changes since 0.6.0

### Packages

- On Windows, the R source package builds with a Rust toolchain for the GNU
  host, `x86_64-pc-windows-gnu`, as CRAN's Windows machines have it. Its
  Makevars gave Cargo R's C compiler command as the linker, and R's Windows
  `CC` ends in a space, so Cargo found no linker `gcc ` for the build scripts
  and procedural macros that it links on that host. It now gives Cargo the
  compiler's program alone (#4005). A toolchain for the MSVC host with the
  GNU target added, as `rustup target add x86_64-pc-windows-gnu` sets it up,
  links them with MSVC's linker and was not affected, nor were the R binary
  packages.
- Native qualification's CRAN checks on Windows build the R source package
  with the minimum Rust for the GNU host, as CRAN's Windows check does
  (#4006).
