The first release candidate of yamaa 1.0.0 carries the decided 1.0 interface
(#3030 D150): the four file types, whose files start with `yamaa: "1.0"` and
`type`; the Python and R calls and their results; and the `yamaa` command
line, which also ships as standalone binaries for Linux, Windows and macOS.
The interface may still change before 1.0.0, from which the stability contract
holds (#3030 D1, D20), and later candidates follow as the remaining 1.0 work
lands.

Every file written for 0.5.0 must be rewritten for 1.0. The 1.0.0 notes so
far, which this release gives after this section and
[`docs/releases/1.0.0.md`](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0-rc.1/docs/releases/1.0.0.md)
keeps, start with the break from 0.5.0 and list every change since then. The
approved rename table,
[`tools/migrate/renames.yaml`](https://github.com/elong0527/yamaa/blob/yamaa-v1.0.0-rc.1/tools/migrate/renames.yaml),
gives the 1.0 spelling of every field, keyword and value of the 0.5.0 schemas,
or the reason it was removed.

The candidate's packages are the unchanged files that one native
qualification run built from the tagged commit, which this release names
under "Qualified native artifacts": the Python wheels and source archive, the
R source package, the R binary packages for R 4.6 and R 4.5 on Windows and
macOS, and the command-line archives. The tag names that run, and the
release publishes it only because every job that a release requires passed:
the installation of each package on its platforms, also without a network as
a restricted machine installs it, with the package's selftest; the
conformance corpus through the installed packages; the comparison of the
results across the hosts; and CRAN's incoming checks of the R source package.
