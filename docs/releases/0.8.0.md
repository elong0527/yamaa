# yamaa 0.8.0

0.8.0 adds calculated history through backward row reads and improves execution
of large datasets with column operations and concurrent partitions. The
specification language remains 1.0. Like 0.7.0, this release precedes the
stability contract that starts at yamaa 1.0.0; the saved-output change is
listed under [Upgrading](#upgrading). The
[0.7.0 notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.7.0/docs/releases/0.7.0.md)
cover the previous release.

This release is published on GitHub and PyPI. It is not submitted to CRAN;
R users install the source package or a binary from the GitHub release.

## Install

Install the Python package from PyPI with `python -m pip install yamaa` (#3030
D57). The wheels cover CPython 3.12 to 3.15 on Linux x86_64 and aarch64 with
glibc 2.28 or later, macOS arm64 and Windows x64; elsewhere pip builds the
source archive, which needs Rust 1.82 or later and a C compiler. Each GitHub
release carries the same Python files, and also R binary packages for Windows
x64 and macOS arm64, for R 4.6 and R 4.5, which install without Rust, Rtools or
a network; the R source package, for Linux and any other R from 4.2.0; and the
standalone `yamaa` command line for Linux, Windows and macOS, which needs no
Python, R or Rust and ships unsigned (#3030 D52). Install the R package from
the GitHub release. The
[Python](https://github.com/elong0527/yamaa/blob/main/python/README.md#installation)
and
[R](https://github.com/elong0527/yamaa/blob/main/R/yamaa/README.md#installation)
package pages give the commands, [Supported platforms](#supported-platforms)
lists every platform, and [Installing in a restricted
environment](https://elong0527.github.io/yamaa/articles/restricted-environments/)
covers machines without internet access.

## Supported platforms

Each cell names the CPython or R series that native qualification installs and
tests the package with, the oldest glibc a Linux wheel needs, or the Rust
target of the command-line binary; `no` means the release has no such package.

| Platform | Python wheel | Python source archive | R source package | R binary package | Command-line binary |
| --- | --- | --- | --- | --- | --- |
| Linux x86_64 | CPython 3.12 to 3.15 on glibc 2.28 or later | CPython 3.12 to 3.15 | R 4.2 or later | no | `x86_64-unknown-linux-musl` |
| Linux aarch64 | CPython 3.12 to 3.15 on glibc 2.28 or later | CPython 3.12 to 3.15 | R 4.6 | no | `aarch64-unknown-linux-musl` |
| macOS arm64 | CPython 3.12 to 3.15 | CPython 3.12 to 3.15 | R 4.2 or later | R 4.5 and 4.6 | `aarch64-apple-darwin` |
| Windows x64 | CPython 3.12 to 3.15 | CPython 3.12 to 3.15 | R 4.2 or later | R 4.5 and 4.6 | `x86_64-pc-windows-msvc` |

- The Linux wheels are `manylinux_2_28`, for RHEL 8, Ubuntu 20.04, Debian 10
  or later; older systems build the Python source archive.
- The source packages carry their crates and build offline with Rust 1.82 or
  later, Cargo and a C compiler; an offline Python build needs `maturin`
  installed (`pip install --no-build-isolation --no-index`), and a Windows R
  build the Rtools of its R series and the `x86_64-pc-windows-gnu` target.
- Each R binary package serves one R series, R-release or R-oldrel
  (#3030 D48), and installs without Rust, Rtools or a network; the macOS
  ones need macOS 11. Other R series and Linux use the R source package.
- The command-line binaries are static on Linux (musl) and Windows, need
  macOS 11 on macOS, and ship unsigned (#3030 D52).
- macOS x86_64, free-threaded Python and the Python and R packages on musl
  systems such as Alpine Linux are not supported (#3030 D49).

Saved files are qualified with these readers at these minimums, which the
Python `test` extra and the R package's `Suggests` declare: Polars 1.35.2
(2.0.0 on CPython 3.15) and PyArrow 23.0.1 (26.0.0 on CPython 3.15) for CSV
and Parquet; R arrow 23.0.1 for CSV and Parquet; Python's standard library and
R jsonlite 2.0.0, with `bigint_as_char = TRUE`, for Dataset-JSON 1.1; and lxml
6.1.3 for Define-XML 2.1.

## Upgrading

- **Break: Parquet output bytes change; values do not.** Saved Parquet files
  use Zstandard compression and dictionary encoding, with row groups of
  131,072 rows; fields, row order, nulls and values are preserved, including
  every floating-point bit (PARQUET-4, #4198).

## Changes

- **Calculated values can use earlier calculated rows.** Strictly backward
  `row_value` reads can carry calculated history through causal column groups
  in one independently ordered window. Current-row dependencies remain
  acyclic; the stored, converted and handled value, including a missing value,
  is what later rows read. The dosing-weight benchmark demonstrates this
  without a project function (WINDOW-12, #4233, #4234, #4236).
- **Partitioned runs can read other inputs through lookups.** A CSV or Parquet
  driver can be read by partition while the other inputs are read whole for
  keyed lookups, qualified source reads or intermediates without derivations.
  The row and cell limits then bound each driver partition, allowing a driver
  beyond 10,000,000 records when its operations stay within partitions
  (LIMIT-3, #4203).
- **The hosts and command line expose a thread limit.** Every Python and R
  call that takes `progress` also takes `threads`; the `check`, `run` and
  `submission` commands take `--threads N`. The default is the fewer of four
  and the cores the process may use; one requests serial execution. A project
  builds independent specifications concurrently, and specifications and
  partitions share that limit. Output, diagnostics, reports and progress-event
  order are preserved; concurrent work delivers its events when the partition
  or specification finishes (#4206, #4216, #4226).
- **Column operations and shared grouping reduce repeated work.** Source
  copying, expressions, filters, row construction, joins, aggregates, windows,
  output access and report serialization operate on typed columns and reuse
  grouping or lookup results. Partitioned execution checks and publishes
  partitions in order without merging their rows into one frame (#4194,
  #4197, #4202, #4204, #4205, #4215, #4221, #4224, #4225, #4229, #4231, #4232).
- **Parquet reading and writing use the run's threads.** Inputs decode into
  typed columns and retain the first scanned partition for reuse. Driver
  row-group scans and output row-group encoding share the configured worker
  limit (#4207, #4222, #4235).
- **Selecting one project specification avoids preparing every listing.**
  A listing whose own file writes its domain is named from that file alone;
  selecting it by name prepares the selected specification (#4217).
- **Host packages negotiate boundary version 9.** The native calls group
  engine settings together and refuse mixed host/native builds (#4223).

## Known issues

The command-line binaries are unsigned and not notarized. The YAML reader
remains a vendored copy of saphyr-parser 0.2.1 with reviewed fixes (#3969),
as described in the
[0.7.0 notes](https://github.com/elong0527/yamaa/blob/yamaa-v0.7.0/docs/releases/0.7.0.md#known-issues).
