# Repository validator native routing

The repository's complete specification pass now prepares the original authored
files through the installed native unified engine capability. Static declaration
issues are native Check findings. Explicit source slots retain their original
declaring file, resource policy and immutable byte snapshots. CSV and Parquet
profile admission uses callback-free owned public fixtures; Python reads physical
header carriers only after native admission. Native header/type binding retains
the complete ordinary or producer owner and emits portable diagnostic facts.

This pass never builds the authored project, activates a function, evaluates a
cell, or publishes an artifact. Zero header/type findings proves only that fact
scope. Existing public Check versus Build checkpoints are unchanged. In
particular, the Python public language gate still rejects a foreign R environment
under REQ-0667/REQ-0696. Producer contracts come from the held native graph;
unpublished producer artifacts are never read for metadata proof.

The private metadata services accept bounded closed source identity/name/type
carriers. Duplicate, missing, unknown and mismatched owners fail admission before
binding. Explicit captures use an index and a shared byte ceiling, with the exact
public declaring-only resource policy. Contributor identities for human display
come from held native normalization provenance; public issue context is unchanged.
Native metadata type checks reuse compiled operand kinds and shared diagnostic
constructors. Primary selector/cycle failures cannot establish downstream field
availability. They preserve the original primary diagnostic independently of
later public execution diagnostics.

Formatting, labels, layout and other approved authoring policy remain Python.
The independent partial controls retain their authored assertions. Grammar AST,
span, ODM, window and custom-schema observations use direct typed Rust examples
which are development-only and have no installed parser or probe endpoint. The
production admission entry is guarded against partial-helper/reference fallback.

The [assertion disposition](validator-assertion-disposition.json) lists all 420
original named controls and every explicit native or host successor. Its exact
79 non-function fixture inventory records 77 native original declaration/header
proofs and the two approved historical resource-path exclusions. Every original
declared phase, condition, requirement, path and context fact is retained; no
benchmark expected truth is edited. The separate negative-function contract is
proved in the actual Python host and in mandatory installed R qualification.

When a real installed R SDK and the real declared lock are unavailable, the CLI
prints one deferred source/binding/runtime lane for each of schema-functions,
schema-non-finite, adam-adsl-bmi, adam-advs-percentiles and
negative-function-contract. A clean CLI means the available-host repository
checks are clean and explicitly retains those deferrals. Five individually named
typed Rust tests preserve each original R declaration's metadata assertion.
`R/yamaa/tests/public_environment.R` replays each named original case through
installed public Check and Domain, verifies the real lock and callable cases,
and pins repeated activation plus unchanged expected CSV bytes. The negative case
pins its complete issue table, missing-study ordering and Save refusal. Those
mandatory R matrix witnesses own full R semantic acceptance.

The source, assertion and required-host inventories are deletion prerequisites
for #1994. This change does not retire evaluator source or relax its qualification
gates. The immutable static/style slices keep their separate exact-head evidence;
the complete routing head requires its own full installed native matrix.
