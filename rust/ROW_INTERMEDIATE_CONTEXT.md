# Common input records and named selections

The native compiler admits ungrouped `rows` whose written `dataset` values
select one common input. Input declarations keep their written order; the
selected input need not be first, and `base` does not decide row construction.
An omitted row dataset defaults only for a single input. Invalid or omitted
names retain the original model preflight before source inspection.

Direct named `source` reads may run in record construction and later column
assignments. The frozen match-value compiler owns selector types, expression
keys and static key failures. The row bridge promotes row-local defaults
needed by actual matching output dependencies and row identity, checks actual
row availability, and adds those matching dependencies to the row graph. It
binds each selector once, independently of candidates; it creates no synthetic
output assignments or host expressions. Failed selector declarations and
unknown fields retain their original causes and authored paths.

Every attempted candidate receives an attempt-local selection token before
assignments. Filtering never refunds that token, and retained candidates carry
it into the column pass. The token is separate from source position, output
keys and diagnostic row position. Named selection caches hold immutable donor
coordinates or absence, keyed by token and selector. Each reading still obtains
its selected value and records its own reached inherited handler. Unused named
handlers do not acquire new zero-count ledger entries. Destination-free key
probes cannot read named selections; real key candidates preserve their prior
first-appearance selection identities.

The source lifecycle is unchanged: inspect all declared inputs, capture/decode
in written order, bind all schemas, admit aggregate source capacity, derive and
convert each row value, filter the candidate, then derive columns. Semantic
selector width/field failures remain later than missing input-path causes.
Unmatched/multiple and conversion failures remain earlier than a row filter
that would discard the candidate. Original opaque non-Clone Box/Rc source-cell
payloads move unchanged, and a failure stops later reads without retries.

New row occurrence expansion has a conservative aggregate 16 MiB metadata
ceiling and 100 million logical binding-work ceiling, admitted before row
parser/default ownership. The schema bridge admits aggregate schema, path,
dependency and finding-copy costs before owning secondary schema copies. It
uses typed compiler resource errors, never a language condition. Runtime token
issuance, tree lookup/insertion comparisons, eligibility/matching vectors,
current match values, selected cells and repeated handlers share existing
attempt-local cumulative work/text/identity/output counters. Cache and vector
allocation is admitted by those logical counters before allocation; discarded
attempts retain their evaluated work. These limits bound logical work/storage,
not allocator overhead or wall time. Fresh attempts start with empty caches and
budgets. Output text retains the existing peak live candidate policy, including
values completed before a discarding filter.

SELF, correlated filters and broader secondary scalar families remain gated.
