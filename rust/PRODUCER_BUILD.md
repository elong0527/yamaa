# Shared producer builds

The #1869 service consumes the complete validated graph into one immutable build
owner. Preparation has already compiled every canonical node once against its
retained environment. The build borrows that complete closure; it cannot replace
or recompile individual nodes. Metadata `Node` still keeps its compilation private,
and static graph checking still returns explicit execution refusal.

Every fresh attempt activates the unique called-function union in environment
order. Lock verification, all bindings and every conformance case complete before
any study inspection or capture. The engine then validates every node's complete
local call signature against its immutable local-to-global projection before the
first study request. Invocation and signature lookup use the same projection.
Unused environment definitions grant no activation authority; a graph with no
called functions performs no activation host crossings.

Nodes execute once in deterministic producer-first order. A producer declaration
routes by its dataset and canonical dependency to an earlier accepted artifact's
held bytes. Consumers decode these bytes again with their declared producer
contract. They never receive an unrounded producer table or read a prospective
output file. Aliases borrow one immutable byte `Arc`; each ingestion still charges
its source, cell and work capacities. CSV stored header order is admitted before
declared typing. Complete native logical schemas are compared before execution.
Mismatch evidence retains portable REQ-0535 geometry and original field order.

Ordinary execution, output-key and verification gates precede output preparation.
Output declarations, bounded encoding and complete report rendering precede
artifact acceptance and dependent consumption. Capture, ingestion, execution,
verification, encoding or reporting refusal stops the graph. Caller-owned attempts
retain entered nodes only, with source inspection/capture facts, original captured
bytes, decoded tables, handler counts and completed checks. Typed host errors and
interrupt payloads are preserved without retry; the native panic fence owns the
original unwind payload beside the actual entered prefix.

Capacities precede growth. Graph nodes and activation selection are admitted
before port entry. Sources share cumulative captured-byte and decoded-cell
budgets. Every declared source reserves an equal codec storage/decoding-work share
before decoding, including aliases. Native CSV bounds parsed fields before typed
or Arrow construction; native Parquet bounds framing, expansion, retained values
and array elements. Execution rows/cells/text/work and report capacities reserve a
conservative equal node share. Serialized output bytes share a cumulative budget;
declaration scans and prior-artifact searches consume routing work. These are
capacity policies, not normative language limits or allocator/RSS guarantees.

`FileGraph::into_build` transfers native resources, original prepared documents
and the held environment into a separate `FileBuild`. The initial metadata
snapshot prefix is verified before activation. Cached study bytes are reread only
after fresh activation; changed content preserves the original `Changed` failure
and snapshot. External requests resolve from each original node's declaring
context, including inherited rebased paths and canonical Unix roots containing
literal backslashes. Native capture/snapshot/path/work and bounded raw-evidence
retention have separate explicit capacities. Evidence ownership remains available
after files and the resource owner disappear. No content hashes are used.

The independent CSV witness remains
`1.234/2.345 -> 1.23/2.35 -> 2.46/4.70` through two consumer references. Native
Parquet and diamond witnesses also compare independent cells and exact consumer
bytes. No POWER dependency is introduced.

This build service accepts no publication port. It qualifies shared orchestration
and native codecs with fake activation/report ports. Ordinary installed Python/R
producer dispatch, complete host workflow reports and ordered explicit
publication remain #1741. Its publication lifecycle decision remains #1866;
Windows R release scope remains #1857. Neither decision is inferred by this slice.
