yamaa third-party notices
=========================

The yamaa command-line binaries link third-party Rust crates and the Rust
standard library, and on the musl targets the musl C library, into the yamaa
executable. This file lists those crates with the license that yamaa relies on
and the license, copyright and NOTICE texts that each crate ships for it, and
the standard library's licensing and the crates that it links. The project's
own license is in LICENSE.txt; LICENSE-READSTAT.txt, LICENSE-UNICODE.txt and
LICENSE-YAML.txt carry the notices for the vendored ReadStat sources, the
Unicode data in yamaa's own tables and the vendored saphyr-parser crate. The
archives for the musl targets also carry LICENSE-MUSL.txt, the notice of musl.

The list covers the third-party crates that the shipped crate yamaa-cli links,
as locked in rust/Cargo.lock and built with its default features: its normal
dependency closure on each of the targets x86_64-unknown-linux-gnu,
aarch64-unknown-linux-gnu, x86_64-unknown-linux-musl,
aarch64-unknown-linux-musl, aarch64-apple-darwin, x86_64-pc-windows-msvc,
x86_64-pc-windows-gnu, without procedural macros. Crates that only build
scripts or procedural macros use, and crates that only other features or other
platforms select, are not linked, so they are not listed. Crates come from
crates.io unless an entry names another source.

Where a crate offers a choice of licenses, yamaa relies on the first license
in this order that the crate offers and whose text the crate ships: MIT,
Apache-2.0, BSD-3-Clause, Unicode-3.0, Apache-2.0 WITH LLVM-exception,
CC0-1.0, Zlib. Each entry names only the license relied on. Texts that only
grant another license are not reproduced; the crate's general license,
copyright, NOTICE and AUTHORS files are.

Texts are reproduced verbatim, with LF line endings and a final newline.
Identical texts are printed once and numbered; each entry names the numbered
texts its crate ships. A crate whose package ships no notice, but whose
repository also publishes a listed crate that does, names that crate's texts.
Otherwise, where a crate package ships no text for the license it is relied on
under, the entry says so and the canonical text from the SPDX License List
3.29.0 is reproduced instead, with its placeholders unfilled.

The Rust standard library section gives the Rust project's licensing statement
and the licenses and copyright holders of the standard library's own files,
with the license texts that the toolchain ships in share/doc/rust/licenses,
from the notice that Rust 1.99.1, the toolchain that builds the released
packages, ships as share/doc/rust/COPYRIGHT-library.html. It then lists the
third-party crates that the standard library links on the targets above, from
the toolchain's rust-src component: those that library/std/Cargo.toml declares
for the targets and for the features that the Rust project builds std with,
and their dependencies, at the versions that library/Cargo.lock locks, each
with the texts that its package in library/vendor ships, chosen like a
crate's, and the in-tree crates that the standard library links whose
manifests declare a license that the notice does not give them, with the
license files of their sources.

This file is generated by tools/packaging/generate_third_party_notices.py from
rust/Cargo.lock and the Rust 1.99.1 toolchain; do not edit it by hand.

musl C library
--------------

The yamaa executables for x86_64-unknown-linux-musl and
aarch64-unknown-linux-musl link musl, the C library that Rust 1.99.1 bundles
for those targets, statically. Their archives carry its notice as
LICENSE-MUSL.txt: musl's COPYRIGHT file, verbatim, after a header that names
the release.

Library: musl 1.2.5
    License: MIT
    Text: LICENSE-MUSL.txt
