# Shared function invocation

`yamaa-engine::function_invocation` applies REQ-0676-0686 and REQ-0700-0704
for one logical row, after a caller has resolved and activated a binding.
It does not read an environment, import code, execute a specification, or expose
an installed callback API. Python remains the only dataset backend.

`InvocationPlan` owns immutable identity, declaration-order parameters, mapped
host names, exact result type and missing-result permission. Requiredness uses
an enum: required parameters cannot hold defaults, while every optional parameter
holds an explicit value, including missing. Construction checks logical identifier
syntax, unique logical/host names, nonempty identity, exact default types and
missing-default permission. Host-language identifier syntax, qualified callable
resolution, fingerprints, activation vectors and static call preflight remain
outer compiler/adapter responsibilities. This internal typed API accepts already
materialized values; byte, parameter-count and cumulative callback budgets must
be enforced before untrusted host exposure. It does not bound callback duration.

Invocation checks sorted unknown names first. It then checks parameters in
signature order. Omission selects an optional default; explicit missing never
does. Present types must match exactly, without integer/float widening or Boolean
coercion. A non-accepting missing argument immediately returns missing without
calling the port or checking later runtime arguments. This preserves the current
Python `BoundFunction` order; it does not replace static implementation-stage
validation of all argument declarations. A skipped call does not require
`may_return_missing`.

`FunctionPort` receives only mapped names and borrowed normalized scalar values
in declaration order, and returns an owned value or an opaque error. It is
synchronous, requires no Send/Sync/Clone implementation, and introduces no worker,
retry, memoization or rollback. A caller reusing a plan invokes the port again.
Effects preceding a host error or rejected result remain observable. Adapters
must normalize nonfinite scalars to missing, reject unsupported host objects,
contain host exceptions and perform REQ-0570 temporal argument encoding. Temporal
precision is retained within this typed service until that actual host boundary.
Neither the service nor its fake port proves Python GIL or R-thread integration.

All invocation failures are fatal derivation conditions with resolved function,
contract-version and implementation-version identity. The bound call label is
also retained. Argument failures use REQ-0700; host exceptions use REQ-0701;
invalid host representations, Boolean results, undeclared missing results and
wrong exact result types use REQ-0702. Result checks happen before any lifecycle
conversion. Opaque host payloads move intact and need not be Clone; disclosure
policy and host-specific exception serialization belong to adapters.

The 42 independently authored TSV cases run through both the Rust fake port and
the actual Python `BoundFunction`. They check full i64, signed zero, Unicode,
temporal scalars, defaults, missing behavior, validation order, exact types,
nonfinite returns, host failures and ordered/countable callback effects.
Additional Rust tests cover invalid plans, retained temporal precision, owned
result lifetime, non-Clone errors, thread-local ports and repeated effects after
failures. No expected truth is generated by either implementation.
