# Shared host interface

[bindings.yaml](bindings.yaml) is the authoritative declaration input for the
Python and R binding generators. It uses a closed, declarative YAML IDL that
generates Rust-level PyO3/extendr registration, host declarations and the
public layer of each host package. This is the design for
[#2689](https://github.com/elong0527/yamaa/issues/2689). Both hosts' native
declarations and public layers are generated by
`tools/packaging/generate_bindings.py`; callable implementations, conversions,
host-function ports and interrupt probes remain handwritten. The generator
also writes [manifest.txt](manifest.txt), the normalized inventory of the
frozen sections. `make check-repository` and the `native-rust` job of the
native qualification lane compare the generated files with this definition
([#2693](https://github.com/elong0527/yamaa/issues/2693)). The runtime
negotiation below is the design contract, not an implemented handshake; it and
the boundary compatibility tests
([#2692](https://github.com/elong0527/yamaa/issues/2692)) wait for an engine
that loads separately from the host facade, planned for 0.5.0
([#2785](https://github.com/elong0527/yamaa/issues/2785)).

## Boundary choice and source ownership

Choose Rust-level generated host glue. Each host package builds the shared
engine, adapters and its binding crate together with the selected toolchain and
lock. Rust values never cross between independently built shared libraries.
There is no stable Rust binary layout promise. A separately loadable C engine
would additionally need a handle table, allocator API, C record layouts and a
callback ABI; none is needed to generate the current host declarations. The
existing Arrow C Data/Stream interface remains the standard C ABI for tables.
Its ownership contract below applies to both generated host boundaries.

The IDL owns export names, ordered arguments, defaults, host projections, Rust
implementation paths, feature names and semantic pairings. The adjacent document
owns negotiation and lifetime rules. Shared adapters/core own execution,
diagnostics, resource authority, scalar admission and publication. PyO3/extendr
own their interpreter registration machinery. Generated declarations must invoke
the existing Rust implementations; they must not generate a second engine or
duplicate semantic validation in Python or R.

The record owner is [#2674](https://github.com/elong0527/yamaa/issues/2674), split
from [#2591](https://github.com/elong0527/yamaa/issues/2591). Its approved decisions
specify a boundary version starting at 1 in `yamaa-adapters`, severity
`error`/`warning` (all current conditions are errors), and unchanged optional core
span/route geometry. The `records` import names roles, not guessed Rust symbols
or a second schema. The generator resolves each role to its public symbol in
`yamaa_adapters::diagnostic_record` (`BOUNDARY_VERSION`, `DiagnosticRecord`,
`ResultRecord` and `PlanRecord`); an unresolved role is a generation error.
The imported version constant is the single
runtime source for both hosts; neither generator embeds a separately maintained
version number. `format_version` versions the IDL grammar only.

## Definition grammar and generation

Format 2 has the top-level keys shown in the definition: `format`,
`format_version`, `boundary`, `contract`, `imports`, `handshake`, `values`,
`tables`, `records`, `public`, `cli`, `python`, `r`, `operations`, and
`host_only`. Reject unknown keys, duplicate mapping keys, aliases, arbitrary
YAML tags, mapping keys that are not text (only the command line's exit
statuses are integers), unknown type tokens, duplicate exports, invalid Rust
paths, unresolved imports and operation references to absent exports.
Argument mapping order is positional order; sequence order is emission order.
Strings contain identifiers, types and prose, never executable generator
snippets. The R group's `module` supplies the implementation path for its
functions; the root `yamaa` group's function is defined in the crate root. The
only argument-default syntax is `type = literal`, with `None` for optional
values, `false`/`true` for booleans and nonnegative integers; generators parse
these literals without eval.

The definition declares today's surface only. The 1.0 surface is drafted in
[bindings-1.0.yaml](bindings-1.0.yaml), which nothing reads; each pull request
that implements part of it moves that part here, and the last deletes the
draft.

### Vocabularies, tables and records

`values` holds the closed vocabularies of the public surface, `tables` the
columns of each table a host returns, in order, and `records` the named
records a host returns as a dict or named list (none today). Each vocabulary
and table names, as `rust: yamaa::NAME`, the facade constant that owns it: the
issues and run report columns, the ODM item columns, the phases, the report's
kinds and outcomes, and the severities. The generator reads the constant from
the facade sources, following an alias such as
`pub const ODM_COLUMNS: [&str; 30] = yamaa_core::odm_items::COLUMNS;` into the
core crate, and refuses a declaration that differs from it in any value or
column, or in their order. A value or column added in Rust therefore fails
generation until it is declared here. A column or record field has a `name`,
the language's column `type` (`str`, `int`, `float`, `date` or `datetime`,
with `list<T>` and `optional<T>`), and optionally the vocabulary its `values`
come from (or `yaml/conditions.yaml`, the condition registry) and a `meaning`.

### Public surface

`public` declares each host's user-facing surface. Its `types` give the host
projection of each type token, its `functions` the module functions, its
`classes` the result and lazy classes in definition order (a class is defined
before any class that returns it), its `errors` the refusal and its `python`
block the module docstring and version name. From it the generator writes the
public module `python/src/yamaa/__init__.py` (`__all__`, the error class and
its native mapping, and the delegating classes and functions), and R's
`R/yamaa/R/public-bindings.R` (the exported functions, the constructors of the
result and lazy objects, S3 methods and private accessors) and
`R/yamaa/NAMESPACE`. The handwritten rest stays beside them:
`python/src/yamaa/_support.py` holds the Polars table conversion, path
conversion, lazy-object pickling and the version lookup, and `R/yamaa/R/api.R`
holds the reply and argument conversions, the host-function capabilities, the
interrupt rethrow and the locked-object helpers. Docstrings come from `doc`;
R's help pages stay handwritten under `R/yamaa/man/`.

Generated code only delegates, and the delegation is declared, never written:

- A class `holds` an ordered set of values, each named by what it fills:
  `handle`, the native handle the object wraps; one of its `field` members;
  or a native argument, which the value fills in the object's native calls. A
  class that holds neither a handle nor a field is lazy: it holds paths,
  converts its own path when it is made, and keeps a plans handle when a native
  call it makes takes `plans` (#2821).
- A member or function `calls` an operation of `operations`. Each native
  argument of that operation's Python and R exports is bound by name: to the
  member's own arguments, converted by their type token; to a held value; to
  the plans handle; or, in R, to the host's `version` and `capabilities`. A
  member argument that fills no native argument, or a native argument that
  nothing fills, is a generation error.
- A member that returns a class makes it from the call's result and the values
  it holds; a handle passed to a class must be the native type its members
  call. `raises: refusal` maps the native exception to `yamaa.Error`, which R's
  reply conversion signals as `yamaa_error`.

Member kinds are `property` (a read-only view, an active binding in R),
`method`, `field` (a value the object holds when made), `index` (Python's
`__getitem__` and R's `[[` S3 method: the key is checked against the class's
`names`, and an absent one raises the refusal its `calls` operation gives),
`protocol` (Python's `__contains__` and `__iter__` over `names`) and `private`
(a qualification accessor such as R's `.run_observations(run)`, which Python
reaches through the handle; the manifest leaves it out). A class's
`interrupt` names the R host-only export it asks for a retained project
interrupt before it is returned, which `.rethrow_interrupt` signals again;
Python checks inside the native call. An R object keeps its handle in the
hidden `.handle` binding when an S3 method or a private accessor reaches it.

### Command line

`cli` is empty until `yamaa-cli` exists (#3060); its grammar follows the
draft. A nonempty `cli` has `binary` (`yamaa`), `crate`
(`rust/crates/yamaa-cli`), `synopsis`, `global_flags`, `exit_status` (integer
statuses 0 to 125 and what each means) and `commands`, and may have
`depends_on`, `inputs`, `streams`, `interrupt` and `json` (named lists of JSON
keys). A command has a `name`, a `synopsis` starting with `yamaa <name>`, the
`operations` it reaches and its `json_keys`, and may have `args`, `flags`,
`effect` and `text`. A flag's name starts with `--`; a flag or argument may
name the vocabulary its values come from. An operation's `cli` list, and
`host_only.cli`, may name only declared commands and global flags.

### Native registrations

Type expressions use `optional<T>`, `list<T>` and ordered `tuple<T, ...>`.
`text` is owned Unicode, `bytes`/`raw` is owned arbitrary bytes, `bool` is a
boolean, `i32` is signed 32-bit, `index` is a checked nonnegative Rust `usize`,
and `unit` has no payload. Host projections preserve these distinctions:
Python uses `str`, `bytes`, `int`, `None`, lists and tuples; R's `raw`, `robj`,
`r_list` and `r_function` denote `Raw`, `Robj`, `List` and `Function` in extendr.
`host_object`, `host_callback` and `host_exception` are interpreter-rooted
objects, never serialized addresses. Named Python classes refer to owned native
handles. `arrow_stream_capsule` is the named `arrow_array_stream` PyCapsule.

The `python` and `r` sections inventory the complete current registration lists,
including class methods, the private qualification accessor `observations`, the
one native exception, version metadata and the ODM reader. The `python` section
holds only `module`, `registration` and `exports`, and the generator refuses any
other key. There is no issue-record declaration: the Rust facade builds the
seven-column issues table once, and every issues view crosses the boundary as a
table like any output or report. Python reads it from an `_ArrowTable` as a
Polars DataFrame, and the R binding converts it natively into a data.frame.
`context_object` is the owned tree `spec_resolve` returns, a `dict[str, object]`
of text, booleans, exact integers, floats, `None`, lists and nested objects.
`r_reply` describes the existing `{value, error}` list, whose error carries a
message and the issues table. The definition does not treat a Rust `Result`,
`Vec`, `String`, enum or trait as a C-layout type.

`operations` pairs equivalent semantic operations despite different calling
conventions: a Python handle method with the R function that takes the handle,
such as `_Run.save` and `run_save`, and a Python function with its R
counterpart, such as `_project_run` and `project_run`. Every Python export,
each class method included, and every R function names its counterpart under
`operations` unless `host_only` declares it host transport. The generator
refuses an export that has neither and an operation that names only one host.
`host_only` holds Python's `_style_same_value`, behind the private style
command, and the Arrow capsule `_ArrowTable.__arrow_c_stream__`, and R's two
interrupt helpers, `run_interrupt` and `project_run_interrupt`. Python checks
for a host interrupt inside each native call; R asks a returned run or project
run handle for the interrupt it retained and rethrows that original condition.
Generating both hosts does not mean inventing a public style API in R.
extendr-generated `wrap__*`, metadata, registration and finalizer functions are
framework machinery, not additional engine operations.

### Outputs and the manifest

The generator at `tools/packaging/generate_bindings.py` supports a read-only
default comparison and explicit `--write`, following
`generate_shipped_schema.py`; `tools/packaging/bindings_surface.py` and
`tools/packaging/bindings_public.py` hold its format 2 sections. Python output
includes `_native.pyi`, the Rust registration layer and the public module; R
output includes `yamaa-r/src/generated/*.rs` extendr registrations,
`R/yamaa/R/native-bindings.R` private native-call wrappers,
`R/yamaa/R/public-bindings.R` and `R/yamaa/NAMESPACE`. Each R implementation
module includes its generated registration fragment, and the generated R
layer calls the `.native_*` wrappers. Both hosts are rendered from one loaded
definition and imported record source in each run. Outputs carry
`Generated by ... Do not edit` headers and deterministic UTF-8 bytes checked by
direct comparison. Omitted or invented handwritten exports are drift; R
argument order/types and return types must also match the definition, and
every export must keep its pairing. The native qualification lane runs the
same comparison beside the shipped-schema check.

[manifest.txt](manifest.txt) lists the frozen sections one element per line:
each value, each column and record field with its position and type, each
public type projection, function, class, member and argument with its
position, default and result, the refusal, each exported name and S3 method,
and each command, flag, exit status and JSON key. It leaves out the private
native sections, documentation and implementation details such as `holds` and
`calls`. The stability check of
[the stability contract](../../docs/design/interface-1.0/stability.md)
compares these lines with the latest release tag: a removed or changed line is
a candidate break, and an added line an addition. A stale manifest fails the
read-only comparison like any other generated file.

## Version and feature handshake

Generated facades negotiate once at initialization, before resolving source
paths, reading files, activating project code, invoking resolvers, importing
Arrow pointers or creating an execution handle. Every generated callable also
requires an initialized successful negotiation; importing `_native` or invoking
an R `.Call` wrapper directly must not bypass the gate. Release/finalizer paths
and the handshake itself are exempt. `core_version()` and `_CORE_VERSION`
remain informational engine package versions, not compatibility evidence.

The request contains an unsigned boundary version and ordered lists of required
and optional feature identifiers. The native side returns the imported result
record containing the accepted version, supported features, enabled requested
features and informational core version. The response representation is generated
from the same imported record contract. The facade checks the returned version
and required set before making any execution call. Negotiation has no IO,
callbacks, activation or publication side effects.

Use exact version equality. Reject zero, malformed, older, newer and unknown
versions; never guess a compatible range or retry with a lower version. The
native implementation checks equality before interpreting feature-dependent
payloads. Every refused negotiation uses the frozen bootstrap envelope below;
the facade constructs the typed refusal using its own imported schema. No peer
decodes an unknown record layout. If a legacy native package has no handshake
entry point, the facade refuses with `missing_interface` before any other call.

The bootstrap envelope is a plain named host object with `accepted` (boolean),
`requested_version` (integer or null for malformed input), `supported_version`
(integer, or null when the native handshake is absent), `reason` (one of
`version_mismatch`, `malformed_request`, `missing_feature`, `missing_interface`),
and `missing_features` (ordered strings). `accepted` is always false here.
It is used only
when negotiation refuses and carries no diagnostic schema, execution payload,
handle, pointer or exception text. Its field meanings are frozen across boundary
versions. The bootstrap-to-record mapping is generated from the shared adapter
classification, using core `application_issue::rejected("interface", reason)`
as its source, into the facade's imported diagnostic and result types. The
version/feature facts become owned structured context. The generated mapping
does not call an incompatible native record decoder or infer registry fields
in handwritten host code.
This uses the registry's `ApplicationRejected` identity, null requirement and
absent span/route; it does not define another diagnostic code or record shape.
Failure is raised as `InterfaceError` in Python or `yamaa_interface_error` in R,
carrying that imported record. These are new generated-boundary errors, not
current registrations. Direct native handshake callers receive the same
bootstrap refusal and use the mapping for their own supported record version.

| Request | Outcome |
| --- | --- |
| Supported exact version and all required features available | Accept and enable required features plus the supported optional intersection. |
| Any unsupported version, including a newer facade with an older native library | Refuse before record decoding or execution; include both versions in bootstrap facts. |
| Native library has no handshake entry point | Refuse as `missing_interface`; supported version is unavailable. |
| Unknown or unavailable required feature | Refuse with missing features in request order. |
| Unknown or unavailable optional feature | Leave disabled; report the supported/accepted sets explicitly. |
| Duplicate identifiers within or across feature lists, invalid versions or invalid request field types | Refuse as `malformed_request`. |

`structured_records` and `arrow_c_stream` are mandatory for the generated
boundary. Optional identifiers and their owners are listed in the IDL. Format
features report the actual compiled adapter capabilities, not just declaration
presence. A facade that needs an optional feature must require it in its
negotiation or refuse the operation locally before calling native code. A
successful handshake never proves source authority, lock conformance or a
successful build. It cannot be reused across a replaced native module.

Breaking signature, ownership, field meaning, required-field, variant or
diagnostic-interpretation changes require a new boundary version in the record
owner. Additive optional operations can use a new feature identifier; imported
record extension/ordering rules remain those of #2674. Never reuse a feature
identifier with different semantics. A missing mandatory feature is a failed
handshake even if both packages report the same release version.

## Imported records and errors

Diagnostic, result and plan records come exclusively from the `records` import.
The generator projects their named fields into both hosts. It must retain the
owner's code/phase/requirement/severity mapping, diagnostic and path ordering,
structured context, and absent-versus-present span/route rules. No host sorts,
deduplicates, caps or reconstructs findings from message strings. Context and
record values own their text, arrays, objects and exact numbers. Integers wider
than a host's ordinary numeric type retain their numeric identity through the
record owner's exact representation; R binary64 must never silently narrow
them (R carries such integers as character tokens, Python as `int`). Missing
values remain distinct from zero and empty text. The host issue data frames
are presentation projections of the named diagnostic records, built from the
same record in each host ([#2675](https://github.com/elong0527/yamaa/issues/2675),
[#2676](https://github.com/elong0527/yamaa/issues/2676)).

Semantic failures are imported diagnostic/result records, including failed
builds with retained evidence. Invalid arguments, expired/wrong-kind handles,
busy or poisoned owners, conversion failures and caught native panics are typed
boundary refusals using the shared `ApplicationRejected` classification; they
do not invent a language requirement. Native unwinds and R longjmps must not
cross the host boundary. Ordinary callback exceptions/conditions stay rooted on
their originating attempt. Formatting a secondary error must not replace that
original object.

Version refusal uses the bootstrap mapping above. Ordinary callable boundary
failures use the negotiated imported records directly. Argument failures before
negotiation carry bootstrap facts and are mapped by the facade. A fatal process
abort or allocation abort cannot be turned into a recoverable record.

The imported plan record is inspection metadata, not execution authority.
Neither the resolved JSON artifact nor a previous accepted result authorizes
another run. Plan reuse ([#2821](https://github.com/elong0527/yamaa/issues/2821))
is declared here as the `plans` operation and the required `plan_reuse`
feature. Each public spec or project object holds one opaque plans handle,
which `spec_run` and `project_run` take as their last argument. Python makes
the handle with its object and gives a copy or an unpickled object a new one;
R makes it on the first run, and R's `plans` replaces a handle that came back
expired from `saveRDS`, an `.RData` file or another process. A run reuses a
kept plan only when the request's paths, resolved again as compilation
resolves them, name the files it was compiled from and every one is unchanged
(#3069); otherwise it compiles again. It activates project functions afresh
through the call's own capabilities. No handle method exists, and no public
field shows reuse; only the private run observations record it.

## Ownership, threading and cancellation

| Object | Owner and lifetime |
| --- | --- |
| Input text/bytes | Borrow only during a synchronous call; clone into a retained Rust owner before returning or retaining for a callback. |
| Diagnostic/result/plan metadata | Owned values independent of temporary interpreter buffers and of later calls. |
| Run, project run or submission handle | Owning PyO3 object or rooted R external pointer; drop/finalize once, invalidate before dropping state. No caller dereferences a stale address. |
| Plans handle | Frozen PyO3 object or registered R external pointer owned by one public spec or project object. A run only borrows it, so a run started from a project function shares it too; each run returns its own run handle, which outlives the plans. Kept plans hold no project-function roots or observer. R frees the handle on the R thread at finalization, and a serialized handle comes back expired and is replaced. |
| Project function callback or host failure | Strong interpreter root held by the attempt that may call or inspect it; release on its owning interpreter thread. |
| Arrow stream or emitted schema/array | Current holder of the moved standard header, with independent references to immutable buffers. |

Handles are process-local, host-local and kind checked. Do not serialize them,
use them after finalization, exchange them between Python/R or treat an address
as authority. Access during an existing mutable borrow or after poisoning
returns a refusal. Result accessors own their outputs; dropping the parent
cannot invalidate a copied record or exported table.
Inspection and evidence access grant no Save capability. Save uses the held
build's ordered publication path and reports operational refusal separately from
attempting to save a failed build.

Calls are synchronous. Python callbacks require the originating interpreter and
GIL; R callbacks execute only on the originating R thread. A `Send + Sync`
resource trait does not permit running an R closure on a worker. Do not hold
a mutable result borrow across a reentrant host call. Reentry to the same busy
owner refuses; unrelated owned results remain usable. Generated glue must root
callbacks for all native uses and contain exceptions/conditions before Rust
resumes. Finalizers do not invoke project code or start publication.

Cancellation is control flow, distinct from a semantic finding. Retain the
original Python interrupt/SystemExit or R interrupt on the current attempt,
stop new work when observed, unwind native temporaries normally, and rethrow the
original object after returning to the host. A resolver's `Cancelled` result
stops work without fabricating a host exception when none exists. No background
kill, asynchronous cancellation token or new public cancel API is promised.

On failed conversion, cancellation or callback failure, release temporary native
owners, Arrow schemas/arrays/streams and callback roots exactly once. Owners
transferred into a retained attempt or consumer remain alive until that owner
is released. Close or abort provisional publication through the existing resolver
protocol; retain already committed artifacts and actual attempt evidence.
Cancellation does not roll back a prior commit or permit later Save from a
failed attempt. Cleanup failure is retained alongside the original failure,
never used to erase it. A completed export already owned by a consumer remains
valid if a later call on the build is cancelled.

## Arrow C Data/Stream handoff

Use the existing [host handoff](../README.md#arrow-host-handoff) implemented in
[the shared bridge](../crates/yamaa-adapters/src/arrow_bridge.rs), with PyArrow
>=23.0.1 and Polars >=1.35.2. Tables only leave the engine: Python receives each
output, issues and report table as an `_ArrowTable` and reads it into Polars,
while the R binding copies each table into plain R vectors in Rust, so no Arrow
stream crosses the R boundary. No host passes a table into the engine. The
generated declarations must preserve these shapes:

| Transfer | Ownership transition |
| --- | --- |
| Python export | `_ArrowTable.__arrow_c_stream__()` creates a fresh named capsule owning a stream header shell and independent reader cursor. |
| Stream schema/next batch | Each successful emitted schema/array has its own release callback. End of stream is an array with `release == NULL`, distinct from an empty batch. |

The current owner invokes each non-null release callback once. Moving ownership
sets the source release to null; a moved-from destructor frees only its own
shell. On stream errors, release every successfully obtained live schema/array
and the stream. Copy any borrowed `get_last_error` text before the next stream
call or release. Early stream release drops unread batches. Imported arrays own
buffer references independently and outlive their stream, exporter and build.
Repeated exports use independent cursors over shared immutable buffers.

Arrow-rs callbacks in the existing bridge do not call Python/R or need a build
handle. Foreign callbacks remain the foreign producer's responsibility; consumers
must honor any producer thread/lifetime constraints, keep its required runtime
alive and contain its failures before returning across the C ABI. No native
callback may unwind or longjmp across that ABI. Forged native pointers are
outside the ABI contract; host class/name checks cannot validate arbitrary
memory. Never overwrite a live destination or release a moved header twice.

Preserve signed Int64 extrema, Float64, UTF-8 (including NUL, large/view arrays),
nulls, slices, empty batches and chunks. Public dates use Date32 days and
zone-free datetimes whole TimestampSecond values. Requested Python export
schema conversion is refused. Nonfinite floats become missing under the
existing engine rule. Buffer sharing covers retained public Arrow
value/validity buffers. Build materialization, Polars conversion and R
data-frame conversion can copy. Conversions preserve values or raise an error:
R raises for an integer beyond 2^53 or text containing NUL, which no plain R
vector holds exactly. The generator must reuse these adapters rather than
promise zero copies for those conversions.

## Follow-up verification

Generation already compares this definition with both actual registration
surfaces. Later steps must preserve existing installed-host behavior while
adopting the imported record contract. The compatibility step must cover the
handshake table (including older native/newer facade), refusal before IO or
callbacks, wrong-kind/busy/expired owners, original callback failures,
cancellation during conversion/publication, and post-failure cleanup. Reuse
the existing Arrow pointer, release, early-release, failed-conversion and
repeated-import/export controls from
[#2646](https://github.com/elong0527/yamaa/pull/2646), adding generated-boundary
coverage where needed. Diagnostic full-registry and cross-host payload parity
remain owned by [#2677](https://github.com/elong0527/yamaa/issues/2677). No test
may derive benchmark expected values from the implementation.
