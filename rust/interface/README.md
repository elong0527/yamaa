# Shared host interface

[bindings.yaml](bindings.yaml) is the authoritative declaration input for the
Python and R binding generators. It uses a closed, declarative YAML IDL that
generates Rust-level PyO3/extendr registration, host declarations and the
public layer of each host package. This is the design for
[#2689](https://github.com/elong0527/yamaa/issues/2689). Both hosts' native
declarations and public layers are generated by
`tools/packaging/generate_bindings.py`; callable implementations, conversions,
host-function ports and interrupt probes remain handwritten. The generator
also writes [manifest.txt](manifest.txt), the normalized inventory of the
frozen sections. `make check-repository` and the `native-rust` job of the
native qualification lane compare the generated files with this definition
([#2693](https://github.com/elong0527/yamaa/issues/2693)). Both hosts run
the version and feature handshake below before any other native call, and the
boundary compatibility and lifetime tests of
[#2692](https://github.com/elong0527/yamaa/issues/2692) run in both installed
suites. Both bindings call the `yamaa` facade directly and use
`yamaa-boundary` for the handshake, gate and handle census. Each package
links its engine (below).

## The boundary

Each binding's generated Rust glue registers its host's functions with PyO3
or extendr. Its handwritten implementations call the facade's public Rust
items and keep their results in owned native handles. The binding's
`yamaa-boundary::Gate` negotiates from the facade's engine information and
opens on the first acceptance. The Arrow C Data/Stream interface carries
tables between native code and host libraries, with the ownership contract
below applying to both hosts.

Each host package builds the facade, adapters, core, boundary and its binding
crate together with the selected toolchain and lock. No stable Rust ABI is
required.

The IDL owns export names, ordered arguments, defaults, host projections, Rust
implementation paths, feature names and semantic pairings. The adjacent document
owns negotiation and lifetime rules. Shared adapters/core own execution,
diagnostics, resource authority, scalar admission and publication. PyO3/extendr
own their interpreter registration machinery. Generated declarations must invoke
the existing Rust implementations; they must not generate a second engine or
duplicate semantic validation in Python or R.

The record owner is [#2674](https://github.com/elong0527/yamaa/issues/2674), split
from [#2591](https://github.com/elong0527/yamaa/issues/2591). Its approved decisions
specify severity `error`/`warning` (all current conditions are errors) and
unchanged optional core span/route geometry. The imports name roles, not guessed
Rust symbols or a second schema, and the generator resolves each to its public
symbol: the `records` import's diagnostic role to core's
`yamaa_core::diagnostic::Diagnostic`, the one record from the failure site to
the edge, and the `boundary` import's version role to
`yamaa_boundary::BOUNDARY_VERSION`; an unresolved role is a generation error.
The boundary version, now 7 for Python input frames, is the single source for both hosts:
the generator writes it into each host's request, and neither keeps a
separately maintained copy. `format_version` versions the IDL grammar only.

## Definition grammar and generation

Format 2 has the top-level keys shown in the definition: `format`,
`format_version`, `boundary`, `contract`, `imports`, `handshake`, `values`,
`tables`, `records`, `public`, `cli`, `python`, `r`, `operations`, and
`host_only`. Reject unknown keys, duplicate mapping keys, aliases, arbitrary
YAML tags, mapping keys that are not text (only the command line's exit
statuses are integers), unknown type tokens, duplicate exports, invalid Rust
paths, unresolved imports and operation references to absent exports.
Argument mapping order is positional order; sequence order is emission order.
An optional public argument with a `None` default is emitted only on the hosts
its type projects; adding its other host projection later makes that argument
available there without a second declaration.
Strings contain identifiers, types and prose, never executable generator
snippets. The R group's `module` supplies the implementation path for its
functions; the root `yamaa` group's function is defined in the crate root. The
only argument-default syntax is `type = literal`, with `None` for optional
values, `false`/`true` for booleans and nonnegative integers; generators parse
these literals without eval.

The definition declares the whole host surface that the hosts and the command
line implement, and nothing they do not; the stability contract freezes its
manifest from 1.0.0 (`docs/release.md`).

### Vocabularies, tables and records

`values` holds the closed vocabularies of the public surface, `tables` the
columns of each table a host returns, in order, and `records` the named
records a host returns as a dict or named list: today `info`, the engine
information that `info()` returns and a selftest holds (D41). Each vocabulary and table names, as
`rust: yamaa::NAME`, the facade constant that owns it: the statuses, the
issues, run report, lint, selftest and condition catalogue columns, the ODM
item columns, the phases, the report's kinds and outcomes, the severities,
the lint findings, the file types, the features and the hosts. The generator reads the constant from the facade sources,
following an alias such as
`pub const ODM_COLUMNS: [&str; 30] = yamaa_core::odm_items::COLUMNS;` into
the core or adapters crate, and refuses a declaration that differs from it in
any value or column, or in their order. A value or column added in Rust
therefore fails generation until it is declared here. A column or record
field has a `name`,
the language's column `type` (`str`, `int`, `float`, `date` or `datetime`,
with `list<T>` and `optional<T>`), and optionally the vocabulary its `values`
come from (or `yaml/conditions.yaml`, the condition registry) and a `meaning`.

### Public surface

`public` declares each host's user-facing surface. Its `types` give the host
projection of each type token (a token named for a vocabulary, `status` or
`file_type`, is text from that vocabulary, and both projections name it as
`values.<token>`), its `functions` the module functions, its
`classes` the result and lazy classes in definition order (a class is defined
before any class that returns it), its `errors` the refusal and its `python`
block the module docstring and version name. From it the generator writes the
public module `python/src/yamaa/__init__.py` (`__all__`, native error imports
and their declared constructor and pickle methods, and the delegating classes and functions), and R's
`R/yamaa/R/public-bindings.R` (the exported functions, the constructors of the
result and lazy objects, S3 methods and private accessors) and
`R/yamaa/NAMESPACE`. The handwritten rest stays beside them:
`python/src/yamaa/_support.py` holds path conversion, lazy-object pickling and
the version lookup, and `R/yamaa/R/api.R`
holds the reply and argument conversions, the host-function capabilities and
the locked-object and table-memo helpers. Docstrings come from `doc`;
R's help pages stay handwritten under `R/yamaa/man/`. The refusal's Python
`native` names its PyO3-created exception, and `state` names its native subclass.
`picklable: true` generates its reconstruction arguments from its declared
attributes, preserving its instance state as well. `chained: true` also
retains Python's `__cause__` when the refusal is pickled. The cause and any
added instance state must themselves be picklable: an unpicklable cause raises
its normal pickle error and stays attached to the original refusal. R's `parent` field
keeps the original callback condition. R constructs the same
condition fields and state subclass from its declaration. Every refusal carries
an issues table, including before negotiation and after an R table-conversion
failure (D258 reversed by #4077). Table pickling is native
and preserves its Arrow schema and batches without a Python table library.

Generated code only delegates, and the delegation is declared, never written:

- A class `holds` an ordered set of values, each named by what it fills:
  `handle`, the native handle a result wraps, or a native argument, which the
  value fills in the object's native calls. A class that holds no handle is
  lazy: it holds paths, converts its own path when it is made, and keeps a
  plans handle when a native call it makes takes `plans` (#2821).
- A member or function `calls` an operation of `operations`. Each native
  argument of that operation's Python and R exports is bound by name: to the
  member's own arguments, converted by their type token; to a held value; to
  the plans handle; or, in R, to the host's `version` and `capabilities`. A
  member argument that fills no native argument, or a native argument that
  nothing fills, is a generation error.
- A member that returns a class makes it from the call's result and the values
  it holds; a handle passed to a class must be the native type its members
  call. `raises: refusal` declares the native `yamaa.Error` hierarchy, which R's
  reply conversion signals as the `yamaa_error` hierarchy. In R, a member that returns
  `nothing` or `paths_written`, as `save()` does, returns it invisibly.

Member kinds are `property` (a read-only view, an active binding in R),
`method`, `index` (Python's `__getitem__` and R's `[[` S3 method: the key is
checked against the class's `names`, and an absent one raises the refusal its
`calls` operation gives), `protocol` (Python's `__contains__`, `__iter__` and
`__len__` over `names`), `printing` (Python's `__repr__`, which `str()` falls
back to, and R's `print` and `format` S3 methods: `format()` returns the lines
its `calls` operation renders in Rust and `print()` writes them, so no host
formats a result or a lazy object, which prints from the path it holds; D37)
and `private` (a qualification accessor such as R's `.run_observations(run)`,
which Python reaches through the handle; the manifest leaves it out). A member
that returns a record token (`info`) names the record it returns as `record`.
An R object keeps each held value
that an S3 method or a private accessor reaches in a hidden binding: its
handle in `.handle`, and any other value under its own name with a leading
dot, such as a lazy object's `.path` or a project-run member's `.name`.
In R, a result's `property` that returns `table`, `optional_table` or
`run_output` keeps the data frame its first read converted and answers later
reads with it, until a `method` of the result, such as `save()`, runs; a NULL
and a streamed run's output stream are read again on each read (#4071). A
result and each member its `index` makes share that memo, which the result
keeps in `.memo`, and the helpers in `api.R` drop it from an object restored
from `saveRDS`.

Every result, a class that holds a handle, also has R `names()` and `length()`
S3 methods, which nothing declares (D44): the generator derives them. A result
with an `index` member names the keys its `names` member gives; any other
names its `property` and `method` members in declaration order, never its
hidden bindings. `length()` counts the names. The manifest records each
result's names, so a reordered member changes a frozen line. A lazy object
keeps R's own `names()` and `length()` of an environment.

A class with `hosts: [python]` is Python's alone: a native class of
`yamaa._native` that the public module imports and exports as it is, today
only `yamaa.Table` (D11, D43), which R has no counterpart for because its
tables are data frames (D44). It has no `r`, `holds` or `doc`. Each member
names one method of the native class, by its `python` spelling for a
`protocol` or `printing` member (`printing` is `__repr__`) and by its own name
otherwise, and declares that method's arguments; a `property` is a native
getter, and a `method` may list the modules it `imports` when it is called.
Every native method of the class is one member, and `host_only` names each. A
type token with only a `python` projection, such as `polars_frame`, serves
only such members. `value_types` gives both hosts' projection of each of the
language's column types, the type of a table's column and of each value its
rows hold; every table column's type is one of them, possibly inside `list<T>`
or `optional<T>`.

### Command line

`cli` declares the `yamaa` binary of `rust/crates/yamaa-cli` (#3060), which
calls the facade directly and so pairs no native export. It has `binary`
(`yamaa`), `crate` (`rust/crates/yamaa-cli`), `synopsis`, `global_flags`,
`exit_status` (integer statuses 0 to 125 and what each means) and `commands`,
and may have `depends_on`, `inputs`, `values`, `streams`, `interrupt` and
`json` (named lists of JSON keys: those of the objects the documents hold,
such as an issue). `values` holds the command line's own closed vocabularies,
which no facade constant owns, such as the output formats: each lists its
values, and none shares a name with a vocabulary of the top-level `values`. A
command has a `name`, a `synopsis` starting with `yamaa <name>`, the
`operations` it reaches and its `json_keys`, the keys of the JSON document it
prints, or text naming a document with no fixed keys, such as the JSON Schema
that `schema` prints. It may have `args`, `flags`, `effect`, `text` and
`refusal_keys`, the keys of the document a refusal prints when they differ
from `json_keys`. A flag's name starts with `--`; a flag or argument may name
the vocabulary its values come from, in either `values`. A command's
`operations` are the only record of what the command line reaches:
`operations` and `host_only` pair Python and R exports alone.
`tools/tests/test_bindings_cli.py` reads the binary's parser table and usage
text, and keeps the commands, their arguments and flags, the global flags, the
output formats and the exit statuses equal to them.

### Native registrations

Type expressions use `optional<T>`, `list<T>` and ordered `tuple<T, ...>`.
`text` is owned Unicode, `bytes`/`raw` is owned arbitrary bytes, `bool` is a
boolean, `i32` is signed 32-bit, `index` is a checked nonnegative Rust `usize`,
and `unit` has no payload. Host projections preserve these distinctions:
Python uses `str`, `bytes`, `int`, `None`, lists and tuples; R's `raw`, `robj`,
`r_list` and `r_function` denote `Raw`, `Robj`, `List` and `Function` in extendr.
`host_object`, `host_callback` and `host_exception` are interpreter-rooted
objects, never serialized addresses. Named Python classes refer to owned native
handles. `arrow_stream_capsule` is the named `arrow_array_stream` PyCapsule,
and `row` is one table row as a `dict[str, object]`. A class method with
`kind: getter` is a read-only attribute, a `#[getter]` in Rust, which the stub
declares as a property.

The `python` and `r` sections inventory the complete current registration lists,
including class methods, the private qualification accessor `observations`, the
one native exception, version metadata, the ODM reader, the handshake and the
private census of live handles. The `python` section
holds only `module`, `registration` and `exports`, and the generator refuses any
other key. There is no issue-record declaration: the Rust facade builds the
twelve-column issues table of #3030 D28 once, and every issues view crosses the
boundary as a table like any output or report. Python returns it as the
native `Table`, and the R binding converts it natively into a data.frame.
`context_object` is the owned tree `spec_resolve` returns, a `dict[str, object]`
of text, booleans, exact integers, floats, `None`, lists and nested objects.
`handshake_record` is the handshake's accepted record or refusal envelope, and
`handle_census` the live native handles by kind.
`r_reply` describes the existing `{value, error}` list, whose error carries a
message and the issues table. The definition does not treat a Rust `Result`,
`Vec`, `String`, enum or trait as a C-layout type.

`operations` pairs equivalent semantic operations despite different calling
conventions: a Python handle method with the R function that takes the handle,
such as `_Run.save` and `run_save`, and a Python function with its R
counterpart, such as `_project_run` and `project_run`. Every Python export,
each class method included, and every R function names its counterpart under
`operations` unless `host_only` declares it host transport. The generator
refuses an export that has neither and an operation that names only one host.
`host_only` holds the methods of Python's `Table`; R has no host-only
exports. Both hosts check interrupts inside their native calls and retain
original callback interrupts until the call returns. extendr-generated
`wrap__*`, metadata, registration and finalizer functions are
framework machinery, not additional engine operations.

### Outputs and the manifest

The generator at `tools/packaging/generate_bindings.py` supports a read-only
default comparison and explicit `--write`, following
`generate_shipped_schema.py`; `tools/packaging/bindings_surface.py`,
`tools/packaging/bindings_public.py` and `tools/packaging/bindings_handshake.py`
hold its format 2 sections. Python output includes `_native.pyi`, the Rust
registration layer and the public module, which begins with the handshake; R
output includes `yamaa-r/src/generated/*.rs` extendr registrations,
`R/yamaa/R/native-bindings.R` private native-call wrappers, which end with the
handshake and its `.onLoad`, `R/yamaa/R/public-bindings.R` and
`R/yamaa/NAMESPACE`. Each R implementation module includes its generated
registration fragment, and the generated R layer calls the `.native_*`
wrappers. Both hosts are rendered from one loaded definition and the imported
sources in each run. Outputs carry
`Generated by ... Do not edit` headers and deterministic UTF-8 bytes checked by
direct comparison. Omitted or invented handwritten exports are drift; R
argument order/types and return types must also match the definition, and
every export must keep its pairing. The native qualification lane runs the
same comparison beside the shipped-schema check.

[manifest.txt](manifest.txt) lists the frozen sections one element per line:
each value, each column and record field with its position and type, each
public type projection, function, class, member and argument with its
position, default and result, the refusal, each exported name and S3 method,
and the command line's synopses, output formats, global flags and exit
statuses, each command with its arguments, flags and JSON keys, a refusal's
included, and the keys of each object its documents hold. It leaves out the
private native sections, documentation and implementation details such as
`holds` and `calls`. The interface check of
[the stability contract](../../docs/release.md#stability-contract) compares
these lines with the newest final release of the same major: a removed or
changed line is a break, and an added line an addition. A stale manifest fails
the read-only comparison like any other generated file.

## Version and feature handshake

Each host package negotiates once, as it loads, before any other native call:
before resolving a path, reading a file, activating project code or making a
handle. The generated `yamaa/__init__.py` imports `_native` and calls
`_native._interface_handshake(request)` before it imports anything else from
the package, and the generated `.onLoad` of the R package calls the
`interface_handshake` routine. Both send the request that the `handshake`
section declares, with the version `yamaa_boundary::BOUNDARY_VERSION`, and the
binding negotiates through `yamaa-boundary::Gate` using the facade's engine facts.
Negotiation reads nothing, calls nothing and publishes nothing.

| | Contents |
| --- | --- |
| Request | `version`, the boundary version, from 1; `required`: `structured_records`, `arrow_c_stream` and `plan_reuse`; `optional`: `format_yaml`, `format_parquet`, `format_readstat` and `format_odm` |
| Accepted record | `accepted` (true); `version`; `enabled`, the required identifiers and then the supported optional ones, in request order; `supported`, every identifier the engine has; `core_version`, the engine's release; `language_versions`, as `info()` reports them |
| Refusal envelope | `accepted` (false); `requested_version`, null when the version field itself is malformed; `supported_version`, null when the native side has no handshake; `reason`, one of `version_mismatch`, `malformed_request`, `missing_feature` and `missing_interface`; `missing_features`, in request order |

Only the boundary version is negotiated, by exact equality: no ranges and no
retry with a lower version. The release and language versions are
informational, and a file the engine cannot read is refused by SCHEMA-2. The
format identifiers name the compiled features that `info()` lists as
`features`, and the hosts ask for them as optional: a missing format keeps the
engine's own refusal, such as `parquet_reader_unavailable`.

The check order holds in every boundary version, so that any two yamaa builds
refuse each other cleanly:

1. The request must be a mapping that holds one `version`, a positive integer
   of at most 32 bits and never a boolean, or it is malformed.
2. The version must equal the supported one, or it is a mismatch, and nothing
   else in the request is read, so an older side never has to understand a
   newer request.
3. The request must hold exactly `version`, `required` and `optional`, each
   list must hold identifiers (`[a-z][a-z0-9_]*`), and no identifier may
   appear twice within or across them, or it is malformed.
4. Every required identifier must be supported, or the missing ones are named
   in request order.
5. Otherwise the request is accepted.

Each binding converts its host's request structurally, and no deeper than
the request's own shape (the mapping, a field's list and that list's items),
so deeper input reads as no field whatever its size. A Python `int` that is
not a `bool`, an R integer and a whole R double are integers; an R atomic
vector reads as its element where a value belongs and as a list where a list
does; a key that is not text, or a name R cannot give as text, names no field,
so the version is still read first and nothing else is read for another
version; anything else, such as a float or a missing value, is no field of a
request.

| Request and native side | Outcome |
| --- | --- |
| The exact version, every required identifier supported | Accepted, enabling the required identifiers and the supported optional ones |
| Another version: a newer layer over an older native side, or an older layer over a newer one | `version_mismatch`, with both versions |
| No handshake on the native side: a native module without `_interface_handshake` or `interface_handshake` | `missing_interface`, with `supported_version` null |
| A required identifier unknown or unavailable | `missing_feature`, naming each in request order |
| An optional identifier unknown or unavailable | Accepted; it stays disabled, and the record lists the supported and enabled sets |
| An identifier twice, a zero, negative or oversized version, or a field of the wrong type | `malformed_request` |

A refusal is a fault of the installation, not a finding about the user's
files, so it is an error, not an issue. `import yamaa` raises
`yamaa.InterfaceError`, a subclass of `ImportError` that carries the
envelope's five fields. In R, `.interface_negotiate()` signals a
`yamaa_interface_error` condition with the same fields, but `loadNamespace()`
runs `.onLoad` through a hook that catches the error and stops with a plain
one, so `library(yamaa)` refuses the load with the message alone, and the
typed condition reaches only direct callers of `.interface_negotiate()`. The
message is the template of the reason, declared in the `handshake` section and
filled from the envelope, so a mismatch names both versions in both hosts.
Only a generated layer gives `missing_interface`, since no native side could.
The messages are not frozen.

The first accepted negotiation opens the binding's gate, which stays open for
the life of the process; a replaced native module starts closed, and a later
direct call of the handshake answers its request and leaves the negotiation as
it was. Every other native call passes the gate first: a Python function calls
`gate()`, itself or through the helper that runs its call, and every R
routine replies through `reply()`, which passes it. A result handle only comes from a gated
call, so its methods need no gate of their own. Before negotiation, which
only loading `_native` or the R library by hand allows, a call gets the
binding's state refusal: `yamaa.StateError` in Python and
`yamaa_state_error` in R, both carrying an empty issues table. The handshake itself, the
release paths, the informational `_CORE_VERSION` and `core_version()`, and
extendr's own routines that describe each module and write its R wrappers,
are exempt. The generator checks that every registered native function
reaches the gate, so a new export cannot skip it.

Each binding counts its live handles by kind (`check`, `run`,
`project_run`, `submission`, `lint`, `selftest`, `plans` and `table`, which only
Python hands out; R copies each table into host values) in a census
that the private accessors `_native._live_handles()` and
`.native_live_handles()` read for the handle lifetime suites.

The `handshake` section, its two errors and the census stay outside the frozen
manifest. The boundary version and the identifiers are internal: any release
may change them with a new boundary version, which a change that an older side
would misread needs, while an additive operation can take a new optional
identifier, and an identifier is never reused with another meaning. The
request's fields, the envelope's five fields and four reasons and the check
order stay the same across boundary versions. A successful handshake never
proves source authority, lock conformance or a successful build.

## Imported records and errors

The diagnostic record comes from the `records` import, and each issues view
projects its named fields into both hosts, keeping the record's rules:

- **Ordering.** Diagnostic order is authored order. A producer emits findings
  in stage order, and every boundary collection keeps that order; records are
  never sorted, grouped or deduplicated at the boundary. Within one record,
  `spec_paths` keep their authored order, and `operand_route` the order the
  core diagnostic recorded.
- **Severity.** The vocabulary is closed: `error` and `warning`. Every
  condition of the current registry is an `error`, which blocks the result it
  belongs to; `warning` is reserved for later non-blocking findings, and
  assigning one is a registry decision recorded with the condition, never a
  host's choice.
- **Geometry: absent is not zero.** `source_span` and `operand_route` are
  optional because geometry is not always available, and absent means
  unavailable, never a default. A present span with `start == end == 0` is a
  real zero-width span at the first byte of the original expression, and a
  present empty route is a recorded route with no steps; both differ from
  absent, and no host collapses them.
- **Context ownership.** A record owns its context outright: the core's owned
  JSON tree, which a producer neither keeps nor changes after handing it
  over. Its numbers keep their width end to end; nothing narrows them to
  binary64 at the boundary.
- **Extension.** Within one boundary version, a new registry condition, a
  severity for such a new condition, or a new optional record field is
  compatible, since a reader that ignores what it does not know is unaffected.
  Renaming or removing a field, changing a field's type or meaning, reading
  absent geometry as zero, reassigning an existing condition's severity,
  changing the severity vocabulary or weakening the ordering above needs a new
  boundary version.

It must retain the owner's code/phase/rule/severity mapping, diagnostic and
path ordering, structured context, and absent-versus-present span/route rules.
No host sorts,
deduplicates, caps or reconstructs findings from message strings. Context and
record values own their text, arrays, objects and exact numbers. Integers wider
than a host's ordinary numeric type retain their numeric identity through the
record owner's exact representation; R binary64 must never silently narrow
them (R carries such integers as character tokens, Python as `int`). Missing
values remain distinct from zero and empty text. The host issue data frames
are presentation projections of the named diagnostic records, built from the
same record in each host ([#2675](https://github.com/elong0527/yamaa/issues/2675),
[#2676](https://github.com/elong0527/yamaa/issues/2676)).

Semantic failures are diagnostic records, including failed builds with
retained evidence. Invalid arguments, expired/wrong-kind handles,
busy or poisoned owners, conversion failures and caught native panics are typed
boundary refusals using the shared `ApplicationRejected` classification; they
do not invent a language rule. Native unwinds and R longjmps must not
cross the host boundary. Ordinary callback exceptions/conditions stay rooted on
their originating attempt. Formatting a secondary error must not replace that
original object.

A refused handshake raises the typed interface error above, and a call
before negotiation gets the binding's ordinary boundary refusal. A fatal
process abort or allocation abort cannot be turned into a recoverable record.

Neither the resolved JSON artifact nor a previous accepted result authorizes
another run. Plan reuse ([#2821](https://github.com/elong0527/yamaa/issues/2821))
is declared here as the `plans` operation and the required `plan_reuse`
feature. Each public spec or project object holds one opaque plans handle,
which `spec_run` and `project_run` take as their last argument. Python makes
the handle with its object and gives a copy or an unpickled object a new one;
R makes it on the first run, and R's `plans` replaces a handle that came back
expired from `saveRDS`, an `.RData` file or another process. A run reuses a
kept plan only when the request's paths, resolved again as compilation
resolves them, name the files it was compiled from and every one is unchanged
(#3069); otherwise it compiles again. It activates project functions afresh
through the call's own capabilities. No handle method exists, and no public
field shows reuse; only the private run observations record it.

## Ownership, threading and cancellation

| Object | Owner and lifetime |
| --- | --- |
| Input text/bytes | Borrow only during a synchronous call; clone into a retained Rust owner before returning or retaining for a callback. |
| Diagnostic/result/plan metadata | Owned values independent of temporary interpreter buffers and of later calls. |
| Run, project run or submission handle | Owning PyO3 object or rooted R external pointer; drop/finalize once, invalidate before dropping state. No caller dereferences a stale address. |
| Plans handle | Frozen PyO3 object or registered R external pointer owned by one public spec or project object. A run only borrows it, so a run started from a project function shares it too; each run returns its own run handle, which outlives the plans. Kept plans hold no project-function roots or observer. R frees the handle on the R thread at finalization, and a serialized handle comes back expired and is replaced. |
| Project function callback or host failure | Strong interpreter root held by the attempt that may call or inspect it; release on its owning interpreter thread. |
| Arrow stream or emitted schema/array | Current holder of the moved standard header, with independent references to immutable buffers. |

Handles are process-local, host-local and kind checked. Do not serialize them,
use them after finalization, exchange them between Python/R or treat an address
as authority. Access during an existing mutable borrow or after poisoning
returns a refusal. Result accessors own their outputs; dropping the parent
cannot invalidate a copied record or exported table.
Inspection and evidence access grant no Save capability. Save uses the held
build's ordered publication path and reports operational refusal separately from
attempting to save a failed build.

Calls are synchronous. Python callbacks require the originating interpreter and
GIL; R callbacks execute only on the originating R thread. A streamed run's
`get_next` may come from another library on any thread: a run that can call
project functions is built only on the thread that started it, and a pull on
another thread fails with `host_thread` instead of calling the interpreter. A
`Send + Sync` resource trait does not permit running an R closure on a
worker. Do not hold a mutable result borrow across a reentrant host call.
Reentry to the same busy owner refuses; unrelated owned results remain
usable. Generated glue must root callbacks for all native uses and contain
exceptions/conditions before Rust resumes. Finalizers do not invoke project
code or start publication.

Cancellation is control flow, distinct from a semantic finding. Retain the
original Python interrupt/SystemExit or R interrupt for the current native
call, stop new work when observed, unwind native temporaries normally, and
rethrow the original object after returning to the host. Each host installs a
probe on the call's cancellation token: Python checks pending signals; R
checks under `R_tryCatch`, at most every 20 ms and once more as the call
returns. A nested call restores its enclosing call's interrupt state. A resolver's `Cancelled` result
stops work without fabricating a host exception when none exists. No background
kill, asynchronous cancellation token or new public cancel API is promised.

On failed conversion, cancellation or callback failure, release temporary native
owners, Arrow schemas/arrays/streams and callback roots exactly once. Owners
transferred into a retained attempt or consumer remain alive until that owner
is released. Close or abort provisional publication through the existing resolver
protocol; retain already committed artifacts and actual attempt evidence.
Cancellation does not roll back a prior commit or permit later Save from a
failed attempt. Cleanup failure is retained alongside the original failure,
never used to erase it. A completed export already owned by a consumer remains
valid if a later call on the build is cancelled.

## Arrow C Data/Stream handoff

Use the existing [host handoff](../README.md#arrow-host-handoff) implemented in
[the shared bridge](../crates/yamaa-adapters/src/arrow_bridge.rs). Tables only
leave the engine: Python returns each output, issues and report table as a
`yamaa.Table`, whose `to_arrow()`, `to_polars()` and `to_pandas()` read it
through this stream with PyArrow >=23.0.1, Polars >=1.35.2 or pandas
>=2.3.3, and whose `to_pylist()` reads it in Rust,
while the R binding reads each table's stream in Rust and copies it into plain
R vectors; a streamed run's output crosses into R as an Arrow C stream (#3697).
No host passes a table into the engine. The generated declarations must preserve
these shapes:

| Transfer | Ownership transition |
| --- | --- |
| Python export | `Table.__arrow_c_stream__()` creates a fresh named capsule owning a stream header shell and independent reader cursor. |
| Stream schema/next batch | Each successful emitted schema/array has its own release callback. End of stream is an array with `release == NULL`, distinct from an empty batch. |
| Streamed run output | The engine's export of the run's reader (`Batches::into_stream`): each `get_next` is one pull, which the first time builds the run and then builds one batch, and releasing a stream that started the run before its last batch cancels the run. Python's capsule and R's external pointer of class `nanoarrow_array_stream` own the header until a reader moves it; R's finalizer frees the header and releases an unmoved stream, calling no R or project code. |

The current owner invokes each non-null release callback once. Moving ownership
sets the source release to null; a moved-from destructor frees only its own
shell. On stream errors, release every successfully obtained live schema/array
and the stream. Copy any borrowed `get_last_error` text before the next stream
call or release. Early stream release drops unread batches. Imported arrays own
buffer references independently and outlive their stream, exporter and build.
Repeated exports use independent cursors over shared immutable buffers.

Arrow-rs callbacks in the existing bridge do not call Python/R or need a build
handle. Foreign callbacks remain the foreign producer's responsibility; consumers
must honor any producer thread/lifetime constraints, keep its required runtime
alive and contain its failures before returning across the C ABI. No native
callback may unwind or longjmp across that ABI. Forged native pointers are
outside the ABI contract; host class/name checks cannot validate arbitrary
memory. Never overwrite a live destination or release a moved header twice.

Preserve signed Int64 extrema, Float64, UTF-8 (including NUL, large/view arrays),
nulls, slices, empty batches and chunks. Public dates use Date32 days and
zone-free datetimes whole TimestampSecond values. Requested Python export
schema conversion is refused. Nonfinite floats become missing under the
existing engine rule. Buffer sharing covers retained public Arrow
value/validity buffers. Build materialization, `to_pylist()`, the Polars and
pandas conversions and R data-frame conversion can copy. Conversions preserve
values or raise an error: `to_pandas()` keeps each Arrow type as a
`pandas.ArrowDtype`, and R raises for an integer beyond 2^53 or text containing
NUL, which no plain R vector holds exactly. The generator must reuse these
adapters rather than promise zero copies for those conversions.

## Follow-up verification

Generation compares this definition with both actual registration surfaces.
The installed interface suites of both hosts test every row of the outcome
table, the check order and the gate, the Rust handshake family of
`yamaa-boundary` tests the negotiation, and the handle lifetime suites test
that dropping a result releases its handle, that an exported table outlives
its result, and that a refused conversion or a cancelled run or save leaves no
handle. They reuse the existing Arrow pointer, release, early-release,
failed-conversion and repeated-import/export controls of
[#2646](https://github.com/elong0527/yamaa/pull/2646), which gain the census,
and the interrupt-identity controls of both hosts. Diagnostic
full-registry and cross-host payload parity remain owned by
[#2677](https://github.com/elong0527/yamaa/issues/2677). No test may derive
benchmark expected values from the implementation.
