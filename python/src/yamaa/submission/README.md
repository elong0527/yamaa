# Study submission documents

Run a dataset with an explicitly selected study document to enforce its
bound, non-extensible codelists at the column verification boundary:

```python
import yamaa

pilot = yamaa.yamaa_domain("spec.yaml", study_document="define.yaml")
pilot.save()
yamaa.generate_study_document("define.yaml")
```

The study document selects its dataset specifications. Generation validates
family-dependent metadata, references, identifiers, and package paths before
rendering Define-XML 2.1. It compares canonical declarations directly and uses
the declared file identity and timestamp, so rendering is reproducible.
The bundled official XSD validates the generated bytes without network access.
Dataset specifications use the same inheritance resolver as execution.
Generation accepts the same `project_root`, `data_roots`, and
`read_project_configuration` options as `yamaa_domain` when published artifacts
are stored outside the study document's directory.

When an entry declares `dataset_json`, generation reads the already-published
dataset under its producing specification's output contract. It does not
execute the specification again. The exchange file preserves the published
rows, values, and column order and is validated against the bundled official
Dataset-JSON 1.1 schema. All files are rendered and validated before publication;
data files are replaced first and the XML document last. Each replacement is
atomic. A publication failure stops further replacements and cleans up its
temporary file; replacements already completed remain visible.

For in-memory metadata generation, use `load_study_document`, `compose_study`,
and `render_define_xml` from `yamaa.submission`. Composition resolves defaults
in copies so a source specification can be reused in another study.

Value-level metadata remains outside XML generation: under `Submission`, a
row template's submission map fails with REQ-1169 and names the row and column.
Dataset execution supports its codelist overrides when a study document is
explicitly supplied. Missing values pass terminology checks; extensible and
external codelists add no constraint. Independent declared verifications still
run as written.
